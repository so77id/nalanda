## Problem

Frontend (TypeScript/React) and backend (Go) speak different languages. Without a single source of truth for the HTTP API, schema drift will silently break the platform: a Go handler renaming a field would leave the frontend reading `undefined`, and no CI step would catch it. This is the consequence of decision G' in the plan and is called out as a downside in ADR-0001.

This spec creates `packages/shared-contracts/` with an OpenAPI 3 baseline document and two codegen scripts: one producing TypeScript types for the frontend, one producing Go server stubs (`oapi-codegen` style) for the backend. The baseline defines the minimum surface needed today — `GET /healthz` — so the wiring is real, not theoretical. Future endpoints (auth, sessions, submissions) just extend `openapi.yaml` and re-run codegen.

## Goals

- Create `packages/shared-contracts/` with its own `package.json` (npm install local to the package).
- Author `packages/shared-contracts/openapi.yaml` covering at least `GET /healthz` (the only endpoint that exists today, from S1.2). The schema must be valid OpenAPI 3.0.x or 3.1.
- Provide a `npm run generate` script that produces:
  - TypeScript types at `apps/frontend/src/gen/api-types.ts` (via `openapi-typescript`).
  - Go server stubs at `apps/backend/api/oapi.gen.go` (via `oapi-codegen`).
- Provide a `npm run lint` (or `npm run validate`) that lints the OpenAPI doc (via `@redocly/cli` or `swagger-cli`).
- Provide a `npm run diff` (or equivalent) script that runs codegen into a temp dir and `diff`s against the committed output — used in CI (S1.5 will call it) to detect uncommitted drift.
- Document the workflow in `packages/shared-contracts/README.md`: "edit openapi.yaml → run npm run generate → commit generated files".
- The generated Go file integrates with the backend without breaking its build (the existing hand-rolled `/healthz` handler in `apps/backend/internal/httpserver/` continues to exist; this spec does NOT yet route through the generated server interface — that switchover is a follow-up).

## Non-goals

- Rewriting the backend's `/healthz` handler to use the generated interface — that's a follow-up after the baseline is proven (decision documented in Notes).
- Authentication / OAuth / session endpoints in the OpenAPI document (those belong to E4 specs, which will extend `openapi.yaml`).
- Frontend code consuming the generated types in real components (the types are generated and committed; consumption happens organically as new features arrive).
- CI workflow wiring (S1.5).
- Publishing the package to npm (it stays a local-only workspace consumed via relative paths).

## Design

**Reference decisions:** G' (OpenAPI 3 + oapi-codegen), A (monorepo), W (manual monorepo, no npm workspaces — so `packages/shared-contracts/` has its own `package.json` and `node_modules/`).

**Layout:**

```
packages/shared-contracts/
├── package.json
├── package-lock.json
├── README.md
├── openapi.yaml                  # the single source of truth
├── scripts/
│   ├── gen-ts.mjs                # invokes openapi-typescript → apps/frontend/src/gen/api-types.ts
│   ├── gen-go.mjs                # invokes oapi-codegen (via npx) → apps/backend/api/oapi.gen.go
│   └── verify-no-drift.mjs       # runs gen-* into tempdir, diffs against committed outputs
├── node_modules/                 # gitignored
└── .gitignore
```

**`openapi.yaml` baseline content (illustrative):**

```yaml
openapi: 3.0.3
info:
  title: Nalanda API
  version: 0.1.0
  description: |
    Nalanda platform HTTP API. Single source of truth for frontend (TS types)
    and backend (Go handlers) contracts. Edit this file and run
    `npm run generate` from packages/shared-contracts/.
servers:
  - url: http://localhost:8080
    description: Local dev
paths:
  /healthz:
    get:
      operationId: getHealth
      summary: Service health check
      responses:
        '200':
          description: Service is healthy
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/HealthResponse'
components:
  schemas:
    HealthResponse:
      type: object
      required: [status, version]
      properties:
        status:
          type: string
          enum: [ok]
        version:
          type: string
```

**Dependencies (in `packages/shared-contracts/package.json` devDependencies):**

- `openapi-typescript` (latest stable) — generates TS types.
- `@redocly/cli` or `swagger-cli` — validates `openapi.yaml`.

**Go codegen:** `oapi-codegen` is a Go tool. Two integration options — pick at implementation time:

- **Option A (recommended):** `gen-go.mjs` shells out to `go run github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@latest -config oapi-codegen-config.yaml openapi.yaml`. Requires Go on PATH (CI installs it anyway via `actions/setup-go`).
- **Option B:** add `oapi-codegen` as a tool dependency inside `apps/backend/` via `tools.go` + `go install` pattern. Slightly cleaner for Go-only contributors. Slightly more setup for repo newcomers.

**TODO at implementation time:** decide A vs B; the spec assumes A unless someone justifies B. Both produce the same artifact.

**`oapi-codegen-config.yaml` (in shared-contracts/):**

```yaml
package: api
output: ../../apps/backend/api/oapi.gen.go
generate:
  models: true
  chi-server: true
  embedded-spec: false
```

Generates Go models + a chi-compatible `ServerInterface`. Backend keeps its current hand-rolled `/healthz` handler; later we can add a small adapter that bridges the existing handler to the generated `ServerInterface`. That migration is intentionally out of scope here.

**`gen-ts.mjs` example:**

```js
import { execSync } from 'node:child_process';
import { mkdirSync } from 'node:fs';
import { dirname } from 'node:path';

const out = '../../apps/frontend/src/gen/api-types.ts';
mkdirSync(dirname(out), { recursive: true });
execSync(`npx openapi-typescript openapi.yaml --output ${out}`, { stdio: 'inherit' });
```

**`verify-no-drift.mjs`:** runs both codegens into a temp dir, then `diff -u` against the committed outputs. Exits non-zero if any diff is found. This is the script CI calls (S1.5).

**README content:**

- "How to add an endpoint": edit `openapi.yaml`, then `npm run generate`, then commit both `openapi.yaml` and the regenerated TS + Go files.
- "How to validate locally": `npm run lint`.
- Note that `apps/frontend/src/gen/` and `apps/backend/api/oapi.gen.go` are committed (not gitignored) so reviewers see the contract diff in PRs.

## Acceptance criteria

- [ ] AC1: `cd packages/shared-contracts && npm install && npm run lint` exits 0 (OpenAPI doc is valid).
- [ ] AC2: `cd packages/shared-contracts && npm run generate` produces `apps/frontend/src/gen/api-types.ts` containing an exported `HealthResponse` type or equivalent.
- [ ] AC3: The same command produces `apps/backend/api/oapi.gen.go` containing a `HealthResponse` Go struct and a chi `ServerInterface` with a `GetHealth` method.
- [ ] AC4: After AC2/AC3 run, `cd apps/frontend && npm run build` still succeeds AND `cd apps/backend && go build ./...` still succeeds (generated files are syntactically and semantically valid).
- [ ] AC5: `cd packages/shared-contracts && npm run verify-no-drift` (or equivalent) exits 0 immediately after `npm run generate` (idempotency check).
- [ ] AC6: `packages/shared-contracts/README.md` documents the edit→generate→commit workflow.
- [ ] AC7: Generated files are committed to git (not gitignored).

## Slices (1 slice = 1 commit in the PR)

- [ ] Slice 1: Scaffold `packages/shared-contracts/`: `package.json`, `.gitignore` (node_modules only), `README.md` stub, empty `scripts/` directory. Run `npm install` (no deps yet) to produce a clean `package-lock.json`.
- [ ] Slice 2: Author `openapi.yaml` with `/healthz`. Add `@redocly/cli` (or `swagger-cli`) as devDep. Wire `npm run lint` to validate it. Confirm lint passes.
- [ ] Slice 3: Add `openapi-typescript` devDep + `scripts/gen-ts.mjs` + `npm run generate:ts`. Run it. Commit `apps/frontend/src/gen/api-types.ts`. Verify `apps/frontend` still builds.
- [ ] Slice 4: Add `scripts/gen-go.mjs` shelling out to `oapi-codegen` + `oapi-codegen-config.yaml` + `npm run generate:go`. Run it. Commit `apps/backend/api/oapi.gen.go`. Verify backend still builds (existing `/healthz` handler is unchanged).
- [ ] Slice 5: Add `npm run generate` (alias for `generate:ts && generate:go`) + `scripts/verify-no-drift.mjs` + `npm run verify-no-drift`. Update README with full workflow.

Dependencies between slices: linear (each builds on the previous). Slice 4 requires the backend skeleton from S1.2 to exist.

## Test plan

- Manual verification:
  1. Edit `openapi.yaml` to add a dummy field on `HealthResponse` (e.g., `uptime_seconds: integer`). Run `npm run generate`. Confirm both `api-types.ts` and `oapi.gen.go` reflect the new field. Run `verify-no-drift` (should pass). Revert the edit.
  2. Run `npm run generate` twice in a row. Second invocation must produce no git diff (idempotent).
  3. Delete the generated files, run `npm run verify-no-drift` — confirm it fails (drift detection works).
- Lint: `cd packages/shared-contracts && npm run lint` passes.
- Build (frontend): `cd apps/frontend && npm run build` passes with the generated types in `src/gen/`.
- Build (backend): `cd apps/backend && go build ./...` passes with the generated Go file in `api/`.
- Smoke tests: none added.

## Notes

- The generated files are committed (not gitignored) so PRs make contract changes reviewable. CI (S1.5) will run `verify-no-drift` to enforce that committed = generated.
- The backend continues to use the hand-rolled `/healthz` handler from S1.2 in this spec — wiring chi to the generated `ServerInterface` is a follow-up (could be an E4 spec where real endpoints arrive and the cost-benefit flips).
- This package is consumed via relative paths only (no npm publish). The frontend imports its TS types from `src/gen/`. The backend imports the generated Go file from `apps/backend/api/`.
- Per decision W, no npm workspaces are used — `packages/shared-contracts/` has its own `package.json` and is operated standalone.
