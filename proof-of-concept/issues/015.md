## Problem

Students need to solve programming tasks with automated test feedback. Tasks have a statement (MDX), starter code, hidden test cases, and scoring. Frontend executes student code locally (CheerpJ for Java), captures outputs, submits to backend. Backend keeps expected outputs hidden, compares submitted outputs, returns pass/fail per case + score.

## Goals

- Concrete decision on R (test case format) and S (validation flow) — emit follow-up ADR if needed (per deferred decisions in plan).
- Schema for tasks + submissions.
- `<TaskRunner taskId="..." />` MDX-embeddable widget that runs all test cases locally and submits results.
- Backend endpoint validating submission outputs against hidden expected.
- Submissions persisted (unlike session events — submissions are durable artifacts).
- Submission history per user.

## Non-goals

- Server-side compile-and-run for canonical validation (post-MVP per S decision; output-only validation for MVP).
- Sandboxing of arbitrary code execution.
- Anti-cheat hardening (educational context, not high-stakes assessment).
- Interactive task creation UI (tasks created as files in repo for MVP).
