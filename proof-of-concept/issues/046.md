## Problem

Per decision G', the source of truth for HTTP contracts between Go backend and React frontend is `packages/shared-contracts/openapi.yaml`. E1's baseline (assumed delivered) registered the package and codegen scripts but contained no real endpoints — just a healthcheck stub. S4.2 through S4.5 introduce six concrete endpoints (`/api/auth/google/start`, `/api/auth/google/callback`, `/api/auth/session` GET + DELETE, `/api/admin/enrollments`). This spec defines those endpoints in the OpenAPI document, regenerates Go server stubs and TypeScript types, wires the regen into a CI check that fails on drift, and lets the spec body of S4.2/S4.4/S4.5 cite the contract instead of duplicating schemas.

## Goals

- Add `paths` and `components.schemas` entries to `packages/shared-contracts/openapi.yaml` covering all six endpoints introduced in this epic.
- Regenerate Go server stubs (`oapi-codegen` server-side) into `apps/backend/internal/api/gen/`.
- Regenerate TypeScript types (`openapi-typescript`) into `apps/frontend/src/api/gen/types.d.ts`.
- Verify Go handlers in `internal/auth/handlers.go` + `internal/admin/enrollments.go` satisfy the generated interfaces.
- Update `apps/frontend/src/auth/api.js` and `apps/frontend/src/api/admin.js` to use the generated types (TS types via JSDoc `@type` or migration to .ts file if S4.5 already opened that door — out-of-scope for this spec, JSDoc is fine).
- CI workflow `.github/workflows/contracts-ci.yml` (assumed exists from E1) runs `npm run codegen` and `git diff --exit-code`; fails on uncommitted drift.

## Non-goals

- Introducing TypeScript to the whole frontend (out of scope; JSDoc with the generated `types.d.ts` is enough).
- A full API client generator (e.g., `openapi-fetch` or `orval`) — we stay with hand-rolled `fetch` + generated *types*. The "client" part is small enough that we don't need a runtime generator.
- Material Domain endpoints (`/api/content/*`) — those belong to E2.
- Session / live class endpoints — those belong to E5.
- Authn endpoints versioning — we use v1-by-convention (URLs are `/api/auth/...`, not `/api/v1/auth/...`); revisit at first breaking change.

## Design

### Endpoints to define in `openapi.yaml`

```yaml
openapi: 3.0.3
info:
  title: Nalanda API
  version: 0.1.0
servers:
  - url: /api
paths:
  /auth/google/start:
    get:
      operationId: authGoogleStart
      summary: Start Google OAuth flow
      tags: [auth]
      parameters:
        - in: query
          name: return_to
          schema: { type: string }
          required: false
      responses:
        '302':
          description: Redirect to Google consent screen
          headers:
            Location: { schema: { type: string } }

  /auth/google/callback:
    get:
      operationId: authGoogleCallback
      summary: Google OAuth callback
      tags: [auth]
      parameters:
        - in: query
          name: code
          schema: { type: string }
        - in: query
          name: state
          schema: { type: string }
      responses:
        '302':
          description: Redirect to return_to (or /) on success, /login?error=... on failure

  /auth/session:
    get:
      operationId: getSession
      summary: Get the current user from session cookie
      tags: [auth]
      responses:
        '200':
          description: Authenticated user
          content:
            application/json:
              schema: { $ref: '#/components/schemas/CurrentUser' }
        '401':
          description: Not authenticated
          content:
            application/json:
              schema: { $ref: '#/components/schemas/Error' }
    delete:
      operationId: deleteSession
      summary: Log out (clear session cookie)
      tags: [auth]
      responses:
        '204': { description: Logged out }

  /admin/enrollments:
    post:
      operationId: createEnrollments
      summary: Enroll a batch of students by email
      tags: [admin]
      requestBody:
        required: true
        content:
          application/json:
            schema: { $ref: '#/components/schemas/CreateEnrollmentsRequest' }
      responses:
        '200':
          description: Per-email results
          content:
            application/json:
              schema: { $ref: '#/components/schemas/CreateEnrollmentsResponse' }
        '400':
          description: Validation error
          content:
            application/json:
              schema: { $ref: '#/components/schemas/Error' }
        '403':
          description: Not authorized (must be admin)
          content:
            application/json:
              schema: { $ref: '#/components/schemas/Error' }

components:
  schemas:
    CurrentUser:
      type: object
      required: [id, email, role]
      properties:
        id:           { type: string, format: uuid }
        email:        { type: string, format: email }
        role:         { type: string, enum: [student, professor, admin] }
        display_name: { type: string, nullable: true }

    CreateEnrollmentsRequest:
      type: object
      required: [course_version_id, emails]
      properties:
        course_version_id: { type: string, format: uuid }
        emails:
          type: array
          minItems: 1
          maxItems: 500
          items: { type: string, format: email }

    CreateEnrollmentsResponse:
      type: object
      required: [results]
      properties:
        results:
          type: array
          items: { $ref: '#/components/schemas/EnrollmentResult' }

    EnrollmentResult:
      type: object
      required: [email, status]
      properties:
        email:   { type: string, format: email }
        status:  { type: string, enum: [created, enrolled, already_enrolled, email_failed, invalid_email] }
        user_id: { type: string, format: uuid, nullable: true }
        error:   { type: string, nullable: true }

    Error:
      type: object
      required: [error]
      properties:
        error:   { type: string }
        message: { type: string, nullable: true }
```

### Codegen pipeline

Files modified/added:

- `packages/shared-contracts/openapi.yaml` — extended with the above.
- `packages/shared-contracts/package.json` — `scripts.codegen` runs both generators.
- `packages/shared-contracts/scripts/codegen.sh` — one-shot script: invoke `oapi-codegen` for the Go server, `openapi-typescript` for the TS types. (Or whatever shape E1 established — this spec follows it.)
- `apps/backend/internal/api/gen/` — committed generated Go code (`-package gen -generate types,chi-server`). Output: `types.gen.go`, `server.gen.go`.
- `apps/frontend/src/api/gen/types.d.ts` — committed generated TS types.
- `apps/frontend/src/api/gen/.gitattributes` — mark as `linguist-generated=true` so they don't pollute repo language stats.

### Wiring Go handlers to generated interface

`oapi-codegen --generate chi-server` produces a `ServerInterface`. We have two paths:

1. **Strict**: handlers implement `ServerInterface`; chi mux is built by `HandlerFromMux(srv, r)`. Most type-safe.
2. **Pragmatic**: keep existing handler signatures, use generated types only for request/response. Less ceremony.

**Decision for this spec**: pragmatic (option 2). The generated **types** (`gen.CurrentUser`, `gen.CreateEnrollmentsRequest`, etc.) are imported by `internal/auth/` and `internal/admin/` and used in JSON encode/decode. The full `ServerInterface` migration is a future cleanup once the API surface stabilises.

This means S4.2 and S4.4 will get small follow-on edits in this spec's slices to replace their inline structs with `gen.*` types.

### CI workflow

`.github/workflows/contracts-ci.yml` (presumed-existing from E1) runs on PRs touching `packages/shared-contracts/**`, `apps/backend/internal/api/gen/**`, `apps/frontend/src/api/gen/**`:

```yaml
- run: npm --workspace packages/shared-contracts run codegen
- run: git diff --exit-code
```

If anyone edits `openapi.yaml` without regenerating, CI fails with a clear "drift detected — run `npm run codegen` and commit" message. Add a `CONTRIBUTING.md` snippet (or update existing) describing the workflow.

## Notes

- This spec is a **chore**: it changes no user-visible behavior. Its value is preventing future drift between Go and TS sides.
- The pragmatic stance (generated types only, not handler interface) keeps slice size manageable. Full `ServerInterface` migration is queued for a later refactor.
- If `oapi-codegen` or `openapi-typescript` version is not pinned in E1, this spec pins them in `packages/shared-contracts/package.json`.
