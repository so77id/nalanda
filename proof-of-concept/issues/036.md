## Problem

The POC's `Presentation` component computes slide boundaries by treating every `<h2>` as a new slide (visible in `src/widgets/presentation/Presentation.jsx`). That works for simple linear content but offers no control: you can't have a slide span multiple sections, you can't mark "show in book but not in slides", and you can't attach speaker notes. Per decision **E**, the way forward is explicit JSX markers in MDX content: `<Slide>`, `<BookOnly>`, `<PresentationOnly>`, `<TeacherNote>`, `<SectionBreak/>`.

This spec defines those marker components plus a parser that, given the children of an MDX-rendered section, computes a list of slides (with their content) for the presentation viewer. The components themselves render appropriately in *book* mode (where prose flows continuously) and *presentation* mode (where slides are discrete pages).

This spec ONLY defines the components and parser. It does NOT yet wire them into `Presentation.jsx` — that's S2.6.

## Goals

- Five marker components live in `src/widgets/presentation/markers/`:
  - `<Slide title="..." id="...">{children}</Slide>` — explicit slide boundary. In book mode: renders an `<h2>{title}</h2>` followed by children. In presentation mode: a discrete slide.
  - `<BookOnly>{children}</BookOnly>` — visible in book mode; hidden in presentation mode.
  - `<PresentationOnly>{children}</PresentationOnly>` — visible in presentation mode; hidden in book mode.
  - `<TeacherNote>{children}</TeacherNote>` — visible in presentation mode (in a small footer panel for the presenter); hidden in book mode by default.
  - `<SectionBreak/>` — self-closing. Causes a slide break in presentation mode without introducing a heading. In book mode renders a subtle visual divider (e.g. `<hr/>` styled).
- Components consume mode from a `PresentationModeContext` (defined in this spec). The context provides `mode: 'book' | 'presentation' | 'teacher'`. Default `'book'`.
- A pure parser function `computeSlides(children, { title, subtitle, summary })` that walks `Children.toArray(children)` and returns an array of slide objects:
  ```js
  [
    { kind: 'cover', title, subtitle, summary, content: [...] },
    { kind: 'slide', title: '...', id: '...', content: [...], teacherNotes: [...] },
    ...
  ]
  ```
  The parser MUST:
  - Group children up to the next `<Slide>`, `<SectionBreak/>`, or `<h2>` into the same slide.
  - Filter out `<BookOnly>` content when producing presentation slides.
  - Collect `<TeacherNote>` content separately, attached to the enclosing slide.
  - Fall back to `<h2>` as a boundary when no `<Slide>` markers exist (backward compatibility with current POC content).
- The parser is exported from `src/widgets/presentation/parser.js` (a separate module from `Presentation.jsx` so it's testable in isolation).
- Markers are exported from a single barrel `src/widgets/presentation/markers/index.js`.
- The `MDXProvider` from S2.1 is extended to register these markers globally so MDX files can use them without explicit imports (best UX for content authors).

## Non-goals

- Updating `Presentation.jsx` to use the parser — that's S2.6.
- Migrating POC lesson to use markers — that's S2.7 (or content authoring in E6).
- Slide transitions / animations — out of scope (presentation already uses simple show/hide).
- Speaker view (separate window with notes + next slide preview) — defer to a future polish ticket.

## Design

**Approach:**
- Each marker is a small React component that reads from a `PresentationModeContext` and conditionally renders. They don't compute slide boundaries themselves — they just render appropriately for the current mode.
- The parser is a pure function that knows about the marker components by reference (`child.type === Slide`, etc.). It runs once per render of the parent (memoized via `useMemo`).

**Architecture decisions consumed:**
- **E** — JSX slide markers (`<Slide>`, `<BookOnly>`, `<PresentationOnly>`, `<TeacherNote>`, `<SectionBreak/>`). Fallback to `<h2>` for unmarked content.
- **D** — Markers are JSX components, so they work natively inside MDX files.
- **X** — Material Domain: markers and parser deal only with content presentation.

**Files to create:**
- `src/widgets/presentation/markers/Slide.jsx`
- `src/widgets/presentation/markers/BookOnly.jsx`
- `src/widgets/presentation/markers/PresentationOnly.jsx`
- `src/widgets/presentation/markers/TeacherNote.jsx`
- `src/widgets/presentation/markers/SectionBreak.jsx`
- `src/widgets/presentation/markers/index.js` (barrel)
- `src/widgets/presentation/PresentationModeContext.jsx` (context + Provider + `usePresentationMode` hook)
- `src/widgets/presentation/parser.js` — `computeSlides(children, headerOpts)`.
- `src/widgets/presentation/parser.test.mjs` — node-based unit test for the parser (no React render needed, just JSX children mocking).
- Register markers in `MDXProvider` (in `src/App.jsx` or wherever the provider lives after routing refactor).

**Parser algorithm (pseudocode):**

```js
function computeSlides(children, { title, subtitle, summary }) {
  const arr = Children.toArray(children)
  const cover = { kind: 'cover', title, subtitle, summary, content: [] }
  const out = [cover]
  let current = cover
  let teacherNotes = []

  for (const child of arr) {
    if (child.type === Slide || child.type === SectionBreak) {
      // flush teacher notes to previous slide
      current.teacherNotes = teacherNotes
      teacherNotes = []
      // start new slide
      current = {
        kind: 'slide',
        title: child.props?.title,
        id: child.props?.id,
        content: child.type === Slide ? Children.toArray(child.props.children) : [],
      }
      out.push(current)
    } else if (child.type === 'h2') {
      // fallback path: h2 starts a new slide
      teacherNotes = []
      current = { kind: 'slide', titleNode: child, content: [] }
      out.push(current)
    } else if (child.type === BookOnly) {
      // skip in presentation; in book, the component itself handles rendering
      // BUT for the parser we keep it; rendering layer will filter
      current.content.push(child)
    } else if (child.type === TeacherNote) {
      teacherNotes.push(...Children.toArray(child.props.children))
    } else {
      current.content.push(child)
    }
  }
  current.teacherNotes = teacherNotes
  return out
}
```

The component-level filtering (BookOnly hidden in presentation, etc.) happens at render time via the context — the parser doesn't second-guess.

## Acceptance criteria

- [ ] AC1: All five marker components exist and export from `src/widgets/presentation/markers/index.js`.
- [ ] AC2: `PresentationModeContext` exists with `Provider` and `usePresentationMode()` hook. Default mode is `'book'`.
- [ ] AC3: `<BookOnly>` returns its children in book mode, `null` in presentation mode. Verify by rendering with mode='presentation' and asserting absence.
- [ ] AC4: `<PresentationOnly>` is the inverse of `<BookOnly>`.
- [ ] AC5: `<Slide title="X">` renders an `<h2>X</h2>` followed by children in book mode. In presentation mode, the parser uses it as a slide boundary; the component's render in presentation mode just unwraps children (the wrapper section is provided by `Presentation.jsx` in S2.6).
- [ ] AC6: `<TeacherNote>` returns `null` in book mode. In presentation mode (or teacher mode), it's stripped from the main slide flow by the parser and attached to slide metadata.
- [ ] AC7: `<SectionBreak/>` renders an `<hr/>` in book mode; in presentation mode, the parser uses it as a boundary, the component renders `null`.
- [ ] AC8: `computeSlides` returns a cover slide + N content slides. Verify via `parser.test.mjs` with mocked JSX children.
- [ ] AC9: Parser fallback to `<h2>` works: given content with no markers (current POC structure), `computeSlides` returns the same slide list shape.
- [ ] AC10: `MDXProvider` is updated to include all marker components so MDX files can use them without explicit imports. Verify with a sample `.mdx` file that uses `<Slide title="X">`.
- [ ] AC11: `npm run lint && npm run build` pass.

## Test plan

- **Unit test:** `parser.test.mjs` — run via `node --test` (Node's built-in test runner; no new dependencies). Tests:
  - Empty children → just cover slide.
  - Children with only h2s → cover + N slides (legacy fallback).
  - Children with `<Slide>` markers → cover + slides with titles/ids from props.
  - Mixed `<Slide>` and h2s → markers win (h2 inside a `<Slide>` is just content).
  - `<BookOnly>` content survives in slide.content.
  - `<TeacherNote>` content goes to slide.teacherNotes, not slide.content.
  - `<SectionBreak/>` starts a new slide without a title.
- **Manual verification:** Use a sample MDX file with all marker types. Render in book mode → BookOnly/SectionBreak visible, PresentationOnly/TeacherNote hidden. Toggle context to presentation mode (just for testing — full UI integration is S2.6) → opposite happens.
- **Lint + build:** pass.
