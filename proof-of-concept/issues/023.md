## Problem

Non-technical professors don't want to use git to edit course content. They need an in-browser editor (markdown side-by-side with live preview, ShareLatex-style) that saves to a backend. This is the natural evolution beyond fase 1's "files in repo".

This epic concretizes the deferred decision **O' (storage for fase 2+)** with the tentative recommendation Postgres TEXT + R2 for assets.

## Goals

- Concrete decision on O' (storage backend for editable content) — emit ADR.
- Editor UI: markdown source on left, live MDX-rendered preview on right.
- Autocompletion of widget tags (`<CodeEditor>`, `<BSTViz>`, etc.) and slide markers.
- Save flow: editor → backend → storage (whichever O' resolves to).
- Asset upload (images, PDFs) to R2.
- Migration path from "files in repo" to backend storage (graceful — both can coexist during transition).

## Non-goals

- Multi-author concurrent editing (CRDT, operational transform — too complex).
- Version history UI beyond simple "show previous version" (full git-style history is post-this).
- Drag-and-drop visual editing (markdown source remains canonical).
