## Problem

The backend exposes auth endpoints (S4.2: `/api/auth/google/start`, `/api/auth/session`, etc.) but the frontend has no concept of "current user" — there's no store, no login UI, no protected routes. Per decision F, client state lives in Zustand (with TanStack Query for server reads). This spec brings the user identity from the backend into the React app: a Zustand store, a `<LoginButton>`, a `useRequireAuth` hook to gate routes by role, a logout action, and the small machinery that consumes S4.2 and is consumed by S4.4 and every future authenticated page.

## Goals

- `useUserStore` (Zustand) with `{user, loading, error, hydrated, login, logout, refresh}`.
- On app mount, `refresh()` is called once: `GET /api/auth/session` → if 200, set user; if 401, clear user. Drives a loading splash so we don't flash an unauthenticated UI to an authenticated user.
- `<LoginButton>` component: a button that redirects to `/api/auth/google/start?return_to=<current_path>`.
- `<LogoutButton>` component: calls `DELETE /api/auth/session`, then `useUserStore.getState().logout()` (which clears the store and navigates to `/`).
- `useRequireAuth(role?)` hook: if no user → redirect to `/login?return_to=<current_path>`; if `role` provided and `user.role !== role` → redirect to `/forbidden`.
- A `<RequireAuth role?>` wrapper for declarative route gating in React Router setups (alternative to the hook).
- Post-login navigation: after callback, backend redirects to `oauth_return_to` cookie value → app lands on `/admin/enrollments` (or wherever) with the cookie set; the next `refresh()` populates the store.
- `/login` and `/forbidden` pages with minimal content.

## Non-goals

- TanStack Query setup at the app level (deferred — this spec uses plain `fetch` for the three calls; TanStack Query is introduced when the first server-state-heavy page exists, likely E5 or E6).
- A user dropdown / avatar menu in the layout — a placeholder `<LogoutButton>` is enough.
- Refresh token / silent refresh — JWT lifetime is 12h per S4.2; on expiry the user is redirected to `/login`.
- Multi-tab session sync (BroadcastChannel listening for logout in another tab) — deferred.

### Store shape

```js
const useUserStore = create((set, get) => ({
  user: null,             // { id, email, role, display_name } | null
  loading: false,
  error: null,
  hydrated: false,

  async refresh() {
    set({ loading: true, error: null });
    try {
      const res = await fetch('/api/auth/session', { credentials: 'include' });
      if (res.ok) {
        const user = await res.json();
        set({ user, loading: false, hydrated: true });
      } else if (res.status === 401) {
        set({ user: null, loading: false, hydrated: true });
      } else {
        set({ user: null, loading: false, hydrated: true, error: `session: ${res.status}` });
      }
    } catch (e) {
      set({ user: null, loading: false, hydrated: true, error: e.message });
    }
  },

  login(returnTo = window.location.pathname) {
    const url = `/api/auth/google/start?return_to=${encodeURIComponent(returnTo)}`;
    window.location.href = url;
  },

  async logout() {
    await fetch('/api/auth/session', { method: 'DELETE', credentials: 'include' });
    set({ user: null });
  },
}));
```

### `useRequireAuth`

```js
function useRequireAuth(role) {
  const { user, hydrated } = useUserStore();
  const navigate = useNavigate();
  const location = useLocation();
  useEffect(() => {
    if (!hydrated) return;
    if (!user) {
      navigate(`/login?return_to=${encodeURIComponent(location.pathname)}`, { replace: true });
      return;
    }
    if (role && user.role !== role) {
      navigate('/forbidden', { replace: true });
    }
  }, [user, hydrated, role, navigate, location.pathname]);
  return user;
}
```

### `<RequireAuth role?>`

A wrapper that calls `useRequireAuth(role)` and returns `null` while loading, `children` when allowed. Equivalent to the hook; choose by ergonomic preference at the call site.

### Login flow end-to-end

1. User visits `/admin/enrollments` (the S4.4 page).
2. `useRequireAuth('admin')` fires; user is null after `refresh()` returns 401 → redirect to `/login?return_to=/admin/enrollments`.
3. User clicks `<LoginButton>`; button reads `return_to` from query string (fallback to `/`) and redirects to `/api/auth/google/start?return_to=/admin/enrollments`.
4. Google consent → backend callback → cookie set → backend redirects to `/admin/enrollments` (per S4.2's `oauth_return_to` cookie).
5. App boots, `refresh()` returns user → `useRequireAuth('admin')` allows the page.

### Logout flow

1. User clicks `<LogoutButton>` in any header.
2. `DELETE /api/auth/session` clears the cookie server-side.
3. Store clears `user`; if the current page requires auth, the next render's `useRequireAuth` redirects to `/login`.

### Environment variables introduced

None — the frontend reads no env vars in this spec. (Future: maybe `VITE_API_BASE_URL` if dev proxying is replaced with absolute URLs, but for now we use relative `/api/...` paths.)

## Acceptance criteria

- [ ] AC1: `useUserStore` exists; `refresh()` is called on app mount; while loading, a splash is rendered; after settle, the app renders.
- [ ] AC2: With no session cookie, visiting `/admin/enrollments` redirects to `/login?return_to=/admin/enrollments`.
- [ ] AC3: Clicking `<LoginButton>` on `/login?return_to=/admin/enrollments` navigates to `/api/auth/google/start?return_to=%2Fadmin%2Fenrollments` (verifiable via `window.location.assign` spy or by inspecting the href).
- [ ] AC4: With a valid admin session cookie (manually set in dev), visiting `/admin/enrollments` renders the page (the S4.4 form) — verified manually in browser.
- [ ] AC5: With a valid **student** session cookie, visiting `/admin/enrollments` redirects to `/forbidden`.
- [ ] AC6: `<LogoutButton>` click: DELETE call goes out (network tab), store clears, next render of a protected page redirects to login.
- [ ] AC7: `?error=not_enrolled` on `/login` displays a friendly error message.
- [ ] AC8: ESLint clean, `npm run build` clean.
