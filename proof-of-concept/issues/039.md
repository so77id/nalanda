## Problem

Per decision I, the enrollment flow is: admin pre-enrolls an email → backend creates a `users` row → backend sends an invite email saying "you're enrolled in course X, log in with your Google account". Without this spec, S4.4 (the admin endpoint) would create rows silently and students would never know. This spec provides the email-sending capability: a thin wrapper around Resend's API, a templated invite email, and a single internal function `mailer.SendEnrollmentInvite(ctx, user, courseTitle, loginURL)` that S4.4 will call.

## Goals

- Add a `mailer` internal package wrapping the Resend REST API (`POST https://api.resend.com/emails`).
- Define a single template, `enrollment_invite`, with a clean HTML body + plaintext fallback, parameterised by `display_name` (optional fallback to "Hola"), `course_title`, `login_url`.
- Expose `mailer.SendEnrollmentInvite(ctx, user db.User, courseTitle string, loginURL string) error`.
- Make the mailer test-friendly: behind an interface so S4.4 tests don't actually hit Resend; a `NoopMailer` and a `RecordingMailer` for tests are provided.
- Wire the real `ResendMailer` into `cmd/server/main.go` selected when `RESEND_API_KEY` is present.
- Document required env vars in `apps/backend/README.md`.

## Non-goals

- A general email-sending abstraction (only the enrollment invite template for now; future emails are added in their own specs).
- Email open tracking, click tracking, bounce handling (deferred).
- Unsubscribe link UI (deferred; this is a transactional invite, not marketing).
- Queueing / retry on send failure (deferred — S4.4 will log the error and surface in the admin response; the admin can retry).
- Multi-language email (the invite is in Spanish, hardcoded — the course is in Spanish per CLAUDE.md user-facing content rule).

## Design

Files introduced or modified:

- `apps/backend/internal/mailer/mailer.go` — `Mailer` interface, `EnrollmentInviteData` struct, `SendEnrollmentInvite` method signature.
- `apps/backend/internal/mailer/resend.go` — `ResendMailer` impl. HTTP client with 10s timeout, JSON POST to Resend, error mapping.
- `apps/backend/internal/mailer/templates.go` — embedded HTML + plaintext templates via `embed.FS`, rendered with `text/template` and `html/template`.
- `apps/backend/internal/mailer/templates/enrollment_invite.html.tmpl` — HTML template.
- `apps/backend/internal/mailer/templates/enrollment_invite.txt.tmpl` — plaintext fallback.
- `apps/backend/internal/mailer/noop.go` — `NoopMailer` (logs the email it would have sent; used in dev when `RESEND_API_KEY` is absent).
- `apps/backend/internal/mailer/recording.go` — `RecordingMailer` for use in tests; captures all sent emails into a slice.
- `apps/backend/cmd/server/main.go` — instantiate the right mailer based on env config and pass it into the handlers (DI-by-constructor).
- `apps/backend/go.mod` — no new deps (uses stdlib `net/http`, `embed`, `text/template`, `html/template`).

### Interface

```go
package mailer

type Mailer interface {
    SendEnrollmentInvite(ctx context.Context, data EnrollmentInviteData) error
}

type EnrollmentInviteData struct {
    ToEmail      string
    DisplayName  string // may be empty
    CourseTitle  string
    LoginURL     string // e.g. "https://nalanda.xx/login"
}
```

### Resend impl

`POST https://api.resend.com/emails` with body:

```json
{
  "from": "Nalanda <noreply@<MAIL_FROM_DOMAIN>>",
  "to": ["<ToEmail>"],
  "subject": "Estás inscrito en <CourseTitle>",
  "html": "<rendered HTML>",
  "text": "<rendered text>"
}
```

Headers: `Authorization: Bearer <RESEND_API_KEY>`, `Content-Type: application/json`.

Behavior on non-2xx: read the response body, return a wrapped error with the HTTP status and Resend error message. No retry inside the mailer (callers decide).

### Selection at startup

```go
var m mailer.Mailer
if key := os.Getenv("RESEND_API_KEY"); key != "" {
    m = mailer.NewResendMailer(key, os.Getenv("MAIL_FROM_DOMAIN"))
} else {
    log.Println("RESEND_API_KEY not set; using NoopMailer (emails will be logged, not sent)")
    m = mailer.NewNoopMailer()
}
```

### Environment variables introduced by this spec

- `RESEND_API_KEY` — Resend API key. **Required for prod**, optional in dev (NoopMailer takes over). Stored as a Fly secret in prod.
- `MAIL_FROM_DOMAIN` — verified sending domain in Resend (e.g. `mail.nalanda.xx`). **Required** when `RESEND_API_KEY` is set.

## Notes

- The mailer is invoked by S4.4 inside the admin enrollment endpoint. This spec only delivers the capability.
- We accept the "fire-and-forget" model for MVP: if the email send fails, S4.4 surfaces it in the response and the admin retries. No background queue.
- Email content is hardcoded Spanish per CLAUDE.md (user-facing content language).
