## Problem

The current `src/widgets/presentation/Presentation.jsx` computes slide boundaries inline via a `useMemo` that walks children looking for `<h2>`. With S2.5 delivering the new marker components and parser, `Presentation.jsx` should delegate slide computation to the parser and provide the `PresentationModeContext` so markers render correctly in both modes.

The refactor must preserve the `<h2>` fallback so existing content (the POC lesson, which uses h2 without markers) keeps working until S2.7 explicitly migrates it.

## Goals

- Replace the inline `useMemo` slide-computation in `Presentation.jsx` with a call to `computeSlides(...)` from S2.5's `parser.js`.
- Wrap rendering in `<PresentationModeProvider>` and update `mode` based on the `presenting` state. When `presenting === true` → `mode='presentation'`. When `false` → `mode='book'`. Teacher-mode is reserved for future (no UI to set it yet).
- Preserve the existing cover-slide rendering, keyboard nav, navigation footer, theme toggle, slide counter, and progress bar — none of those change.
- Preserve `<h2>` fallback: when content has no `<Slide>` markers, slides come from h2 boundaries (parser already handles this; this spec just exercises it).
- Surface teacher notes from `slide.teacherNotes`: in presentation mode, render notes in a small panel (e.g. bottom-right, collapsible). Notes are visible only to whoever has the laptop — students see the slides via screen-share but the presenter view shows them.
- Update the `Presentation` component's prop documentation (in `IMPROVEMENTS.md` or via JSDoc) to mention the new marker-driven flow.

## Non-goals

- Removing h2 fallback (it stays — content authors can choose markers OR h2; both work).
- Changing the navigation UX or styling.
- Adding speaker view as a separate window.
- Migrating POC content to use markers — that is S2.7.
- New keyboard shortcuts beyond what exists.

## Design

**Approach:** Surgical refactor. The component shape stays the same; only the internals change. The slide rendering loop now respects `slide.kind === 'slide'` with optional `title`, `content`, `teacherNotes` fields.

**Architecture decisions consumed:**
- **E** — Use markers + h2 fallback.
- **X** — Material Domain.

**Files to modify:**
- `src/widgets/presentation/Presentation.jsx`:
  - Import `computeSlides` from `./parser.js`.
  - Replace the inline `useMemo` with `const slides = useMemo(() => computeSlides(children, { title, subtitle, summary }), [children, title, subtitle, summary])`.
  - Wrap returned JSX in `<PresentationModeProvider mode={presenting ? 'presentation' : 'book'}>`.
  - For each slide, render based on `slide.kind`. For `kind === 'slide'`: if `slide.title` (from `<Slide>` marker), render heading from prop; if `slide.titleNode` (from h2 fallback), render that; otherwise no heading (SectionBreak case). Then render `slide.content`.
  - Add a small `<TeacherNotesPanel/>` (new sub-component, can live inline in this file or as `src/widgets/presentation/TeacherNotesPanel.jsx`) that renders the active slide's `teacherNotes` when in presentation mode. Collapsible, bottom-right placement.
- `src/widgets/presentation/IMPROVEMENTS.md` — append a note about marker integration.
- `smoke-test-presentation.mjs` — re-run as-is (should still pass because h2 fallback is preserved). Optionally extend to verify a slide using `<Slide>` markers renders correctly when injected via a test MDX file.

**Mode toggle wiring:**

```jsx
<PresentationModeProvider mode={presenting ? 'presentation' : 'book'}>
  {/* existing JSX, with the slide render block adapted */}
</PresentationModeProvider>
```

**Teacher notes panel sketch:**
- Fixed position, bottom-right of presentation viewport.
- Collapsed by default. A small toggle button.
- Shows notes for the *current* slide only.
- Styled subtly so it doesn't dominate the slide view.

## Notes

- **TODO**: Teacher notes panel UI design — current spec assumes a simple collapsed bottom-right panel. If a richer "speaker view" (separate window) is desired, that's a follow-up.
- **TODO**: When `slide.title` (from `<Slide title="...">` prop) is provided in book mode, the marker component (per S2.5) already renders `<h2>{title}</h2>` itself. The parser stores the slide title separately for presentation-mode rendering. There's a risk of duplicate `h2` rendering in book mode if not careful. Solve in slice 2 by either (a) having the parser strip the title from book-mode content, or (b) having the marker NOT render its own h2 and let `Presentation.jsx` handle headings. Pick during implementation; document the choice.
- Domain: **Material Domain** (per ADR-0002). No backend.
- This spec is a `type:refactor` because the component shape and external API (`<Presentation subtitle title summary>{children}</Presentation>`) is unchanged. Only internals shift.
