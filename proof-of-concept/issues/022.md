## Problem

Professor B wants to use professor A's course as a base, modifying 3 sections. Currently this is impossible — there's no inheritance model, no fork mechanic.

This epic concretizes the deferred decisions **M (course inheritance model)** and **N (course versioning)** that were left open in the plan with tentative recommendations (M1 lazy resolution with overrides; N2 continuous + semester snapshots).

## Goals

- Concrete decision on M (inheritance resolution algorithm) and N (versioning model) — emit ADRs.
- Schema changes: `course_versions.parent_version_id`, `section_overrides` table or similar.
- Resolver in backend that walks parent chain for sections not overridden locally.
- UI "Fork course" action.
- Visual diff between forked version and parent (optional, useful).

## Non-goals

- Bidirectional sync (changes in parent don't backflow to fork automatically unless not overridden).
- Conflict resolution UI (the lazy resolution model avoids conflicts by design).

## Specs hijos

To be defined when the epic opens for refinement. First spec must concretize M + N decisions.

## Internal sequencing
