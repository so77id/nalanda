## Problem

The professor needs to start a live class session, students join via code or QR (after Google OAuth + enrollment check), and slides sync from professor to students in real time. Students can send back ephemeral signals (raise hand, reactions). Session state lives only in memory during the session — no event log persisted (per P decision).

## Goals

- Backend `sessions` table + lifecycle endpoints (start, get state, join, slide change, end).
- In-memory broadcaster abstraction supporting multiple connection topologies: 1:N (prof → students), N:1 (students → prof), 1:1 (prof → specific student), and forward-compatible with future NxN (peer groups).
- SSE endpoint as default transport (final SSE-vs-WS choice happens at S5.3 spec time per J decision).
- Frontend `/presenter` view (professor): session code + QR display + slide control.
- Frontend `/sessions/:code/student` view (student): slide sync, raise hand, reactions.
- `useSessionStore` (Zustand) consuming SSE.
- Smoke test with 2 puppeteer clients (1 professor + 1 student) verifying slide sync.

## Non-goals

- Persistent event log (P decision: no — ephemeral only).
- Chat (post-MVP).
- Polls (post-MVP).
- Anonymous join (deferred per I decision).
- Multiple sessions in parallel per professor (one active per professor in MVP).
