## Problem

Per decision I, the only authentication method in Nalanda is Google OAuth, and only emails pre-enrolled by an admin (S4.4) may log in. The backend needs to (1) start the OAuth dance, (2) handle the callback, (3) issue a JWT in an `httpOnly` cookie tied to the user row, and (4) provide middleware that downstream specs (S4.4, S4.5, E5, E7) use to require authentication and check roles. Without this spec, no protected endpoint can exist.

## Goals

- Implement `GET /api/auth/google/start` that generates a CSRF-resistant `state`, stashes it in a short-lived `httpOnly` cookie, and redirects to Google's consent screen.
- Implement `GET /api/auth/google/callback` that validates `state`, exchanges the `code` for tokens, verifies the Google ID token (`iss`, `aud`, `exp`, `sub`, `email`, `email_verified`), looks up the user by email, and either rejects (no row) or finalises (mint JWT, set `google_sub` if previously NULL).
- Implement `GET /api/auth/session` that returns the current user (`{id, email, role, display_name}`) or 401.
- Implement `DELETE /api/auth/session` that clears the cookie (logout).
- JWT signed HS256 with `JWT_SECRET`, in an `httpOnly` `Secure` `SameSite=Lax` cookie named `nalanda_session`.
- Middleware `auth.RequireUser` and `auth.RequireRole(role string)` consumable by any handler in the Administration Domain.

## Non-goals

- Refresh tokens / silent re-auth (out of scope for MVP — JWT lifetime is 12h and user re-clicks "Sign in with Google" on expiry).
- Multi-provider OAuth (only Google per decision I).
- Per-session revocation list (the JWT is stateless; logout = clear cookie. Acceptable for MVP).
- Frontend integration (S4.5).
- Email sending (S4.3).
- Creating users at login time — login NEVER creates rows; only S4.4 (admin enrollment) does. Mismatched emails get a 403 error redirect.

## Design

Files introduced or modified:

- `apps/backend/internal/auth/oauth.go` — Google OAuth client config (uses `golang.org/x/oauth2` + `golang.org/x/oauth2/google`).
- `apps/backend/internal/auth/handlers.go` — `StartHandler`, `CallbackHandler`, `SessionHandler`, `LogoutHandler`.
- `apps/backend/internal/auth/jwt.go` — `Mint(userID uuid.UUID, role string) (string, error)`, `Parse(token string) (*Claims, error)`. Uses `github.com/golang-jwt/jwt/v5`.
- `apps/backend/internal/auth/middleware.go` — `RequireUser(next http.Handler) http.Handler`, `RequireRole(role string) func(http.Handler) http.Handler`. Extracts the cookie, parses + verifies the JWT, loads the `User` from `internal/db`, injects into `context.Context` under a typed key.
- `apps/backend/internal/auth/context.go` — `UserFromContext(ctx) (db.User, bool)` typed accessor.
- `apps/backend/internal/auth/idtoken.go` — wraps `google.golang.org/api/idtoken` for ID token verification.
- `apps/backend/cmd/server/main.go` — mount routes `/api/auth/google/start`, `/api/auth/google/callback`, `/api/auth/session` (GET + DELETE) on the chi router.
- `apps/backend/go.mod` — add `golang.org/x/oauth2`, `google.golang.org/api/idtoken`, `github.com/golang-jwt/jwt/v5`.

### OAuth flow

1. Browser hits `/api/auth/google/start` (optionally with `?return_to=/some/path`).
2. Backend generates a random 32-byte `state`, base64url-encodes it, sets cookie `oauth_state` (`httpOnly`, `Secure`, `SameSite=Lax`, `Path=/api/auth/google/callback`, `Max-Age=300`). If `return_to` is provided and is a same-origin path, stash it in a parallel `oauth_return_to` cookie.
3. Redirect to Google with `client_id=$GOOGLE_OAUTH_CLIENT_ID`, `redirect_uri=$APP_BASE_URL/api/auth/google/callback`, `scope=openid email profile`, `state=<generated>`, `prompt=select_account`.
4. Google redirects back with `?code=...&state=...`.
5. Backend verifies `state` matches the cookie value, then exchanges `code` via `oauth2.Config.Exchange(ctx, code)`.
6. Backend calls `idtoken.Validate(ctx, idToken, GOOGLE_OAUTH_CLIENT_ID)` to verify the ID token. Pulls `sub`, `email`, `email_verified` (must be `true`), `name` (optional).
7. Lookup `FindUserByEmail(email)`:
   - Not found → respond 403 with redirect to `/login?error=not_enrolled`. **Do not create a user row.**
   - Found, `google_sub` NULL → call `SetUserGoogleSub(id, sub)`. (First-time login; binds the Google identity.)
   - Found, `google_sub` set and equal → continue.
   - Found, `google_sub` set and different → log a warning, reject 403 (`/login?error=account_mismatch`). (Defensive against email re-use.)
8. Mint JWT: payload `{sub: user.id, role: user.role, iat, exp = iat + 12h}`. Sign HS256 with `JWT_SECRET`.
9. Set cookie `nalanda_session` (`httpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, `Max-Age=43200`, value = JWT). Clear `oauth_state` + `oauth_return_to` cookies.
10. Redirect to `oauth_return_to` if set and same-origin, else to `/`.

### JWT claims

```go
type Claims struct {
    Sub  uuid.UUID `json:"sub"`
    Role string    `json:"role"`
    jwt.RegisteredClaims // for iat, exp, nbf
}
```

Lifetime 12h. Re-issued on each successful login. No rotation in MVP.

### Middleware

`RequireUser`:
1. Read `nalanda_session` cookie. Missing → 401 `{error: "not_authenticated"}`.
2. Parse + verify JWT signature with `JWT_SECRET`. Bad → 401.
3. Check `exp`. Expired → 401.
4. Load `db.User` by `claims.Sub`. Missing → 401 (defensive; the row was deleted while session active).
5. Inject `User` into context. Call `next`.

`RequireRole(role)`:
1. Run `RequireUser` first.
2. Compare `user.Role == role`. Mismatch → 403 `{error: "forbidden"}`.

### Endpoints summary

| Method | Path                          | Auth        | Description                                   |
|--------|-------------------------------|-------------|-----------------------------------------------|
| GET    | `/api/auth/google/start`      | none        | Start OAuth flow (302 to Google).             |
| GET    | `/api/auth/google/callback`   | none        | OAuth callback; sets cookie, redirects.       |
| GET    | `/api/auth/session`           | RequireUser | Return current user info.                     |
| DELETE | `/api/auth/session`           | none        | Clear cookie (idempotent).                    |

### Environment variables introduced by this spec

- `GOOGLE_OAUTH_CLIENT_ID` — from Google Cloud Console. **Required.**
- `GOOGLE_OAUTH_CLIENT_SECRET` — from Google Cloud Console. **Required.**
- `JWT_SECRET` — random 32+ byte string for HS256 signing. **Required.** In prod, store in Fly secrets; in dev, set in `apps/backend/.env`.
- `APP_BASE_URL` — e.g. `http://localhost:5173` (frontend dev) or `https://nalanda.xx` (prod). Used to build the OAuth `redirect_uri`. **Required.**

Notes:
- `redirect_uri` registered in Google Cloud Console must include both `http://localhost:8080/api/auth/google/callback` (dev — pointing at the Go backend, since the frontend proxies `/api/*` per E1 setup) and the prod URL.
- `Secure` flag on cookies — in dev (`http://localhost`) we set `Secure=false` only if `APP_BASE_URL` is `http`. Backend reads `APP_BASE_URL` to decide.

## Acceptance criteria

- [ ] AC1: Hitting `/api/auth/google/start` redirects to `https://accounts.google.com/...` with the expected query params (verifiable via `curl -I`).
- [ ] AC2: A successful callback with a pre-enrolled email sets a `nalanda_session` cookie, redirects to `/`, and a subsequent `GET /api/auth/session` returns the user JSON.
- [ ] AC3: A callback with a **non-enrolled** email returns 403 / redirects to `/login?error=not_enrolled` and does NOT create a row in `users`.
- [ ] AC4: A first-time login on a row with `google_sub IS NULL` updates the row's `google_sub` to the Google `sub` value (DB inspection confirms).
- [ ] AC5: `DELETE /api/auth/session` clears the cookie (response includes `Set-Cookie: nalanda_session=; Max-Age=0`) and subsequent `GET /api/auth/session` returns 401.
- [ ] AC6: `RequireRole("admin")` rejects a `student`-role JWT with 403 and accepts an `admin`-role JWT with 200 (verified by a smoke handler that mounts `/api/auth/_admin_ping` behind it during the spec — handler removed before merge OR kept as `/healthz`-style sanity).
- [ ] AC7: Tampered JWT (changed signature, altered `role` claim) is rejected with 401.
- [ ] AC8: `go vet ./...`, `go test ./internal/auth/...`, lint clean.
