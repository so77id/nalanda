## Problem

Today all content lives hardcoded in `src/App.jsx` as a single lesson written in JSX. To scale to a multi-chapter, multi-course platform we need a real content pipeline: MDX-based authoring, a content model, routing with TOC navigation, and a slide-mapping system that lets the same section serve as both reading material AND as a slide deck (with section-level control over which parts go where).

This epic lives entirely in the **Material Domain** (per ADR-0002). It produces no per-user state, no DB tables, no auth requirements. Its job is to deliver the substrate that course content gets written into.

## Goals

- File-based content under `apps/frontend/src/content/courses/<slug>/<chapter>/<section>.mdx`, glob-imported by Vite at build time.
- `SectionLoader` abstraction (`useSection` hook) so the storage backend can swap in fase 2+ without rewriting content consumers.
- React Router v6 routing: `/`, `/courses/:slug`, `/courses/:slug/:chapter/:section`.
- Sidebar TOC navigation + breadcrumbs.
- MDX setup with `@mdx-js/rollup` Vite plugin. Hot reload functional.
- Slide markers: `<Slide title="...">`, `<BookOnly>`, `<PresentationOnly>`, `<TeacherNote>`, `<SectionBreak />`. Fallback to `<h2>` boundary when no markers exist (backward-compatible with POC).
- Refactor `Presentation` component to consume markers.
- POC's "Listas Enlazadas" lesson migrated to the new structure as proof of concept.

## Non-goals

- In-browser editor (that's D6/E11).
- Multi-course (just the one is fine; loader supports more, but only one is wired up).
- Course inheritance / forking (M decision, deferred to D5/E10).
- Storage backend for fase 2+ (O' decision, deferred to D6/E11).
- Anything that requires the backend.
