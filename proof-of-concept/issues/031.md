## Problem

The Administration Domain (per ADR-0002) requires a persistent identity model. Today the backend Go skeleton (delivered in E1) has no schema, no migrations, and no SQL queries. Every other spec in E4 — Google OAuth (S4.2), invite emails (S4.3), admin enrollment (S4.4), frontend session (S4.5) — depends on the existence of `users` and `enrollments` tables plus typed Go accessors generated by `sqlc`. This spec lays the foundation.

## Goals

- Add `goose` (per decision G) migration tooling to `apps/backend/` with a `make migrate-up` / `make migrate-down` developer workflow against the local Postgres in `docker-compose.yml`.
- Introduce migration `001_users.sql` with the canonical user shape used across all Administration features.
- Introduce migration `002_enrollments.sql` linking users to a course version with the natural composite primary key.
- Wire `sqlc` (per decision G) to generate typed Go code from SQL queries colocated under `apps/backend/queries/`.
- Provide a minimum set of queries that downstream specs in this epic will consume.
- Connection pool + DSN configuration via `DATABASE_URL` env var (decision H).

## Non-goals

- Login flow / OAuth (S4.2).
- Email sending / Resend (S4.3).
- API handlers that touch these tables (S4.4 owns the admin enrollment endpoint; S4.2 owns user lookup at login).
- Course / course_version tables (these belong to the Material Domain, owned by E2). For now `course_version_id UUID` is stored opaquely with **no FK** — the FK is added by E2 when those tables exist.
- Indexes for performance tuning (only the index strictly required for `FindUserByEmail` lookup is added).

## Design

Files introduced or modified:

- `apps/backend/migrations/001_users.sql` — goose-format migration with `-- +goose Up` / `-- +goose Down` markers.
- `apps/backend/migrations/002_enrollments.sql` — same format.
- `apps/backend/queries/users.sql` — sqlc query annotations for `CreateUser`, `FindUserByEmail`, `FindUserByID`, `SetUserGoogleSub`.
- `apps/backend/queries/enrollments.sql` — `CreateEnrollment`, `ListEnrollmentsForUser`, `EnrollmentExists`.
- `apps/backend/sqlc.yaml` — sqlc config: `engine: postgresql`, `queries: ./queries`, `schema: ./migrations`, output package `internal/db`.
- `apps/backend/internal/db/` — sqlc-generated (`models.go`, `queries.sql.go`, `db.go`). Committed.
- `apps/backend/internal/db/pool.go` — `pgxpool.Pool` setup reading `DATABASE_URL`, exported `Open(ctx)` helper.
- `apps/backend/cmd/server/main.go` — wire pool open + graceful shutdown (close on SIGINT/SIGTERM).
- `apps/backend/Makefile` — `migrate-up`, `migrate-down`, `migrate-status`, `sqlc-gen` targets.
- `apps/backend/go.mod` — add `github.com/pressly/goose/v3`, `github.com/jackc/pgx/v5`, `github.com/jackc/pgx/v5/pgxpool`, `github.com/google/uuid`. `sqlc` itself is a CLI tool, not a runtime dep.

### Schema — `001_users.sql`

```sql
-- +goose Up
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE TABLE users (
    id            UUID         PRIMARY KEY DEFAULT gen_random_uuid(),
    email         TEXT         NOT NULL UNIQUE,
    role          TEXT         NOT NULL CHECK (role IN ('student','professor','admin')),
    display_name  TEXT,
    google_sub    TEXT         UNIQUE,
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

CREATE INDEX users_email_lower_idx ON users (LOWER(email));

-- +goose Down
DROP INDEX IF EXISTS users_email_lower_idx;
DROP TABLE IF EXISTS users;
```

Notes:
- `email` is normalized to lowercase by the application layer (S4.2/S4.4) before insert/lookup; the `users_email_lower_idx` exists in case any future lookup does case-insensitive search.
- `google_sub` is nullable: pre-enrolled users have no Google identity yet (decision I). It is `UNIQUE` to avoid two rows claiming the same Google identity.
- Role enum is a CHECK constraint, not a Postgres `ENUM` type, to keep migrations cheap to extend.

### Schema — `002_enrollments.sql`

```sql
-- +goose Up
CREATE TABLE enrollments (
    user_id            UUID         NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    course_version_id  UUID         NOT NULL,
    enrolled_at        TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    PRIMARY KEY (user_id, course_version_id)
);

CREATE INDEX enrollments_user_idx ON enrollments (user_id);

-- +goose Down
DROP TABLE IF EXISTS enrollments;
```

Notes:
- No FK on `course_version_id` until the Material Domain (E2) introduces `course_versions`. This is the documented cross-domain rule from ADR-0002 (Administration may FK to Material — once Material exists).
- `enrollments_user_idx` supports `ListEnrollmentsForUser` (used at every authenticated request to verify access — added at this spec because the cost is negligible and S4.5 will use it on first paint).

### Queries — `queries/users.sql`

```sql
-- name: CreateUser :one
INSERT INTO users (email, role, display_name)
VALUES ($1, $2, $3)
RETURNING *;

-- name: FindUserByEmail :one
SELECT * FROM users WHERE LOWER(email) = LOWER($1);

-- name: FindUserByID :one
SELECT * FROM users WHERE id = $1;

-- name: SetUserGoogleSub :one
UPDATE users SET google_sub = $2 WHERE id = $1 RETURNING *;
```

### Queries — `queries/enrollments.sql`

```sql
-- name: CreateEnrollment :exec
INSERT INTO enrollments (user_id, course_version_id) VALUES ($1, $2)
ON CONFLICT (user_id, course_version_id) DO NOTHING;

-- name: ListEnrollmentsForUser :many
SELECT * FROM enrollments WHERE user_id = $1 ORDER BY enrolled_at DESC;

-- name: EnrollmentExists :one
SELECT EXISTS (SELECT 1 FROM enrollments WHERE user_id = $1 AND course_version_id = $2);
```

### Connection pool — `internal/db/pool.go`

`Open(ctx)` calls `pgxpool.New(ctx, os.Getenv("DATABASE_URL"))`, applies sane defaults (`MaxConns=10`, `MaxConnLifetime=30m`), pings, and returns the pool. Main calls `pool.Close()` on shutdown.

### Environment variables introduced by this spec

- `DATABASE_URL` — Postgres DSN, e.g. `postgres://nalanda:nalanda@localhost:5432/nalanda?sslmode=disable` for local docker-compose. **Required.** Documented in `apps/backend/README.md`.
