## Problem

The platform needs an operational backend with: Postgres connectivity, the first migrations (users + enrollments), Google OAuth login flow, JWT session cookies, admin pre-enrollment via CSV upload, and Resend-powered invite emails. Frontend needs a login UI, a Zustand user store, and protected routes.

Without this epic, no user can log in, no enrollment exists, no session lifecycle can start. It's the spine of the Administration Domain (per ADR-0002).

## Goals

- Backend Go service with `chi` router fully wired (extending the E1 skeleton): config loader, structured logging, Postgres connection pool, graceful shutdown.
- First migrations: `001_users.sql` (id, email UNIQUE, role, display_name, google_sub, created_at) and `002_enrollments.sql` (user_id, course_version_id, enrolled_at).
- Google OAuth flow: `/api/auth/google/start` → Google consent → `/api/auth/google/callback` → JWT minted into `httpOnly` `Secure` `SameSite=Lax` cookie.
- Admin endpoint: `POST /api/admin/enrollments` accepting list of emails + course_version_id → creates `users` rows (or matches existing) + creates `enrollments` rows + queues invite emails.
- Resend integration: invite email template ("you've been enrolled, log in with your Google account").
- Frontend: `useUserStore` (Zustand), login button → OAuth redirect, protected route HOC, simple admin UI to upload CSV of student emails.
- OpenAPI contracts (in `packages/shared-contracts/`) for all the auth + enrollment endpoints.

## Non-goals

- Live class sessions (E5).
- Multi-role dashboards beyond the minimum needed to enroll students (E9 owns that).
- Anonymous join (deferred — only pre-enrolled with Google for MVP per I decision).
- Course content endpoints (those belong to Material Domain endpoints in E2; this epic is Administration Domain).

## Internal sequencing

S4.1 (schema) first — everything depends on it. Then S4.2 (OAuth) and S4.6 (contracts) in parallel. S4.3 (Resend) follows S4.1. S4.4 (admin endpoint) needs S4.1, S4.2, S4.3. S4.5 (frontend integration) needs S4.2 and S4.6 (typed contracts).

## Architecture decisions referenced

- F — Zustand for client state (`useUserStore`); TanStack Query for server reads
- G — Go + chi + sqlc + goose
- G' — OpenAPI contracts via oapi-codegen
- H — Postgres (docker-compose local, Neon free in prod), schema incremental per spec
- I — Google OAuth + pre-enrollment by admin + Resend invite email
- X — Administration Domain (`/api/admin/...`, `/api/auth/...`, requires auth + role/enrollment)
