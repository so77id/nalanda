## Problem

The current Nalanda POC is a single-package frontend. The platform expansion (per the architecture plan) requires a monorepo housing frontend (Vite/React) and backend (Go), shared OpenAPI contracts, Terraform-managed infrastructure, and CI/CD pipelines that run independently per application. None of this exists today.

We need to land this foundational reorganization without breaking the working POC, so that subsequent epics (E2 Content Pipeline, E3 Java Runtime, E4 Backend & Auth) can all build on it in parallel.

## Goals

- Reorganize repo to `apps/frontend/` + `apps/backend/` + `packages/shared-contracts/` + `infra/` + `docs/` + `.github/workflows/`.
- Backend Go skeleton up and running with `chi` router and a healthcheck endpoint.
- `packages/shared-contracts/` set up with OpenAPI 3 baseline + `oapi-codegen` scripts producing TS types (for frontend) and Go server stubs (for backend).
- Terraform `infra/` modules for the chosen hosting stack (Cloudflare Pages, Fly.io, Neon, R2) with a `prod` environment definition.
- Four GitHub Actions workflows with path filters: `frontend-ci`, `backend-ci`, `contracts-ci`, `infra-ci`. Independent triggers, independent deploys.
- Local dev environment: `docker-compose.yml` with PostgreSQL 16 and a `make dev` (or equivalent) entrypoint.
- POC continues to function before, during, and after the migration. Smoke tests still pass.

## Non-goals

- Bundle size optimization or runtime performance tuning.
- Production monitoring / observability stack (Sentry et al. are E8 Polish & Stability).
- Any business feature work — this epic is pure infrastructure.
- Backend feature endpoints beyond healthcheck (those belong in E4).

## Internal sequencing

S1.1 (#25) first (unblocks everything). After S1.1: S1.2 (#28, backend skeleton) and S1.4 (#37, Terraform) can proceed in parallel. S1.3 (#32, contracts) depends on S1.2. S1.5 (#41, CI) depends on S1.1 + S1.2 (it needs both apps to test). S1.6 (#42, docker-compose) depends on S1.2.
