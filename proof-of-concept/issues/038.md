## Problem

After S3.2 (runtime files) and S3.3 (UI integration), there's no automated end-to-end verification that Java compilation and execution actually work in a real browser. The existing smoke test pattern (`smoke-test-multilang.mjs`, `smoke-test-globalang.mjs`) uses `puppeteer-core` to drive a real Chrome against `npm run dev`, expand a runner, wait for warm, click run, and assert on the output text. We need the equivalent for Java.

This is the closing spec of E3: it certifies the epic is done.

## Goals

- Add `smoke-test-java.mjs` to the repo root, mirroring the structure of `smoke-test-multilang.mjs`.
- The smoke test exercises the full happy path AND error path:
  1. **Compile + run "Hello, World!"** — output contains `Hello, World!`.
  2. **Run a program that reads stdin** — supply a multi-line stdin (e.g. two integers), compute `n^2` and `m^2`, output matches.
  3. **Compile error surfacing** — modify code to have a syntax error (e.g. remove a semicolon), assert that the `errores` panel contains a non-empty compiler message AND the `stdout` panel is empty / shows fallback.
- The smoke test runs against `npm run dev` on `http://localhost:5173/` (the same URL pattern the other smoke tests use). The CI/dev story for "start dev server before running smoke" is whatever the existing smoke tests assume (manual today).
- The smoke test exits with non-zero on any of: page errors, console errors, assertion failures, timeouts.
- Document in the issue PR how to run it locally (`node smoke-test-java.mjs` after `npm run dev`).

## Non-goals

- Adding the smoke test to CI (no CI for smoke today; deferred until D4 / E8 Polish & Stability).
- Performance benchmarks (this spec is correctness, not perf).
- Stress testing (no parallel-worker tests).
- Testing variants other than the one S3.3 wires up. We test ONE variant end-to-end; variant matrix verification was done manually in S3.3.
- Server-side compilation tests (deferred).
- Headless vs headed nuance — match existing pattern (headless: true).

## Design

**File to create:** `smoke-test-java.mjs` at repo root (NOT `apps/frontend/` even after S1.1 reorg — smoke tests stay at repo root per existing convention; verify before moving).

**Structure (mirroring `smoke-test-multilang.mjs`):**

```js
import puppeteer from 'puppeteer-core'

const CHROME = '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'
const URL = 'http://localhost:5173/'

const browser = await puppeteer.launch({
  executablePath: CHROME,
  headless: true,
  args: ['--no-sandbox', '--disable-setuid-sandbox'],
})
const page = await browser.newPage()
await page.setViewport({ width: 1280, height: 900 })

const errs = []
page.on('pageerror', (e) => errs.push(`pageerror: ${e.message}`))
page.on('console', (m) => {
  if (m.type() === 'error') errs.push(`console.error: ${m.text()}`)
})

console.log('→ loading', URL)
await page.goto(URL, { waitUntil: 'networkidle2', timeout: 60000 })

// 1. Locate the Java <CodeEditor>. Strategy: expand it and assert via the language picker showing 'java' as the active value.
// 2. Wait for warm (CheerpJ ~10-20s first time; budget 60s).
// 3. Type a "Hello, World!" Java program into CodeMirror.
// 4. Click Ejecutar, wait for output, assert stdout contains 'Hello, World!'.
// 5. Type a program that reads stdin (two integers, prints squares).
//    Fill stdin with "3
4
", Ejecutar, assert output contains '9' and '16'.
// 6. Type a program with a syntax error, Ejecutar, assert 'errores' panel non-empty AND stdout empty.
// 7. Take screenshots at each step (smoke-test-java-{hello,stdin,error}.png).
// 8. If errs.length > 0 OR any assertion failed, console.log + process.exit(1).

await browser.close()
```

**Concrete assertions** (the exact selectors mirror those in `smoke-test-multilang.mjs`):

1. **Find the Java editor**: the test expects S3.3 to provide a Java editor at a known position on the page. Strategy: locate all language selectors, pick the one whose `value` is `'java'`, ascend to its containing `CodeEditor`. If S3.3 added the Java editor as the third runner on the page, we can also use `document.querySelectorAll('button[title="Pantalla completa"]')[2]`. Coordinate with S3.3's actual layout in implementation; pick a strategy that is robust to ordering changes (selectors over indices).

2. **Warm wait**: loop up to 60s checking for `'● listo'` text in the fullscreen container (CheerpJ first warm-up can take 10-20s, conservative budget).

3. **Setting code**: CodeMirror 6 — set code by focusing the editor and using `page.keyboard.type()` after clearing, OR by directly calling the CodeMirror API via `page.evaluate`. Look at how `smoke-test-multilang.mjs` does it (today it relies on the default code — for stdin/error tests we'll need to actually edit). If editing via keyboard typing is brittle, prefer dispatching CodeMirror state updates via `cmView.dispatch`.

4. **Stdin**: the `<textarea>` for stdin (variant `lab`) has placeholder `"(entrada opcional)"` — use that selector or DOM order to locate it.

5. **Output**: read from `<pre>` elements inside the fullscreen container, matching strings.

6. **Compile error**: assert the `errores` panel (`<pre>` after the strip labeled `errores`) is non-empty AND that the stdout panel is either empty or showing the fallback placeholder.

**Decisions referenced:**
- **K** — runtime is CheerpJ; the smoke runs against a real CheerpJ load.
- **L** (Fase A) — no server involved.

**Dependency:** Java program samples used by the smoke test go inline in the script, NOT in repo source. The dev page provides the *mount* but the smoke test provides the *code under test*.

## Acceptance criteria

- [ ] AC1: `smoke-test-java.mjs` exists at repo root, executable as `node smoke-test-java.mjs` against `npm run dev` on port 5173.
- [ ] AC2: Test 1 (Hello World) — script asserts that after compile + run, output contains `Hello, World!` and `exit 0` chip appears.
- [ ] AC3: Test 2 (stdin) — script sets a program that reads two integers from stdin and prints their squares, fills stdin with `3
4
`, runs, asserts output contains both `9` and `16`.
- [ ] AC4: Test 3 (compile error) — script sets a Java program with a syntax error, runs, asserts `errores` panel is non-empty and stdout panel is empty / placeholder.
- [ ] AC5: Test exits with code 0 on full success, code 1 on any assertion failure / console error / page error / timeout.
- [ ] AC6: Test produces screenshots `smoke-test-java-hello.png`, `smoke-test-java-stdin.png`, `smoke-test-java-error.png` (mirroring how `smoke-test-multilang.mjs` writes PNGs).
- [ ] AC7: Test handles CheerpJ's first-load latency (~10-20s) with a generous warm timeout (≥60s).
- [ ] AC8: Lint passes (`npm run lint`).
- [ ] AC9: Build passes (`npm run build`).
- [ ] AC10: README or `docs/conventions.md` (whichever is canonical for "how to run smoke tests") mentions `smoke-test-java.mjs`. (Optional; only if other smoke tests are documented.)

## Slices (1 slice = 1 commit)

- [ ] Slice 1: Skeleton — copy `smoke-test-multilang.mjs` to `smoke-test-java.mjs`, strip cpp/python paths, replace with Java path. Get Test 1 (Hello World) passing locally. Commit.
- [ ] Slice 2: Add Test 2 (stdin). Implement the program-source + stdin injection. Verify locally. Commit.
- [ ] Slice 3: Add Test 3 (compile error). Verify locally. Commit.

If the implementer finds editing CodeMirror via Puppeteer brittle in Slice 2, they may consolidate Slices 2+3 into one commit that uses a more reliable approach (e.g. exposing a `window.__nalandaTest.setEditorContent()` helper for the duration of the smoke test).

## Test plan

- This *is* the test plan for E3. Self-referential — running this smoke test IS the verification.
- Run order:
  1. `npm install` (if first time)
  2. `npm run dev` in one terminal
  3. `node smoke-test-java.mjs` in another
  4. Inspect screenshots
  5. Exit 0 + no errors → epic done.
- Lint: `npm run lint`.
- Build: `npm run build`.
- Manual: also run cpp/python smoke tests (`smoke-test-multilang.mjs`) once to confirm no regression from the Java changes.
