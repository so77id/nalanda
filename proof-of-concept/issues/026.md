## Problem

ADR-0003 commits to CheerpJ 3.0 (Leaning Technologies) for in-browser Java execution under their educational/non-commercial license. Before we write a single line of integration code (S3.2-S3.4) we must confirm the license actually covers our concrete use case: a Chilean university course (PUC / U.Chile / similar) where students execute student-written Java code in the browser as part of regular coursework, on a site that may eventually carry a "Powered by Nalanda" attribution and (post-MVP) host multiple courses.

If the license does NOT cover us, this entire epic pivots to server-side `javac`+`java` in a sandbox (Camino 2 in ADR-0003) and S3.2-S3.4 are rewritten. So S3.1 is a **hard blocker** for the rest of E3.

## Goals

- Read the current CheerpJ 3.0 commercial / non-commercial license terms (Leaning Technologies website + the runtime's own NOTICE/LICENSE files in the distributed bundle).
- Determine whether our use qualifies as "non-commercial / educational" under their terms. Concretely answer:
  - Are Chilean public/private universities explicitly covered?
  - Does "free for non-commercial use" cover a site that hosts coursework but is not sold and has no paid tier in MVP?
  - Are there attribution requirements? (logo, link, splash screen.)
  - Are there usage-volume caps (requests/day, MAU)?
  - Are there hosting restrictions (must be on our own domain vs CDN)?
- If anything is ambiguous, reach out to `info@leaningtech.com` (or equivalent) requesting written clarification. Record the response.
- Produce a short follow-up note attached to ADR-0003 with the verdict:
  - **OK** → epic proceeds as planned (S3.2 → S3.3 → S3.4).
  - **NOT OK** → write ADR-0004 superseding 0003, epic pivots to server-side compilation, and the parent epic body + S3.2-S3.4 must be rewritten by the user (this spec only records the verdict).

## Non-goals

- Implementing any Java runtime code (that's S3.2).
- Negotiating a commercial license (out of MVP budget — if non-commercial doesn't cover us, we pivot).
- Benchmarking warm time / bundle size (deferred to S3.2 where the worker actually runs).
- Drafting ADR-0004 if pivot is needed — that's a separate task triggered by this spec's verdict.

## Design

The artefact is a documentation update, not code. Two possible shapes:

1. **Preferred**: append a `## Follow-up: License verification (2026-MM-DD)` section to `docs/decisions/0003-java-runtime-cheerpj-with-pivot-path.md` containing:
   - Sources consulted (URLs with snapshot date, since terms change).
   - Quoted license clauses relevant to our case.
   - Verdict: OK / NOT OK / NEEDS-CONTACT.
   - If contact was required: the email thread (redacted), date, and the named representative's response.
   - Attribution requirements (if any) — recorded so S3.2 can comply (e.g., "must show CheerpJ logo on first load").

2. **Fallback**: if the verdict is NOT OK, create `docs/decisions/0004-pivot-to-server-side-java.md` that supersedes 0003, and add a `Status: Superseded by ADR-0004` line at the top of 0003.
