## Problem

The platform's local dev environment is currently a single `npm run dev` for the frontend. Once the backend (Go + chi from S1.2) lands and depends on Postgres (per decision H), a new developer needs to: install Go, install Postgres locally, create a database, configure env vars, and start three processes. Without a one-command entrypoint, the cost of starting work each morning grows and new contributors stall on setup.

This spec lands a `docker-compose.yml` at the repo root that runs PostgreSQL 16, plus a `Makefile` (or `scripts/dev.sh`) at the repo root that becomes the canonical entrypoint: `make dev` boots everything a developer needs. The frontend dev server and the Go backend continue to run on the host (better hot-reload), but the database runs in Docker.

## Goals

- Create a root-level `docker-compose.yml` that runs PostgreSQL 16 with a persistent volume.
- Create a root-level `Makefile` with targets that cover the common dev workflows.
- Create an `.env.example` at the repo root documenting required env vars (frontend + backend + tools).
- Provide a documented "first-time setup" sequence in the root README that a new contributor can follow top-to-bottom and end with a running frontend, running backend, and reachable Postgres.
- The setup works on macOS and Linux (Windows via WSL2 acceptable, not first-class).

## Non-goals

- Putting the frontend or backend processes inside Docker for dev (worse hot-reload story; deferred — they run on host).
- A production Dockerfile for the backend (`flyctl deploy` builds the image; the production Dockerfile if needed lives with the backend code, not in this spec).
- Database seeding with fake data (no migrations exist yet — those arrive with E4 specs).
- Database backup/restore scripts (operations concern, post-MVP).
- Devcontainers (`.devcontainer/`) — out of scope; can be added later if requested.
- Migration runner wiring (`goose up`) — arrives with the first E4 spec that introduces migrations.

## Design

**Reference decisions:** H (Postgres in Docker for dev, Neon in prod), G (Go backend), A (monorepo).

**`docker-compose.yml` at repo root:**

```yaml
services:
  postgres:
    image: postgres:16-alpine
    container_name: nalanda-postgres
    restart: unless-stopped
    environment:
      POSTGRES_USER: nalanda
      POSTGRES_PASSWORD: nalanda
      POSTGRES_DB: nalanda
    ports:
      - "5432:5432"
    volumes:
      - nalanda-pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U nalanda -d nalanda"]
      interval: 5s
      timeout: 5s
      retries: 10

volumes:
  nalanda-pgdata:
```

**`.env.example` at repo root:**

```
# Backend (apps/backend/)
DATABASE_URL=postgres://nalanda:nalanda@localhost:5432/nalanda?sslmode=disable
PORT=8080
LOG_LEVEL=debug

# Frontend (apps/frontend/) — Vite reads from .env, but documented here for completeness
VITE_API_BASE_URL=http://localhost:8080
```

Contributors copy this to `.env` (per-app) at first setup. `.env` is gitignored.

**Root `Makefile`:**

```makefile
.PHONY: help dev db-up db-down db-logs db-shell frontend backend lint test clean

help:
	@echo "Available targets:"
	@echo "  dev          - start postgres in docker, print next-step instructions"
	@echo "  db-up        - start postgres container"
	@echo "  db-down      - stop postgres container"
	@echo "  db-logs      - tail postgres logs"
	@echo "  db-shell     - psql into the running postgres"
	@echo "  frontend     - run frontend dev server (cd apps/frontend && npm run dev)"
	@echo "  backend      - run backend dev server (cd apps/backend && go run ./cmd/server)"
	@echo "  lint         - run frontend lint + backend vet"
	@echo "  test         - run frontend smoke tests + backend go tests"
	@echo "  clean        - stop containers and remove volumes (destructive)"

dev: db-up
	@echo ""
	@echo "Postgres is up at localhost:5432 (user/pass/db: nalanda/nalanda/nalanda)."
	@echo "Open two more terminals and run:"
	@echo "  make frontend   # http://localhost:5173"
	@echo "  make backend    # http://localhost:8080"

db-up:
	docker compose up -d postgres

db-down:
	docker compose stop postgres

db-logs:
	docker compose logs -f postgres

db-shell:
	docker compose exec postgres psql -U nalanda -d nalanda

frontend:
	cd apps/frontend && npm run dev

backend:
	cd apps/backend && go run ./cmd/server

lint:
	cd apps/frontend && npm run lint
	cd apps/backend && go vet ./...

test:
	cd apps/backend && go test ./...
	@echo "Frontend smoke tests must be run manually against a running dev server."

clean:
	docker compose down -v
```

## Test plan

- Manual verification (run end-to-end from a fresh clone or `make clean` reset):
  1. `make db-up` — Postgres comes up, healthcheck passes.
  2. `make db-shell` — psql opens, `\l` lists `nalanda` database.
  3. `make frontend` (in a separate terminal) — Vite dev server runs on :5173, browser loads the POC.
  4. `make backend` (in a third terminal) — Go server runs on :8080, `curl localhost:8080/healthz` returns 200.
  5. `make lint` — both lints pass.
  6. `make test` — backend tests pass.
  7. `make clean` — containers stopped and volume removed.
- Smoke tests: existing frontend smoke tests continue to pass when run manually with the dev server up.
- Lint: workflow files (none here) — N/A. Frontend lint and backend vet are exercised via `make lint`.
- Build: not directly exercised by this spec, but covered indirectly when `make backend` does `go run`.

## Notes

- Postgres is in Docker; frontend and backend processes run on the host. This is intentional: faster hot-reload and easier debugging than running everything in containers.
- Production uses Neon (per H), not Docker — the `DATABASE_URL` shape is identical, so `apps/backend/` reads the same env var locally and in prod.
- The Makefile is the *entrypoint*, not the contract. Each target is a thin wrapper around `cd <dir> && <command>`. Developers can also run the commands directly.
- This spec assumes S1.1 (monorepo) and S1.2 (backend skeleton) have landed. The Makefile's `frontend` and `backend` targets reference `apps/frontend/` and `apps/backend/` paths.
