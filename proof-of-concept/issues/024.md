## Problem

Today all course content lives hardcoded as JSX inside `src/App.jsx`. To scale to a real multi-chapter platform, we need MDX (`@mdx-js/rollup`) so authors can write prose-first content with embedded React components (widgets) without writing JSX boilerplate. This spec is the foundation that every other E2 spec builds on: it proves that the MDX toolchain compiles, hot-reloads, and can render a section containing existing widgets (`<LinkedListViz />`, `<CodeEditor />`, etc.).

This spec is intentionally minimal: it does NOT migrate the POC content, does NOT introduce routing, and does NOT introduce the loader abstraction. It just proves MDX works end-to-end inside the current Vite setup.

## Goals

- Add `@mdx-js/rollup` Vite plugin to `vite.config.js` (or `apps/frontend/vite.config.js` if E1 monorepo reorg has already landed — check first).
- Add MDX dependencies: `@mdx-js/rollup`, `@mdx-js/react`, `remark-gfm` (for tables/strikethrough), `rehype-slug` (anchor ids for headings).
- Configure the plugin with `providerImportSource: '@mdx-js/react'` so MDX components can be passed via `MDXProvider`.
- Create ONE sample MDX file at `src/content/courses/_sample/intro.mdx` (or `apps/frontend/src/content/...` if reorged). The file imports an existing widget (e.g. `LinkedListViz`) and renders it among prose.
- Wire `src/App.jsx` (temporarily) to import that sample MDX file and render it. The POC lesson stays untouched during this spec — sample MDX is shown as a second route or behind a query param flag, the goal is just proof-of-concept.
- Hot reload of MDX works (edit the .mdx file, the page updates without full reload).
- `.mdx` extension is recognized by ESLint without errors (add `'*.mdx'` to ignores or install minimal mdx plugin if needed).
- Add `vite.config.js` to `.gitignore`? NO — but per CLAUDE.md, requires user confirmation to modify. Confirmation already implicit via this issue.

## Design

**Approach:** Add `@mdx-js/rollup` as the Vite plugin. MDX files become first-class JS modules — `import Section from './intro.mdx'` returns a React component. Inside the .mdx file, JSX expressions and imports work natively.

**Architecture decisions consumed:**
- **D** — MDX as the content format.
- **X** — Material Domain: this spec only deals with content. No backend, no auth, no per-user state.

**Files to create / modify:**
- `vite.config.js` — add `mdx()` to the plugins array, before `react()`. Use `{ providerImportSource: '@mdx-js/react', remarkPlugins: [remarkGfm], rehypePlugins: [rehypeSlug] }`.
- `package.json` — add dev deps: `@mdx-js/rollup`, `@mdx-js/react`, `remark-gfm`, `rehype-slug`. (Requires user approval per CLAUDE.md.)
- `src/content/courses/_sample/intro.mdx` — sample file. ~30-50 lines of prose + 1 widget import + 1 widget render.
- `src/App.jsx` — TEMPORARY: render the sample MDX alongside or instead of current lesson, gated by `?sample=1` URL param (so the POC continues to render by default). This is undone in S2.7 when content migration happens.
- `smoke-test-mdx.mjs` — new puppeteer smoke test that loads `?sample=1`, asserts MDX content renders, asserts the embedded widget appears.

**MDX provider:** wrap App tree with `<MDXProvider components={{}}>` so future slide markers (S2.5) plug into the same provider without touching this spec.

## Test plan

- **Smoke test:** `smoke-test-mdx.mjs` (puppeteer-core) loads `http://localhost:5173/?sample=1`, waits for known selector (e.g. `[data-mdx-sample]` on a wrapper div), asserts text content and presence of `[data-widget="linked-list"]`.
- **Manual verification:** `npm run dev` → visit `/?sample=1` → MDX prose, headings, and embedded widget render. Edit the .mdx file → hot reload triggers. Visit `/` (no query) → POC lesson renders unchanged.
- **Lint:** `npm run lint` passes.
- **Build:** `npm run build` succeeds, `dist/` ships.
