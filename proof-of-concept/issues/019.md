## Problem

Before real classes start, the platform must be stable: error boundaries in the frontend, structured logging in the backend, basic monitoring, smoke tests covering critical flows end-to-end, and onboarding documentation for invited professors who will trial the platform.

This epic doesn't add features. It hardens what exists.

## Goals

- Error boundaries on all top-level routes; meaningful fallback UIs.
- Backend structured logging via `slog` with consistent fields (request_id, user_id, route).
- Sentry (or equivalent free-tier alternative) integrated for both frontend and backend.
- Smoke test suite covering critical flows end-to-end: OAuth login, navigate course, start live session, submit task.
- Onboarding doc for trial professors: `docs/professor-onboarding.md` explaining how to enroll students, start a session, see submissions.

## Non-goals

- Performance optimization (not yet measured to be a bottleneck).
- Mobile responsive design.
- Accessibility audit (post-launch).
- Advanced monitoring (custom dashboards, alerting).
