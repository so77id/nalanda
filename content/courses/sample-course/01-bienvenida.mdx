<Slide title="¿Cómo sabemos que funciona?">

{/* TODO(#119): la curva de costo, lineal contra logarítmica, junto a estos números */}

Buscar un dato entre **cien millones** de elementos, uno por uno: unos
**50.000.000** de comparaciones en promedio.

Un servidor cien veces más rápido: **siguen siendo 50.000.000** de
comparaciones. Solo las hace más rápido.

Sobre los mismos datos, ordenados, la búsqueda binaria necesita **27**.

Hay un factor que ningún hardware compra. Medirlo, sin ejecutar nada, se llama
**análisis de complejidad**, y es la primera unidad del curso.

</Slide>

<Slide title="Contémoslas aquí mismo">

Esto corre de verdad, en el navegador. Un millón de elementos en vez de cien
millones: Java se ejecuta en el hilo de esta página, así que subir `n` a cien
millones congela la pestaña y obliga a recargarla.

El _cómo_ funciona la búsqueda binaria es [[busqueda-binaria|otro documento]];
aquí solo importa cuánto cambia.

<CodeEditor
  language="java"
  defaultValue={`public class Main {
    static int lineal(int[] a, int objetivo) {
        int comparaciones = 0;
        for (int i = 0; i < a.length; i++) {
            comparaciones++;
            if (a[i] == objetivo) break;
        }
        return comparaciones;
    }

    static int binaria(int[] a, int objetivo) {
        int comparaciones = 0;
        int lo = 0, hi = a.length - 1;
        while (lo <= hi) {
            comparaciones++;
            int medio = lo + (hi - lo) / 2;
            if (a[medio] == objetivo) break;
            if (a[medio] < objetivo) lo = medio + 1;
            else hi = medio - 1;
        }
        return comparaciones;
    }

    public static void main(String[] args) {
        int n = 1_000_000;
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = i;

        int objetivo = n - 1;
        System.out.println("Lineal:  " + lineal(a, objetivo) + " comparaciones");
        System.out.println("Binaria: " + binaria(a, objetivo) + " comparaciones");
    }

}
`}

<Slide title="¿Qué hay que saber, exactamente?">

{/* TODO(#119): la caja negra abierta, mostrando lo que hay adentro */}

Más de lo que parece, y ya lo estuvimos usando sin verlo.

En C++ elegimos entre `std::map` y `std::unordered_map` sin que nadie nos dijera
que estábamos eligiendo entre **un árbol balanceado y una tabla de hash**, con
costos distintos y garantías distintas.

Y `std::sort` no es quicksort: es **introsort**, que empieza con quicksort y se
cambia a heapsort cuando la recursión se hace muy profunda.

</Slide>

<Slide title="La caja se abre más de lo que parece">

En Java, `Arrays.sort` son **dos algoritmos distintos según el tipo**:

- para primitivos, **quicksort de doble pivote**
- para objetos, **TimSort**

La razón es la **estabilidad**: dos elementos iguales conservan su orden
relativo. A un `int` no le importa; a un registro ordenado por otro campo, sí.

Nadie elige eso por casualidad. Java, viniendo de C++, es
[[java-desde-cpp|su propio documento]].

</Slide>

<Slide title="Cómo se calcula la nota">

$$
N_p = 0{,}25 \cdot S_1 + 0{,}25 \cdot S_2 + 0{,}25 \cdot N_{TC} + 0{,}25 \cdot N_L
$$

$$
N_F = 0{,}7 \cdot N_p + 0{,}3 \cdot N_{ex}
$$

- $$S_1$$, $$S_2$$ — las dos solemnes
- $$N_{TC}$$ — tareas y controles
- $$N_L$$ — laboratorio
- $$N_{ex}$$ — examen

Se exime del examen con $$N_p \geq 5{,}0$$. Se aprueba el curso con
$$N_F \geq 4{,}0$$.

</Slide>

<Slide title="De dónde sale ese 25%">

$$
N_{TC} = 0{,}8 \cdot \bar{T} + 0{,}2 \cdot \bar{C}
$$

Las **tareas** se publican aquí y las corrigen los ayudantes. Los **controles de
entrada** tienen su propia sección.

La nota de **laboratorio** es el promedio de las actividades de laboratorio y
los proyectos.

</Slide>
