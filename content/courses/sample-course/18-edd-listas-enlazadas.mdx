# Estructuras de Datos · Listas Enlazadas

El arreglo guarda sus elementos juntos, y esa decisión le fija los costos:
llegar a una posición es una cuenta, abrir un hueco obliga a correr todo lo
que sigue. Esta clase estudia la estructura que toma la decisión contraria
—cada elemento por su lado, guardando dónde está el siguiente— y cumple el
mismo contrato con los costos casi invertidos.

Presentamos la lista simplemente enlazada con todas sus operaciones, sus
cuatro variantes, la comparación completa contra el arreglo y los cuatro
ejercicios que la vuelven una herramienta de trabajo.

<Slide title="Dos maneras de guardar una secuencia">
El TDA Sequence de [[edd-introduccion|Estructuras de Datos · Introducción]]
fija qué se le puede pedir a una colección ordenada por posición: cuántos
elementos tiene, cuál está en la posición `i`, insertar, eliminar. No dice
nada sobre dónde viven esos elementos.

Esa libertad admite dos decisiones opuestas:

- **Todos juntos.** Un bloque de casillas consecutivas en memoria. La
  posición `i` está en `base + i × tamaño`, así que llegar a ella es una
  cuenta. A cambio, abrir un hueco en el medio obliga a correr todo lo que
  viene después.
- **Cada uno por su lado.** Elementos dispersos, donde cada uno guarda dónde
  está el siguiente. Insertar donde ya estamos parados es cambiar un enlace.
  A cambio, no hay ninguna cuenta que lleve a la posición `i`: hay que
  caminar hasta ella.

La segunda decisión define la **lista enlazada**. Cumple el mismo contrato y
su tabla de costos es casi la imagen espejo.

</Slide>

<Slide title="El nodo · un valor y un enlace">
La pieza de la que está hecha una lista es el **nodo**: una cajita con dos
cosas adentro, el dato que guardamos y la dirección del nodo que sigue.

```java
class Nodo {
    int valor;
    Nodo next;

    Nodo(int valor) {
        this.valor = valor;
        this.next = null;
    }
}
```

El campo `next` no es una copia del siguiente nodo: es una **referencia** a
él. Un nodo recién creado tiene `next` en `null`, que es la manera de decir
«después de mí no hay nadie».

Nada obliga a que dos nodos consecutivos estén cerca en memoria. Pueden
haberse creado en momentos distintos y quedar en direcciones sin relación
entre sí. Lo único que los mantiene en orden es el enlace.

</Slide>

<Slide title="De head a null">
Una lista es un nodo que conoce al siguiente, que conoce al siguiente, hasta
que alguno apunta a `null`. Para tener la cadena entera basta con guardar
dónde empieza: esa referencia se llama `head`.

<SequenceStepper
  eda="linked-list-singly"
  operation="search"
  values={[7, 3, 1, 5]}
  target={5}
  showCode={false}
/>

Dos consecuencias salen de este dibujo, y las dos ordenan el resto de la
clase. La primera: llegar al elemento de la posición `i` cuesta `i` saltos,
porque no hay otra forma de llegar que siguiendo enlaces. La segunda:
cambiar dónde apunta un enlace reordena la cadena sin mover ningún dato.

</Slide>

## La lista simplemente enlazada

<Slide title="La clase Lista · head y size">
La estructura completa se sostiene con dos atributos:

```java
public class Lista {
    private Nodo head;
    private int size;

    public Lista() {
        this.head = null;
        this.size = 0;
    }
}
```

`head` es la puerta de entrada: desde ahí se llega a todos los demás nodos
siguiendo enlaces. Una lista vacía es exactamente `head == null`.

`size` no es indispensable —se podría contar la cadena cada vez— pero
contarla cuesta recorrerla entera. Guardar el número y mantenerlo al día en
cada inserción y cada eliminación convierte `len()` en una lectura.

</Slide>

<Slide title="Las invariantes de la lista">
Tres propiedades tienen que valer antes y después de cada operación. Si
alguna se rompe, las demás operaciones dejan de funcionar aunque su código
sea correcto.

1. **`head` apunta al primer nodo, o a `null` si la lista está vacía.** Es el
   único punto de entrada a la cadena. Si `head` queda apuntando a un nodo
   del medio, todo lo anterior se vuelve inalcanzable: sigue en memoria y no
   hay manera de llegar.

2. **Desde `head`, siguiendo `next`, se llega a todos los nodos y se termina
   en `null`.** La cadena no tiene cortes ni ciclos. Un corte pierde la cola;
   un ciclo hace que cualquier recorrido no termine nunca.

3. **`size` es la cantidad de nodos de esa cadena.** Cada operación que
   agrega o saca un nodo lo actualiza. Un `size` desfasado convierte en
   válidos índices que no existen.

La segunda es la que cuesta dinero. Es la que permite que insertar al
principio sea cambiar un enlace, sin tocar ningún otro nodo; y es también la
razón de que llegar a la posición `i` obligue a dar `i` saltos, porque la
única forma de avanzar en la cadena es preguntarle a cada nodo por el
siguiente.

</Slide>

<Slide title="El contrato, implementado">
Las operaciones del TDA Sequence se escriben sobre esta representación sin
cambiar sus nombres ni su significado:

```java
public class Lista implements Sequence {
    public int len()                     { ... }
    public int getAt(int i)              { ... }
    public void setAt(int i, int x)      { ... }
    public void insertAt(int i, int x)   { ... }
    public int deleteAt(int i)           { ... }
    public void insertFirst(int x)       { ... }
    public void insertLast(int x)        { ... }
    public int deleteFirst()             { ... }
    public int deleteLast()              { ... }
}
```

El contrato es idéntico al que cumple el arreglo. Un método que reciba un
`Sequence` funciona con cualquiera de las dos sin enterarse de cuál recibió.
Lo que cambia por completo es cuánto tarda cada llamada.

</Slide>

<Slide title="Operaciones y sus costos">
| Operación | Peor caso | Invariante que restaura |
|---|---|---|
| `len()` | $$\Theta(1)$$ | Ninguna: `size` ya guarda el dato |
| `getAt(i)` · `setAt(i, x)` | $$\Theta(N)$$ | Ninguna: no cambian la cadena |
| <code style={{ color: 'var(--color-keep)' }}>insertFirst(x)</code> | <span style={{ color: 'var(--color-keep)', fontWeight: 700 }}>$$\Theta(1)$$</span> | `head` apunta al primero: el nodo nuevo enlaza al que lo era |
| `insertLast(x)` | $$\Theta(N)$$ | La cadena termina en `null`: hay que encontrar quién lo hace |
| `insertAt(i, x)` | $$\Theta(N)$$ | La cadena queda completa: el previo enlaza al nuevo, el nuevo al que seguía |
| <code style={{ color: 'var(--color-keep)' }}>deleteFirst()</code> | <span style={{ color: 'var(--color-keep)', fontWeight: 700 }}>$$\Theta(1)$$</span> | `head` apunta al primero: pasa a ser el segundo |
| `deleteLast()` | $$\Theta(N)$$ | La cadena termina en `null`: el nuevo último debe apuntar ahí |
| `deleteAt(i)` | $$\Theta(N)$$ | La cadena no se corta: el previo salta al siguiente |
| `buscar(x)` | $$\Theta(N)$$ | Ninguna: no cambia nada |

Las dos filas destacadas son las únicas de costo constante, y las dos operan
sobre el mismo lugar: el principio de la cadena. Es el único punto al que se
llega sin caminar, porque `head` ya está ahí.

</Slide>

<Slide title="Dónde vive el costo">
Todo lo que cuesta $$\Theta(N)$$ en esta tabla lo cuesta por la misma razón, y
no es la operación en sí: es **llegar** al lugar donde hay que operar.

Enlazar un nodo cuesta lo mismo en cualquier parte de la cadena —una
asignación—, pero para enlazarlo en la posición `i` primero hay que tener en
la mano el nodo `i - 1`, y para tenerlo hay que dar `i - 1` saltos desde
`head`.

El vocabulario asintótico que ordena estas cifras está en
[[complejidad-de-hilbert-al-big-o|De Hilbert al Big O]]. Aquí interesa una
sola lectura: en una lista, el costo de una operación se mide en **cuántos
enlaces hay que seguir antes de poder trabajar**.

</Slide>

## Las operaciones de la lista

<Slide title="insertFirst · el enlace que no mueve nada">
Insertar al principio se resuelve con tres asignaciones y ninguna depende de
cuántos elementos haya en la lista.

<SequenceStepper
  eda="linked-list-singly"
  operation="insert-first"
  values={[7, 3, 1, 5]}
  value={9}
/>

El nodo nuevo apunta a quien era el primero, y `head` pasa a apuntar al nodo
nuevo. Los demás nodos no se enteran: ninguno cambió de lugar ni de
contenido. La invariante que se restaura es la primera —`head` apunta al
primer nodo— y restaurarla cuesta $$\Theta(1)$$.

</Slide>

<Slide title="insertFirst en un arreglo · el mismo pedido, otro precio">
El arreglo cumple el mismo contrato y tiene que hacer algo completamente
distinto para cumplirlo.

<SequenceStepper eda="array" operation="insert-first" values={[7, 3, 1, 5]} value={9} />

Para que la posición `i` siga estando en `base + i × tamaño` no puede haber
huecos, así que abrir espacio en la posición 0 obliga a copiar cada elemento
una casilla a la derecha. Con $$N$$ elementos son $$N$$ copias: la operación
es $$\Theta(N)$$, y lo es por la invariante de memoria consecutiva.

Una llamada idéntica, `insertFirst(9)`, cuesta tres asignaciones en la lista y
$$N$$ copias en el arreglo.

</Slide>

<Slide title="insertLast · caminar hasta el final">
Insertar al final invierte la comparación anterior.

<SequenceStepper
  eda="linked-list-singly"
  operation="insert-last"
  values={[7, 3, 1, 5]}
  value={9}
/>

Enlazar el nodo nuevo cuesta una asignación, igual que antes. Lo caro es
llegar: el único nodo autorizado a apuntar al nuevo es el último, y la única
forma de saber cuál es consiste en recorrer la cadena hasta encontrar al que
tiene `next == null`. Son $$N - 1$$ saltos, y el total queda en
$$\Theta(N)$$.

En un arreglo, en cambio, insertar al final es escribir en `datos[size]`: una
sola asignación, sin recorrer nada.

</Slide>

<Slide title="insertAt · encontrar al previo">
Insertar en una posición cualquiera se hace en dos tiempos: primero llegar,
después enlazar.

<SequenceStepper
  eda="linked-list-singly"
  operation="insert-at"
  values={[7, 3, 1, 5]}
  value={9}
  index={2}
/>

El nodo que hay que modificar no es el de la posición `i`, sino el de la
posición `i - 1`: es el que tiene que dejar de apuntar a su siguiente para
apuntar al nodo nuevo. Por eso el recorrido se detiene un paso antes.

El orden de las dos asignaciones no es libre. Primero el nodo nuevo toma el
enlace del previo, y solo después el previo apunta al nuevo. Al revés se
pierde la referencia al resto de la cadena y todo lo que venía después queda
inalcanzable.

</Slide>

<Slide title="deleteFirst · soltar la puerta de entrada">
Eliminar el primer nodo es el reflejo de insertarlo.

<SequenceStepper eda="linked-list-singly" operation="remove-first" values={[7, 3, 1, 5]} />

`head` pasa a apuntar al segundo nodo y la cadena queda completa desde ahí.
El nodo que salió ya no es alcanzable desde ninguna parte, y el recolector de
basura de Java se encarga del resto.

Sobre un arreglo la misma operación cuesta $$\Theta(N)$$: eliminar la
posición 0 deja un hueco que la memoria consecutiva no admite, así que hay
que copiar todo lo demás una casilla a la izquierda.

</Slide>

<Slide title="deleteLast · el costo de no mirar atrás">
Eliminar el último nodo es la operación que mejor muestra qué le falta a esta
estructura.

<SequenceStepper eda="linked-list-singly" operation="remove-last" values={[7, 3, 1, 5]} />

El nodo que hay que modificar es el **anteúltimo**: es quien debe pasar a
apuntar a `null` para que la cadena vuelva a terminar bien. Y un nodo no
guarda quién lo apunta, solo a quién apunta: desde el último no hay manera de
retroceder un paso. La única salida es volver a `head` y recorrer.

Sobre un arreglo esta operación es $$\Theta(1)$$ —basta con restar uno a
`size`—, exactamente al revés que `insertFirst`.

</Slide>

<Slide title="deleteAt · saltar por encima">
Eliminar una posición cualquiera repite el patrón: llegar al previo, y
después una sola asignación.

<SequenceStepper
  eda="linked-list-singly"
  operation="remove-at"
  values={[7, 3, 1, 5]}
  index={2}
/>

El previo pasa a apuntar al siguiente del nodo que sale, que queda fuera de
la cadena sin haber movido ningún otro dato. La invariante que se restaura es
la segunda: desde `head` se sigue llegando a todos los nodos y se sigue
terminando en `null`.

Notemos la asimetría con el arreglo. Ahí eliminar del medio cuesta
$$\Theta(N)$$ **copias de datos**; aquí cuesta $$\Theta(N)$$ **saltos** y una
sola asignación. El orden asintótico coincide, pero lo que se hace $$N$$
veces no es lo mismo.

</Slide>

<Slide title="buscar · sin atajos">
Buscar un valor recorre la cadena preguntando nodo por nodo.

<SequenceStepper
  eda="linked-list-singly"
  operation="search"
  values={[7, 3, 1, 5]}
  target={1}
/>

En el peor caso —el valor no está— se visitan los $$N$$ nodos:
$$\Theta(N)$$. Un arreglo desordenado cuesta lo mismo, y por una vez las dos
estructuras empatan.

El empate se rompe cuando los datos están ordenados. Sobre un arreglo
ordenado la búsqueda binaria baja a $$\Theta(\log N)$$ porque puede saltar
al elemento del medio con una cuenta. Sobre una lista ordenada no puede: para
llegar al nodo del medio hay que caminar hasta él, y entonces ya se recorrió
media cadena. La lista se queda en $$\Theta(N)$$ aunque esté ordenada.

</Slide>

<Slide title="La lista vacía y el largo">
Dos operaciones que no recorren nada:

```java
public boolean isEmpty() {
    return head == null;
}

public int len() {
    return size;
}
```

`isEmpty()` lee la primera invariante directamente: una lista está vacía
exactamente cuando `head` es `null`. No hace falta contar.

`len()` es $$\Theta(1)$$ porque `size` se mantiene al día en cada inserción y
cada eliminación. Ese es el trato: pagamos una suma o una resta en cada
operación que cambia la cadena, y a cambio preguntar el largo nunca cuesta
recorrerla.

</Slide>

<Slide title="Los casos de borde">
Tres situaciones rompen el código de estas operaciones si no se escriben con
cuidado, y las tres aparecen en los extremos de la cadena.

- **La lista vacía.** `insertFirst` sobre `head == null` funciona sin cambios:
  el nodo nuevo apunta a `null` y pasa a ser la cadena entera. `deleteFirst`,
  en cambio, no tiene nada que sacar y debe rechazar la llamada.
- **Un solo nodo.** `deleteLast` no tiene anteúltimo al que pedirle que
  apunte a `null`; lo que corresponde es dejar `head` en `null`.
- **Insertar en la posición `size`.** Es válido —significa insertar al
  final— y el recorrido debe detenerse en el último nodo, no pasarse.

En los tres, quien se rompe primero es una invariante, no el programa: el
error aparece más tarde, en una operación que sí confiaba en ella.

</Slide>
