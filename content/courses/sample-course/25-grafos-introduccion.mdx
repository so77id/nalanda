# Grafos · Introducción

Una ciudad tiene esquinas unidas por calles; una red social, personas que se
siguen; una malla curricular, ramos que piden otros antes. Los tres problemas
hablan de cosas y de cuáles están unidas, y de nada más. Un **grafo** guarda
exactamente eso, y con él preguntas que parecen distintas resultan ser la
misma.

## Los puentes de Königsberg

{/* KonigsbergMap — Königsberg in one frame, at the three stages of the abstraction (#356): `city` the town as it is, houses in their blocks and the seven bridges in `mark`; `map` only land, water (`sunk`) and bridges, the zones lettered A to D; `graph` only a point on each zone and a line for each bridge, every line passing where its bridge stands, so the stages line up when shown side by side. Schematic, not to scale. File-local: only this class draws the city. */}

export function KonigsbergMap({ stage = 'map', caption, label }) {
  const width = 520;
  const height = 290 + (caption ? 24 : 0);
  const water = [[0, 105], [300, 105], [520, 45], [520, 95], [360, 150], [520, 205], [520, 255], [300, 195], [0, 195]];
  const bridges = [[125, 101, 10, 28], [212, 101, 10, 28], [125, 171, 10, 28], [212, 171, 10, 28], [258, 145, 104, 10], [435, 62, 10, 64], [435, 174, 10, 64]];
  const inWater = (px, py) => {
    let c = false;
    for (let i = 0, j = water.length - 1; i < water.length; j = i++) {
      const [xi, yi] = water[i];
      const [xj, yj] = water[j];
      if ((yi > py) !== (yj > py) && px < ((xj - xi) * (py - yi)) / (yj - yi) + xi) c = !c;
    }
    return c;
  };
  const onIsland = (px, py) => ((px - 175) / 74) ** 2 + ((py - 150) / 18) ** 2 <= 1;
  const nearBridge = (x, y, w, h) => bridges.some(([bx, by, bw, bh]) => x < bx + bw + 7 && x + w > bx - 7 && y < by + bh + 7 && y + h > by - 7);
  const blocks = [];
  if (stage === 'city') {
    for (let row = 0, y = 8; y < 280; row++, y += 22) {
      for (let x = 6 + (row % 2) * 14; x < 500; x += 34) {
        const w = 27;
        const h = 15;
        const corners = [[x - 3, y - 3], [x + w + 3, y - 3], [x - 3, y + h + 3], [x + w + 3, y + h + 3]];
        const land = corners.every(([cx, cy]) => !inWater(cx, cy)) || corners.every(([cx, cy]) => onIsland(cx, cy));
        if (land && !nearBridge(x, y, w, h)) blocks.push([x, y, w, h]);
      }
    }
  }
  const point = { A: [175, 150], B: [175, 52], C: [175, 248], D: [470, 150] };
  const lines = [
    'M 175 150 Q 85 129 175 52',
    'M 175 150 Q 259 129 175 52',
    'M 175 150 Q 85 171 175 248',
    'M 175 150 Q 259 171 175 248',
    'M 175 150 L 470 150',
    'M 175 52 Q 360 52 440 94 Q 470 112 470 150',
    'M 175 248 Q 360 248 440 206 Q 470 188 470 150',
  ];
  const name = (x, y, t, size) => (
    <text x={x} y={y} textAnchor="middle" fontSize={size} fontWeight="700" style={{ fill: 'var(--color-ink)' }}>{t}</text>
  );
  return (
    <svg viewBox={stage === 'graph' ? '70 18 450 264' : `0 0 ${width} ${height}`} style={{ width: '100%', maxWidth: stage === 'graph' ? '320px' : '560px', height: 'auto', display: 'block', margin: '0.6rem auto' }} role="img" aria-label={label}>
      {stage === 'graph' ? null : (
        <>
          <polygon points={water.map((p) => p.join(',')).join(' ')} style={{ fill: 'var(--color-sunk)', stroke: 'var(--color-rule-strong)' }} strokeWidth="1.2" />
          <ellipse cx="175" cy="150" rx="85" ry="25" style={{ fill: 'var(--color-ground)', stroke: 'var(--color-rule-strong)' }} strokeWidth="1.2" />
          {blocks.map(([x, y, w, h], k) => (
            <rect key={`h${k}`} x={x} y={y} width={w} height={h} rx="1.5" style={{ fill: 'var(--color-surface)', stroke: 'var(--color-rule-strong)' }} strokeWidth="0.8" />
          ))}
          {bridges.map(([x, y, w, h], k) => (
            <rect key={`b${k}`} x={x} y={y} width={w} height={h} rx="2" style={{ fill: stage === 'city' ? 'var(--color-mark)' : 'var(--color-ink-soft)' }} />
          ))}
        </>
      )}
      {stage === 'map' ? (
        <>
          {name(175, 64, 'B', 28)}
          {name(175, 266, 'C', 28)}
          {name(175, 160, 'A', 28)}
          {name(482, 160, 'D', 28)}
        </>
      ) : null}
      {stage === 'graph' ? (
        <>
          {lines.map((d, k) => (
            <path key={`l${k}`} d={d} fill="none" style={{ stroke: 'var(--color-rule-strong)' }} strokeWidth="2.1" />
          ))}
          {Object.entries(point).map(([v, [x, y]]) => (
            <g key={v}>
              <circle cx={x} cy={y} r="28" style={{ fill: 'var(--color-surface)', stroke: 'var(--color-rule-strong)' }} strokeWidth="2.1" />
              {name(x, y + 8, v, 23)}
            </g>
          ))}
        </>
      ) : null}
      {caption ? (
        <text x={width / 2} y={height - 8} textAnchor="middle" fontSize="13" style={{ fill: 'var(--color-ink-soft)' }}>{caption}</text>
      ) : null}
    </svg>
  );
}

Hoy lo dibujamos con un punto por zona y una línea por puente. A este dibujo

<Slide title="El paseo por Königsberg">
En el grafo, el paseo es pasar el lápiz por todas las líneas sin levantarlo
y sin repetir ninguna: cada línea dibujada es un puente cruzado. Se puede
probar a mano, o con Buscar solución:

Cada intento cruza los puentes en un orden: uno primero, otro después, hasta

para probarlos todos: con siete puentes hay 5040, y cada puente más los
multiplica; con veinte, son más de dos trillones. Hace falta una razón que
descarte todos los órdenes a la vez, sin probar ninguno.

## Las partes de un grafo

<Slide title="Los vértices">
Cada zona de tierra es un **vértice**, un punto del dibujo. Los vértices forman
un conjunto, que se llama $$V$$:

$$
V = \{A, B, C, D\} \qquad |V| = 4
$$

Se lee «$$V$$ es el conjunto de A, B, C y D, y tiene cuatro elementos».

<Slide title="Las aristas">
Cada puente es una **arista**: une dos vértices, sus **extremos**. Un puente se
cruza en los dos sentidos, así que la arista no tiene dirección, y se escribe
entre llaves: $$\{A, D\}$$. Si fuera de un solo sentido, como una calle,
tendría dirección, y una arista con dirección se llama **arco**: se dibuja como
una flecha y se escribe entre paréntesis, $$(A, D)$$, de A a D.

<Slide title="Conjuntos y tuplas">
Las llaves y los paréntesis son dos formas de agrupar elementos, y se leen
distinto:

<div style={{ display: 'grid', gridTemplateColumns: 'repeat(auto-fit, minmax(260px, 1fr))', gap: '0.75rem 1.5rem', margin: '1rem 0' }}>
<div style={{ border: '1px solid var(--color-rule)', borderRadius: '8px', padding: '0.5rem 0.9rem 0.1rem', background: 'var(--color-surface)' }}>

**Un conjunto**, entre llaves: sus elementos no tienen orden y no se repiten.

$$
\{A, D\} = \{D, A\}
$$

</div>
<div style={{ border: '1px solid var(--color-rule)', borderRadius: '8px', padding: '0.5rem 0.9rem 0.1rem', background: 'var(--color-surface)' }}>

**Una tupla**, entre paréntesis: sus elementos van en orden. Una tupla de dos
elementos es un **par ordenado**.

$$
(A, D) \neq (D, A)
$$

</div>
</div>

Así se leen una arista y un arco:

- **Una arista**, sin dirección, es un conjunto: $$\{A, D\}$$ es la misma que
  $$\{D, A\}$$, y se abrevia $$AD$$, o $$DA$$.
- **Un arco**, con dirección, es un par ordenado: $$(A, D)$$ va de A a D, y
  también se abrevia $$AD$$. Pero aquí el orden importa: $$AD \neq DA$$, y
  $$DA$$ sería otro arco, de D a A.

</Slide>

<Slide title="Qué es un grafo">
Un **grafo** se describe con dos conjuntos: $$V$$, el de sus vértices, y $$E$$,
el de sus aristas, o de sus arcos si tienen dirección. Se escribe como un par ordenado, primero los vértices y
después las aristas:

$$
G = (V, E)
$$

Se lee «el grafo $$G$$, con los vértices $$V$$ y las aristas $$E$$». Los dos
grafos de abajo tienen los mismos vértices, $$V = \{A, B, C, D\}$$. Cambia lo
que hay en $$E$$: aristas entre llaves en uno, arcos entre paréntesis en el
otro.

las cuentas se escriben simplemente $$V$$ y $$E$$.

<Slide title="La forma y la posición no importan">
Un grafo no dice dónde va cada vértice ni cómo se dibuja cada arista: en
$$G = (V, E)$$ no hay posiciones. Dos dibujos con los mismos vértices y las
mismas aristas son el **mismo grafo**, aunque se vean distintos. El dibujo no
tiene que copiar cómo están las cosas en el mundo real: un vértice puede ir en
cualquier lugar, y una arista larga o curva une lo mismo que una corta y recta.
Conviene elegir el dibujo que mejor deja ver la estructura.

<Slide title="Grafos isomorfos">
Dos situaciones distintas pueden dar el mismo grafo con otros nombres. Un museo
de cuatro salas unidas por siete puertas da el grafo de la derecha: si las
salas 1, 2, 3 y 4 se renombran A, B, C y D, sus aristas son las de Königsberg.
Los dos grafos son **isomorfos**: $$G_1 \cong G_2$$, que se lee «$$G_1$$ es
isomorfo a $$G_2$$».

Una pregunta sobre un grafo depende solo de sus vértices y sus aristas, así que
tiene la misma respuesta en los dos: pasar una vez por cada puerta del museo es
el mismo problema que cruzar una vez cada puente. Lo que se resuelva para uno
queda resuelto para el otro.

<Slide title="Los vecinos de un vértice">
Dos vértices unidos por una arista son **vecinos**, o **adyacentes**: $$u$$ y
$$v$$ son vecinos si $$uv \in E$$, que se lee «la arista $$uv$$ está en $$E$$».
Un vértice puede tener muchos vecinos, o ninguno.

<Slide title="Aristas paralelas">
Entre dos vértices puede haber más de una arista, como los dos puentes entre la
isla y una orilla: son **aristas paralelas**. Cada una cuenta por separado, así
que $$E$$ tiene la misma arista más de una vez, y deja de ser un conjunto, que
no repite: en Königsberg, $$AB$$ y $$AC$$ están dos veces. Un grafo con aristas
paralelas se llama **multigrafo**: Königsberg es uno.

<Slide title="El grado de un vértice">
El **grado** de un vértice $$v$$, que se escribe $$\operatorname{grado}(v)$$, es la

## Caminos y ciclos

<Slide title="Caminos">
Un **camino** recorre el grafo de vértice en vértice por sus aristas, sin
repetir ninguna. Se escribe con sus vértices en orden:

$$
v_0 \to v_1 \to \cdots \to v_k
$$

- El subíndice es la posición: $$v_0$$ es el primer vértice y $$v_k$$, el último.
- Cada flecha cruza la arista entre dos vértices seguidos, así que las aristas
  del camino son $$v_0 v_1,\ v_1 v_2,\ \dots,\ v_{k-1} v_k$$. La flecha indica
  el orden, no una dirección.
- El **largo** de un camino es su cantidad de aristas, una por flecha:
  $$v_0 \to v_1 \to \cdots \to v_k$$ tiene largo $$k$$.

  cols={3}

  edges={[['A', 'B'], ['A', 'C'], ['B', 'C'], ['C', 'D'], ['C', 'E'], ['D', 'E']]}
  walk={['A', 'B', 'C', 'D', 'E', 'C']}

  label="Dos triángulos que comparten el vértice C. Marcado y numerado, el camino de A a B, a C, a D, a E y otra vez a C: cruza cinco aristas y pasa dos veces por C."
/>

</Slide>

<Slide title="Caminos simples">
Un camino es **simple** si no repite vértices: cada vértice aparece una sola
vez.

$$
v_0, v_1, \dots, v_k \ \text{son todos distintos}
$$

A la derecha, C aparece dos veces: ese camino no es simple.

</Slide>

<Slide title="Ciclos">
Un **ciclo** es un camino que termina donde empezó: desde su último vértice,
una arista más lo devuelve al primero. Como todo camino, no repite aristas, y su
largo se cuenta igual: una arista por flecha.

$$
v_0 \to v_1 \to \cdots \to v_k \to v_0
$$

/>

</Slide>

<Slide title="Ciclos simples">
Un **ciclo simple** es un camino simple que vuelve al vértice donde partió:

$$
v_0 \to v_1 \to \cdots \to v_k \to v_0 \qquad v_0, v_1, \dots, v_k \ \text{son todos distintos}
$$

El único vértice que se repite es $$v_0$$, que cierra el ciclo.

A la derecha, el ciclo vuelve a A pero pasa dos veces por C: es un ciclo, porque
no repite aristas, pero no es simple. Algunos libros lo llaman **circuito** y
reservan «ciclo» para el simple.

</Slide>

<Slide title="Grafos conexos">
Un grafo es **conexo** si desde cualquier vértice se puede llegar a cualquier
otro por un camino:

$$
\text{para todo } u, v \in V \text{ hay un camino } u \to \cdots \to v
$$

Si no es conexo, se parte en **componentes**: grupos de vértices que se alcanzan
entre sí, pero desde los que no se llega a ningún vértice de otro grupo.

## La respuesta de Euler

<Slide title="La pregunta de Königsberg">
Ahora que tenemos más palabras para hablar de un grafo, podemos volver a hacer

| En la ciudad | En el grafo |
| --- | --- |
| una zona de tierra | un vértice |
| un puente | una arista |
| un paseo que no cruza dos veces el mismo puente | un camino |
| cruzar todos los puentes | usar todas las aristas |

La pregunta del paseo queda así: **¿hay un camino que use todas las aristas?**

Como el camino usa todas las aristas y no repite ninguna, el grado de X es la
suma de lo que usa en cada visita: dos por cada vez que pasa, y una si comienza
o termina en X. Si el camino solo pasa por X, su grado es par. Queda impar solo
donde el camino comienza o termina.

**Un camino que usa todas las aristas deja, a lo más, dos vértices de grado
impar: su comienzo y su final.** Si vuelve a donde empezó, el comienzo y el
final son el mismo vértice, suman dos, y queda par.

</Slide>

las aristas deja a lo más dos. No hay paseo, parta donde parta.

<Slide title="Caminos y ciclos eulerianos">

euleriano**. Como ningún camino repite aristas, pasa por cada una exactamente
una vez, y su largo es $$|E|$$. Si además vuelve al vértice donde partió, es un
**ciclo euleriano**.

<Slide title="Nunca queda un solo vértice impar">
Ahora la pregunta al revés: ¿cuándo sí hay un camino euleriano? Antes, una
duda: ¿puede un grafo tener un solo vértice de grado impar? Nunca, y se ve
sumando grados.

- Cada arista toca dos vértices: suma uno al grado de cada uno.
- Al sumar los grados de todos los vértices, cada arista se cuenta dos veces:

$$
\sum_{v} \operatorname{grado}(v) = 2E
$$

- La suma es par. Y una suma es par solo si sus números impares vienen de a
  pares: con un solo impar, la suma sería impar.

**En todo grafo, la cantidad de vértices de grado impar es par**: 0, 2, 4…,
nunca 1. Se llama **lema del apretón de manos**: en una reunión, cada apretón
lo cuentan las dos personas que se dieron la mano.

pasa de una a la otra, aunque todos los grados sean pares.

<Slide title="La regla de Euler">
En un grafo conexo, la cantidad de vértices de grado impar decide si hay un
camino euleriano:

- **Ninguno impar**: hay un ciclo euleriano, que parte de cualquier vértice y
  vuelve a él.
- **Dos impares**: hay uno que parte de uno de los dos y termina en el otro.
- **Más de dos impares**: no hay ninguno.

Un solo vértice impar no ocurre nunca: los vértices de grado impar son
siempre una cantidad par. Euler probó en 1736 que con más de dos impares no hay
camino. Que con ninguno o dos sí lo haya lo demostró Carl Hierholzer en 1873,
construyendo el camino.

¿Y si Königsberg tuviera un puente más? ¿Y dos?

</Slide>

## El problema del camino euleriano

<Slide title="Un problema de computación">
La regla de Euler no habla de puentes ni de ciudades: sirve para cualquier
grafo. Una pregunta que se hace sobre cualquier entrada, y no sobre un caso, es
un **problema**. Este es el **problema del camino euleriano**:

- **Entrada**: un grafo.
- **Pregunta**: ¿tiene un camino que use todas las aristas?
- **Respuesta**: la regla de Euler, que cuenta los vértices de grado impar.

<Slide title="Reducir un problema a otro">
El paseo, la figura y el camión parecen problemas distintos, pero modelados
como grafos hacen la misma pregunta:

| Situación | Vértices | Aristas | La pregunta |
| --- | --- | --- | --- |
| el paseo por Königsberg | las zonas | los puentes | ¿cruzar cada puente una vez? |
| la figura de un solo trazo | los puntos | las líneas | ¿dibujar cada línea una vez? |
| el camión de la basura | las esquinas | las cuadras | ¿pasar una vez por cada cuadra? |

Convertir un problema en otro que ya sabemos resolver, de modo que la respuesta
del segundo responda el primero, es **reducir un problema a otro**. Los tres se
reducen al camino euleriano, y la regla de Euler responde los tres.

Con los grafos isomorfos pasaba lo mismo, en su forma más directa: si dos grafos
son isomorfos, responder una pregunta sobre uno es responderla sobre el otro.
Reducir va más allá: los tres grafos de la tabla no se parecen, pero basta con
que la pregunta sobre ellos sea la misma.

</Slide>

<Slide title="Por qué estudiar grafos">
- **Pocas ideas resuelven muchos problemas.** Unos pocos algoritmos de grafos
  responden preguntas de áreas que no se parecen en nada: aprenderlos una vez
  sirve para todas.
- **Aparecen en todas partes.** En algoritmos, redes, inteligencia artificial
  y compiladores, y son uno de los temas más frecuentes en las entrevistas
  técnicas de programación.
- **Todavía hay preguntas abiertas.** Algunos problemas piden **encontrar** una
  respuesta, o la mejor; otros, solo **saber si existe** una; y otros,
  **comprobar** si una respuesta que nos dan es correcta. Comprobar suele ser
  lo fácil: un sudoku lleno se revisa en un minuto, y llenarlo cuesta mucho más.
  Nadie sabe si todo problema cuya respuesta se comprueba rápido también se
  puede encontrar rápido. Es la pregunta **P frente a NP**, uno de los siete
  Problemas del Milenio, con un premio de un millón de dólares, y muchos
  problemas de grafos están en el centro de ella.

hasta aquí, Königsberg incluido, son no dirigidos.

<Slide title="Simples, multigrafos y pseudografos">
Las aristas paralelas y los lazos separan tres tipos de grafos:

- **Grafo simple**: a lo más una arista entre dos vértices, y sin lazos. $$E$$ es un

- **Multigrafo**: puede tener aristas paralelas, pero no lazos. $$E$$ deja de
  ser un conjunto, porque repite aristas. Königsberg es uno.
- **Pseudografo**: puede tener aristas paralelas y también lazos, $$vv$$. En un
  dominó, cada ficha une sus dos números, y los dobles son lazos.

## Tipos de grafos: por la forma del grafo

<Slide title="Grafos completos">
Un grafo simple es **completo** si cada vértice está unido con todos los demás:
tiene todas las aristas posibles. El completo de $$n$$ vértices se escribe
$$K_n$$, y sus aristas se cuentan en dos pasos:

- Cada uno de los $$n$$ vértices se une con los otros $$n - 1$$: son
  $$n(n - 1)$$ extremos de arista.
- Cada arista tiene dos extremos, así que quedó contada dos veces.

$$
|E| = \frac{n(n - 1)}{2}
$$

Es el máximo de aristas que puede tener un grafo simple de $$n$$ vértices.

<Slide title="Grafos densos y dispersos">
El completo marca el máximo: un grafo simple de $$n$$ vértices tiene a lo más
$$\frac{n(n - 1)}{2}$$ aristas. Según cuántas tiene de ese máximo, un grafo es:

- **denso**, si tiene cerca del máximo: casi todos los vértices están unidos con
  casi todos;
- **disperso**, si tiene muchas menos: cada vértice está unido con unos pocos.

llega a cualquier otro. La palabra es para grafos **no dirigidos**: en ellos
cada arista se recorre en los dos sentidos.

<Slide title="Fuertemente y débilmente conexos">
En un grafo **dirigido**, un camino tiene que seguir las flechas, y llegar de
$$u$$ a $$v$$ no asegura poder volver de $$v$$ a $$u$$. Por eso «conexo» se
divide en dos:

- **Fuertemente conexo**: desde cualquier vértice se llega a cualquier otro
  siguiendo las flechas. Para todo $$u, v \in V$$ hay un camino
  $$u \to \cdots \to v$$ que sigue los arcos.
- **Débilmente conexo**: se llega de cualquiera a cualquiera solo si se ignoran
  las flechas, es decir, el grafo sin flechas es conexo.

Todo grafo fuertemente conexo es también débilmente conexo. Las calles de una
ciudad, con sus sentidos, deberían ser fuertemente conexas.

<Slide title="Árboles">
Un **árbol** es un grafo no dirigido, conexo y sin ciclos. Entre dos de sus
vértices hay exactamente un camino simple, y tiene una arista menos que
vértices:

$$
|E| = |V| - 1
$$

Con una arista menos deja de ser conexo, y con una más cierra un ciclo. Ningún
vértice de un árbol es especial: no tiene arriba ni abajo.

<Slide title="Árboles con raíz">
Un **árbol con raíz** es un árbol en el que se elige un vértice, la **raíz**.
Elegirla ordena todo lo demás: los vecinos de la raíz son sus **hijos**, los
vecinos de cada hijo, salvo su padre, son los hijos de ese hijo, y así hacia
abajo. Así son los árboles binarios y los heaps.

Elegir la raíz le da a cada arista una dirección, de padre a hijo. Por eso un
árbol con raíz se dibuja también como un grafo dirigido: desde la raíz hay
exactamente un camino a cada vértice. Cualquier vértice puede ser la raíz.

<Slide title="DAG: grafos dirigidos acíclicos">
Un **DAG** es un grafo dirigido sin ciclos: siguiendo las flechas, nunca se
vuelve a un vértice por el que ya se pasó. El nombre es la sigla de *directed
acyclic graph*.

Los DAG aparecen cuando unas cosas dependen de otras: una malla curricular, una
receta, las tareas de un proyecto. Si los prerrequisitos de una malla formaran
un ciclo, ningún ramo de ese ciclo se podría tomar primero.

<Slide title="Fuentes y sumideros">
En un grafo dirigido, una **fuente** es un vértice al que no llega ningún arco,
$$\operatorname{grado}^-(v) = 0$$, y un **sumidero**, uno del que no sale
ninguno, $$\operatorname{grado}^+(v) = 0$$. Como en un río: el agua nace en la
fuente y termina en el sumidero.

<Slide title="Las preguntas de un grafo">
Cada tipo responde una pregunta sobre el grafo, y las respuestas se combinan:
un mapa de calles es dirigido y ponderado, y Königsberg es un multigrafo no
dirigido.

| | Pregunta | Tipos |
| --- | --- | --- |
| **tipo de arista** | ¿La relación va en los dos sentidos? | no dirigido · dirigido |
| | ¿Trae un número? | sin pesos · ponderado |
| | ¿Se repiten aristas, o hay lazos? | simple · multigrafo · pseudografo |
| **forma del grafo** | ¿Cuántas aristas tiene? | completo, denso o disperso |
| | ¿Se llega de cualquier vértice a cualquier otro? | conexo (no dirigido) · fuertemente o débilmente conexo (dirigido) |
| | ¿Tiene ciclos? | árbol · DAG |

</Slide>

## Lo que sigue

Con las palabras y los tipos de grafos, falta construir un grafo desde un
problema y guardarlo en un programa: **modelar** una situación, decidir qué son
sus vértices y sus aristas, y elegir cómo guardarlo en memoria, con una matriz
o con listas, cada una con su precio.
