# Estructuras de Datos Avanzadas · Árboles I

Un arreglo, una lista, una pila y una cola guardan sus elementos en fila:
cada elemento tiene a lo más un siguiente. Muchos datos no tienen esa forma.
Una carpeta contiene archivos y otras carpetas, que a su vez contienen más;
un organigrama, una expresión aritmética y un árbol genealógico se organizan
igual, por niveles que dependen unos de otros. Esa forma se llama
**jerarquía**, y la estructura que la representa es el **árbol**.

{/* HierarchyPicture — a static drawing of a general tree (any number of children per node): a folder tree or a tree of letters, with tones, badges, notes, level lines, an open path and an optional queue under it. */}
{/* File-local on purpose (add-a-course-document.md §6e-quater): one consumer, no catalog entry, not registered. The second document that wants it promotes it. */}
{/* A leaf takes the next column; a parent sits centred over its first and last child. Every node name in one tree is unique, because tones, badges and notes are keyed by it. */}

export function HierarchyPicture({ tree, tones = {}, badges = {}, notes = {}, path = [], levels = false, queue, caption, label }) {
  const boxH = 26;
  const levelH = 64;
  const padX = 12;
  const padTop = 20;
  const labelW = levels ? 62 : 0;
  const widthOf = (name) => Math.max(40, name.length * 7.6 + 16);
  const nodes = [];
  let leaves = 0;
  const walk = (t, depth, parent) => {
    const me = { name: t.n, depth, parent, kids: [] };
    nodes.push(me);
    if (t.c && t.c.length > 0) {
      for (const c of t.c) me.kids.push(walk(c, depth + 1, me));
      me.x = (me.kids[0].x + me.kids[me.kids.length - 1].x) / 2;
    } else {
      me.x = leaves;
      leaves += 1;
    }
    return me;
  };
  walk(tree, 0, null);
  const pitch = Math.max(...nodes.map((n) => widthOf(n.name))) + 14;
  const depth = Math.max(...nodes.map((n) => n.depth));
  const hasNotes = Object.keys(notes).length > 0;
  const treeH = padTop + boxH + depth * levelH + (hasNotes ? 18 : 6);
  const queueY = treeH + 26;
  const captionY = (queue ? queueY + boxH + 26 : treeH + 18);
  // A caption wider than the drawing widens the canvas, and the drawing is centred in it, so no caption is ever clipped.
  const drawingW = labelW + 2 * padX + leaves * pitch;
  const width = Math.max(drawingW, caption ? caption.length * 6.6 + 24 : 0);
  const offset = (width - drawingW) / 2;
  const height = captionY + (caption ? 8 : -6);
  const cx = (n) => offset + labelW + padX + (n.x + 0.5) * pitch;
  const cy = (n) => padTop + boxH / 2 + n.depth * levelH;
  const onPath = new Set(path);
  const TONE = {
    idle: ['var(--color-surface)', 'var(--color-rule-strong)', 1.3],
    focus: ['var(--color-surface)', 'var(--color-focus)', 2.4],
    mark: ['var(--color-mark-soft)', 'var(--color-mark)', 2.2],
    keep: ['var(--color-keep-soft)', 'var(--color-keep)', 2.2],
    done: ['var(--color-sunk)', 'var(--color-rule-strong)', 1.3],
    faint: ['var(--color-surface)', 'var(--color-rule)', 1.2],
  };
  return (
    <svg viewBox={`0 0 ${width} ${height}`} style={{ width: '100%', maxWidth: `${Math.round(width * 1.35)}px`, height: 'auto', display: 'block', margin: '1rem auto' }} role="img" aria-label={label}>
      {levels
        ? [...new Set(nodes.map((n) => n.depth))].map((d) => (
            <g key={`lv${d}`}>
              <line x1={offset + labelW - 4} y1={padTop + boxH / 2 + d * levelH} x2={offset + drawingW - 4} y2={padTop + boxH / 2 + d * levelH} style={{ stroke: 'var(--color-rule)' }} strokeWidth="1" strokeDasharray="3 5" />
              <text x={offset + 4} y={padTop + boxH / 2 + d * levelH + 4} fontSize="11" style={{ fill: 'var(--color-ink-faint)' }}>{`nivel ${d}`}</text>
            </g>
          ))
        : null}
      {nodes.map((n) =>
        n.parent === null ? null : (
          <line key={`e-${n.name}`} x1={cx(n.parent)} y1={cy(n.parent) + boxH / 2} x2={cx(n)} y2={cy(n) - boxH / 2} style={{ stroke: onPath.has(n.name) && onPath.has(n.parent.name) ? 'var(--color-focus)' : tones[n.name] === 'faint' ? 'var(--color-rule)' : 'var(--color-rule-strong)' }} strokeWidth={onPath.has(n.name) && onPath.has(n.parent.name) ? 2.6 : 1.2} />
        ),
      )}
      {nodes.map((n) => {
        const [fill, stroke, weight] = TONE[tones[n.name] ?? 'idle'];
        const w = widthOf(n.name);
        const faint = tones[n.name] === 'faint';
        return (
          <g key={`n-${n.name}`} opacity={faint ? 0.5 : undefined}>
            <rect x={cx(n) - w / 2} y={cy(n) - boxH / 2} width={w} height={boxH} rx="6" style={{ fill, stroke }} strokeWidth={weight} strokeDasharray={faint ? '4 3' : undefined} />
            <text x={cx(n)} y={cy(n) + 4.5} textAnchor="middle" fontSize="13" fontWeight="600" style={{ fill: 'var(--color-ink)' }}>{n.name}</text>
            {badges[n.name] !== undefined ? (
              <text x={cx(n) + w / 2 - 3} y={cy(n) - boxH / 2 - 3} fontSize="11" fontWeight="700" paintOrder="stroke" strokeWidth="3" style={{ fill: 'var(--color-focus)', stroke: 'var(--color-ground)' }}>{badges[n.name]}</text>
            ) : null}
            {/* A leaf's note sits under it; a parent's goes to its left, clear of the edges leaving for its children. */}
            {notes[n.name] !== undefined ? (
              n.kids.length === 0 ? (
                <text x={cx(n)} y={cy(n) + boxH / 2 + 13} textAnchor="middle" fontSize="10.5" style={{ fill: 'var(--color-ink-soft)' }}>{notes[n.name]}</text>
              ) : (
                <text x={cx(n) - w / 2 - 5} y={cy(n) + 4} textAnchor="end" fontSize="10.5" paintOrder="stroke" strokeWidth="3" style={{ fill: 'var(--color-ink-soft)', stroke: 'var(--color-ground)' }}>{notes[n.name]}</text>
              )
            ) : null}
          </g>
        );
      })}
      {queue ? (
        <g>
          <text x={offset + labelW + padX} y={queueY - 8} fontSize="11" style={{ fill: 'var(--color-ink-faint)' }}>cola · sale por la izquierda</text>
          {queue.map((name, i) => {
            const w = pitch - 14;
            const x = offset + labelW + padX + i * pitch;
            return (
              <g key={`q-${name}`}>
                <rect x={x} y={queueY} width={w} height={boxH} rx="3" style={{ fill: 'var(--color-mark-soft)', stroke: 'var(--color-mark)' }} strokeWidth="1.6" />
                <text x={x + w / 2} y={queueY + 17.5} textAnchor="middle" fontSize="13" fontWeight="600" style={{ fill: 'var(--color-ink)' }}>{name}</text>
              </g>
            );
          })}
        </g>
      ) : null}
      {caption ? (
        <text x={width / 2} y={captionY} textAnchor="middle" fontSize="12" style={{ fill: 'var(--color-ink-soft)' }}>{caption}</text>
      ) : null}
    </svg>
  );
}

<Slide title="Una carpeta dentro de otra">
Una carpeta del computador guarda archivos y también otras carpetas, que a
su vez guardan más. Para llegar a un archivo hay que abrir una carpeta tras
otra, empezando por la de más arriba.

<HierarchyPicture tree={FOLDERS} label="Una carpeta home que contiene dos carpetas, fotos y ramos, y un archivo, notas.txt. La carpeta fotos contiene playa.jpg y perro.jpg. La carpeta ramos contiene dos carpetas: eda, con t1.pdf y t2.pdf, y calculo, con guia.pdf." />

Ninguna de las estructuras que guardan elementos en fila sirve para esta
forma. Un arreglo, una lista, una pila o una cola ponen cada elemento
después de otro, y una carpeta tiene varios elementos debajo, cada uno con
los suyos.

</Slide>

<Slide title="El árbol y sus nodos">
Un **árbol** es una colección de elementos, llamados **nodos**, organizados
en una jerarquía:

1. **Un nodo, la raíz, está arriba de todo** y no cuelga de ningún otro.
2. **Cada uno de los demás cuelga de exactamente un nodo**, su **padre**.
   Los nodos que cuelgan de un mismo padre son sus **hijos**.

La línea que une a un padre con un hijo se llama **arista**. Un nodo puede
tener cualquier cantidad de hijos, incluso ninguno.

<HierarchyPicture tree={FOLDERS} tones={{ 'home/': 'focus', 'ramos/': 'mark', 'eda/': 'keep', 'calculo/': 'keep' }} badges={{ 'home/': 'raíz', 'ramos/': 'padre' }} notes={{ 'eda/': 'hijo', 'calculo/': 'hijo' }} label="El árbol de carpetas con la raíz home marcada, y la carpeta ramos marcada como padre de sus dos hijos, eda y calculo." caption="home/ es la raíz; ramos/ es el padre de eda/ y calculo/" />

</Slide>

<Slide title="Hojas y nodos internos">
Un nodo sin hijos es una **hoja**. Un nodo con al menos un hijo es un
**nodo interno**. En un sistema de archivos, las hojas son los archivos y las
carpetas vacías, y los nodos internos son las carpetas que guardan algo.

<HierarchyPicture tree={FOLDERS} tones={{ 'playa.jpg': 'mark', 'perro.jpg': 'mark', 't1.pdf': 'mark', 't2.pdf': 'mark', 'guia.pdf': 'mark', 'notas.txt': 'mark' }} notes={{ 'playa.jpg': 'hoja', 'perro.jpg': 'hoja', 't1.pdf': 'hoja', 't2.pdf': 'hoja', 'guia.pdf': 'hoja', 'notas.txt': 'hoja' }} label="El árbol de carpetas con sus seis hojas marcadas: playa.jpg, perro.jpg, t1.pdf, t2.pdf, guia.pdf y notas.txt. Las cinco carpetas son nodos internos." caption="seis hojas, los archivos; cinco nodos internos, las carpetas" />

</Slide>

<Slide title="Caminos desde la raíz">
Un **camino** es una secuencia de nodos en la que cada uno es el padre del
siguiente. Su **largo** es la cantidad de aristas que recorre: uno menos que
la cantidad de nodos.

Desde la raíz hasta cualquier nodo hay **exactamente un camino**, porque
cada nodo tiene un solo padre y subir de padre en padre no deja opciones. En
un sistema de archivos, ese camino es la **ruta** del archivo.

<HierarchyPicture tree={FOLDERS} tones={{ 'home/': 'focus', 'ramos/': 'focus', 'eda/': 'focus', 't1.pdf': 'focus' }} path={['home/', 'ramos/', 'eda/', 't1.pdf']} label="El camino desde la raíz hasta t1.pdf: home, ramos, eda, t1.pdf. Cuatro nodos y tres aristas." caption="home/ramos/eda/t1.pdf: cuatro nodos, un camino de largo 3" />

</Slide>

<Slide title="Subárboles">
Un nodo, junto con sus hijos, los hijos de sus hijos y así hasta abajo,
forma un árbol que tiene a ese nodo como raíz: un **subárbol**. Cada carpeta
es la raíz de un subárbol, el de todo lo que guarda.

<HierarchyPicture tree={FOLDERS} tones={{ 'home/': 'faint', 'fotos/': 'faint', 'playa.jpg': 'faint', 'perro.jpg': 'faint', 'notas.txt': 'faint', 'ramos/': 'keep', 'eda/': 'keep', 't1.pdf': 'keep', 't2.pdf': 'keep', 'calculo/': 'keep', 'guia.pdf': 'keep' }} label="El subárbol que tiene raíz en ramos: ramos, eda, t1.pdf, t2.pdf, calculo y guia.pdf. El resto del árbol aparece atenuado." caption="el subárbol de ramos/: seis nodos, y ramos/ es su raíz" />

Por eso un árbol se puede definir a partir de árboles más pequeños: **un árbol
es una raíz y, debajo de ella, cero o más subárboles**. Esa definición es
**recursiva**, y las operaciones sobre árboles también lo son: lo que se
hace con el árbol se hace, igual, con cada subárbol.

</Slide>

<Slide title="Profundidad y niveles">
La **profundidad** de un nodo es el largo del camino desde la raíz hasta él.
La raíz tiene profundidad 0, sus hijos 1, los hijos de ellos 2, y así.

Los nodos de igual profundidad forman un **nivel**. El nivel $$d$$ reúne
a todos los nodos que están a $$d$$ aristas de la raíz.

<HierarchyPicture tree={FOLDERS} levels label="El árbol de carpetas con una línea por nivel. Nivel 0: home. Nivel 1: fotos, ramos y notas.txt. Nivel 2: playa.jpg, perro.jpg, eda y calculo. Nivel 3: t1.pdf, t2.pdf y guia.pdf." caption="la profundidad de cada nodo es el número de su nivel" />

</Slide>

<Slide title="La altura">
La **altura** de un nodo es el largo del camino más largo que baja desde él
hasta una hoja. Una hoja tiene altura 0, y un nodo interno tiene una unidad
más que el más alto de sus hijos.

La **altura del árbol** es la altura de su raíz: la cantidad de niveles menos
uno. La profundidad se mide desde arriba y la altura desde abajo.

<HierarchyPicture tree={FOLDERS} badges={{ 'home/': 'h=3', 'fotos/': 'h=1', 'playa.jpg': 'h=0', 'perro.jpg': 'h=0', 'ramos/': 'h=2', 'eda/': 'h=1', 't1.pdf': 'h=0', 't2.pdf': 'h=0', 'calculo/': 'h=1', 'guia.pdf': 'h=0', 'notas.txt': 'h=0' }} label="El árbol de carpetas con la altura de cada nodo. Las hojas tienen altura 0; fotos, eda y calculo, 1; ramos, 2; y la raíz home, 3, que es la altura del árbol." caption="la altura del árbol es 3: el camino más largo baja de home/ a un archivo de eda/" />

La altura dice cuántas aristas hay que bajar, como máximo, desde la raíz para
llegar a cualquier nodo.

</Slide>

## Recorridos de un árbol

<Slide title="El recorrido de un árbol">
**Recorrer** una estructura es visitar cada uno de sus elementos una vez. En
una fila hay un orden natural: del primero al último. En un árbol no lo hay:
después de la raíz puede seguir cualquiera de sus hijos, y después de un
hijo, uno de sus hijos o uno de sus hermanos.

Un **recorrido** es una regla que decide ese orden. Hay varias, y cada una
responde una pregunta distinta sobre la jerarquía.

</Slide>

<Slide title="El preorden">
En **preorden**, cada nodo se visita **antes** que sus subárboles, y los
subárboles se recorren de izquierda a derecha, cada uno con la misma regla.

<HierarchyPicture tree={FOLDERS} badges={{ 'home/': '1', 'fotos/': '2', 'playa.jpg': '3', 'perro.jpg': '4', 'ramos/': '5', 'eda/': '6', 't1.pdf': '7', 't2.pdf': '8', 'calculo/': '9', 'guia.pdf': '10', 'notas.txt': '11' }} label="El árbol de carpetas con el orden de visita en preorden: home 1, fotos 2, playa.jpg 3, perro.jpg 4, ramos 5, eda 6, t1.pdf 7, t2.pdf 8, calculo 9, guia.pdf 10, notas.txt 11." caption="preorden: cada carpeta, antes que su contenido" />

</Slide>

<Slide title="El listado de una carpeta">
El preorden es el orden en que se lista el contenido de una carpeta: cada
carpeta aparece antes que lo que guarda, y lo que guarda aparece completo
antes de pasar a la carpeta siguiente.

```
home/
├── fotos/
│   ├── playa.jpg
│   └── perro.jpg
├── ramos/
│   ├── eda/
│   │   ├── t1.pdf
│   │   └── t2.pdf
│   └── calculo/
│       └── guia.pdf
└── notas.txt
```

</Slide>

<Slide title="El postorden">
En **postorden**, cada nodo se visita **después** de sus subárboles.

Es el orden que necesita una pregunta que se responde desde las hojas: el
tamaño de una carpeta es la suma de lo que guarda, así que antes de sumar
una carpeta hay que conocer el tamaño de cada cosa que tiene dentro.

<HierarchyPicture tree={FOLDERS} badges={{ 'playa.jpg': '1', 'perro.jpg': '2', 'fotos/': '3', 't1.pdf': '4', 't2.pdf': '5', 'eda/': '6', 'guia.pdf': '7', 'calculo/': '8', 'ramos/': '9', 'notas.txt': '10', 'home/': '11' }} notes={{ 'playa.jpg': '2 MB', 'perro.jpg': '3 MB', 'fotos/': '5 MB', 't1.pdf': '1 MB', 't2.pdf': '1 MB', 'eda/': '2 MB', 'guia.pdf': '2 MB', 'calculo/': '2 MB', 'ramos/': '4 MB', 'notas.txt': '1 MB', 'home/': '10 MB' }} label="El árbol de carpetas con el orden de visita en postorden y el tamaño de cada nodo. Primero playa.jpg y perro.jpg, después fotos, que suma 5 MB; después t1.pdf, t2.pdf y eda, 2 MB; guia.pdf y calculo, 2 MB; ramos, 4 MB; notas.txt, 1 MB; y al final home, 10 MB." caption="postorden: cada carpeta, cuando ya se conoce el tamaño de todo lo que guarda" />

</Slide>

<Slide title="El recorrido por niveles">
El recorrido **por niveles** visita primero la raíz, después todos los nodos
de profundidad 1, después los de profundidad 2, y así; dentro de cada nivel,
de izquierda a derecha.

Es el orden que encuentra primero lo más cercano a la raíz: si se busca un
archivo por su nombre, el primero que aparece por niveles es el que está a
menos carpetas de distancia.

<HierarchyPicture tree={FOLDERS} levels badges={{ 'home/': '1', 'fotos/': '2', 'ramos/': '3', 'notas.txt': '4', 'playa.jpg': '5', 'perro.jpg': '6', 'eda/': '7', 'calculo/': '8', 't1.pdf': '9', 't2.pdf': '10', 'guia.pdf': '11' }} label="El árbol de carpetas con el orden de visita por niveles: home 1; fotos 2, ramos 3, notas.txt 4; playa.jpg 5, perro.jpg 6, eda 7, calculo 8; t1.pdf 9, t2.pdf 10, guia.pdf 11." caption="por niveles: un nivel completo antes que el siguiente" />

</Slide>

<Slide title="Una cola para recorrer por niveles">
El preorden y el postorden se escriben con la misma recursión que define al
árbol: un nodo y, debajo, sus subárboles. El recorrido por niveles no sigue
esa forma, porque salta de un subárbol a otro dentro del mismo nivel. Lo que
lo ordena es una **cola**, que entrega los elementos en el mismo orden en
que entraron:

1. Se pone la raíz en la cola.
2. Mientras la cola no esté vacía, se saca el primero, se visita, y sus
   hijos entran al final de la cola.

Un nodo entra a la cola cuando se visita su padre, así que los hijos de los
nodos de un nivel entran todos detrás de ese nivel: la cola tiene siempre lo
que falta del nivel actual y, después, el comienzo del siguiente.

<HierarchyPicture tree={FOLDERS} tones={{ 'home/': 'done', 'fotos/': 'done', 'ramos/': 'mark', 'notas.txt': 'mark', 'playa.jpg': 'mark', 'perro.jpg': 'mark' }} badges={{ 'home/': '1', 'fotos/': '2' }} queue={['ramos/', 'notas.txt', 'playa.jpg', 'perro.jpg']} label="El recorrido por niveles después de visitar home y fotos. En la cola, de adelante hacia atrás: ramos y notas.txt, que quedan del nivel 1, y playa.jpg y perro.jpg, los hijos de fotos, que abren el nivel 2." caption="visitados home/ y fotos/: en la cola, lo que queda del nivel 1 y el comienzo del 2" />

</Slide>

<Slide title="Tres recorridos · la pregunta">
Escribamos el preorden, el postorden y el recorrido por niveles de este
árbol antes de pasar a la respuesta.

<HierarchyPicture tree={LETTERS_ORDER} label="Un árbol de siete nodos. La raíz a tiene tres hijos: b, c y d. c tiene dos hijos, e y f, y f tiene un hijo, g." />

</Slide>

<Slide title="Tres recorridos · la respuesta">
Cada recorrido aplica su regla en cada nodo: el preorden escribe el nodo
antes de sus subárboles, el postorden después, y el recorrido por niveles
termina un nivel antes de empezar el siguiente.

| Recorrido    | Orden           |
| ------------ | --------------- |
| Preorden     | a b c e f g d   |
| Postorden    | b e g f c d a   |
| Por niveles  | a b c d e f g   |

<HierarchyPicture tree={LETTERS_ORDER} badges={{ a: '1', b: '2', c: '3', e: '4', f: '5', g: '6', d: '7' }} label="El árbol con el orden de visita en preorden: a 1, b 2, c 3, e 4, f 5, g 6, d 7." caption="el preorden, número a número: a, b, c, e, f, g, d" />

</Slide>

{/* BinaryPicture — a static drawing of a binary tree, with the geometry of the binary-tree recipe of <SequenceStepper> (sequenceStepperTreeLayout.ts): every node in the column of its inorder position and on the row of its depth, so a figure and the widget beside it draw the same tree. File-local like HierarchyPicture (§6e-quater). A tree is { v, l, r }; values are unique within one tree, because tones, badges and notes are keyed by them. */}

export function BinaryPicture({ tree, tones = {}, badges = {}, notes = {}, levels = false, strip = false, caption, size = 1, minColumns = 0, compact = false, label }) {
  const r = 17;
  // compact narrows the columns for figures set three in a row, so each fills its own column at full size.
  const pitch = compact ? 38 : 46;
  const levelH = compact ? 50 : 56;
  const pad = 16;
  const labelW = levels ? 58 : 0;
  const nodes = [];
  let column = 0;
  const walk = (t, depth, parent) => {
    if (!t) return;
    const me = { v: t.v, depth, parent };
    walk(t.l, depth + 1, me);
    me.x = column;
    column += 1;
    nodes.push(me);
    walk(t.r, depth + 1, me);
  };
  walk(tree, 0, null);
  const depth = Math.max(0, ...nodes.map((n) => n.depth));
  const hasNotes = Object.keys(notes).length > 0;
  // strip draws the inorder under the tree, one slot per column: each value lands under its own node.
  const stripY = 2 * pad + 2 * r + depth * levelH + (hasNotes ? 12 : 0) + 6;
  const treeH = strip ? stripY + 30 + pad : stripY - 6;
  // minColumns gives figures set side by side one canvas width, so their nodes come out the same size; the tree is centred in it.
  const columns = Math.max(column, minColumns, 1);
  const shift = ((columns - column) / 2) * pitch;
  // A caption wider than the drawing widens the canvas, and the drawing is centred in it, so no caption is ever clipped.
  const drawingW = labelW + 2 * pad + columns * pitch;
  const width = Math.max(drawingW, caption ? caption.length * 6.6 + 24 : 0);
  const offset = (width - drawingW) / 2;
  const height = treeH + (caption ? 20 : 0);
  const cx = (n) => offset + labelW + pad + shift + (n.x + 0.5) * pitch;
  const cy = (n) => pad + r + n.depth * levelH;
  const TONE = {
    idle: ['var(--color-surface)', 'var(--color-rule-strong)', 1.3],
    focus: ['var(--color-surface)', 'var(--color-focus)', 2.4],
    mark: ['var(--color-mark-soft)', 'var(--color-mark)', 2.2],
    keep: ['var(--color-keep-soft)', 'var(--color-keep)', 2.2],
    done: ['var(--color-sunk)', 'var(--color-rule-strong)', 1.3],
    faint: ['var(--color-surface)', 'var(--color-rule)', 1.2],
  };
  return (
    <svg viewBox={`0 0 ${width} ${height}`} style={{ width: '100%', maxWidth: `${Math.round(width * 1.4 * size)}px`, height: 'auto', display: 'block', margin: '1rem auto' }} role="img" aria-label={label}>
      {levels
        ? [...Array(depth + 1).keys()].map((d) => (
            <g key={`lv${d}`}>
              <line x1={offset + labelW - 4} y1={pad + r + d * levelH} x2={offset + drawingW - 4} y2={pad + r + d * levelH} style={{ stroke: 'var(--color-rule)' }} strokeWidth="1" strokeDasharray="3 5" />
              <text x={offset + 4} y={pad + r + d * levelH + 4} fontSize="11" style={{ fill: 'var(--color-ink-faint)' }}>{`nivel ${d}`}</text>
            </g>
          ))
        : null}
      {nodes.map((n) => {
        if (n.parent === null) return null;
        const dx = cx(n) - cx(n.parent);
        const dy = cy(n) - cy(n.parent);
        const len = Math.hypot(dx, dy);
        const faint = tones[n.v] === 'faint';
        return <line key={`e${n.v}`} x1={cx(n.parent) + (dx / len) * r} y1={cy(n.parent) + (dy / len) * r} x2={cx(n) - (dx / len) * r} y2={cy(n) - (dy / len) * r} style={{ stroke: faint ? 'var(--color-rule)' : 'var(--color-rule-strong)' }} strokeWidth="1.3" strokeDasharray={faint ? '4 3' : undefined} />;
      })}
      {nodes.map((n) => {
        const [fill, stroke, weight] = TONE[tones[n.v] ?? 'idle'];
        const faint = tones[n.v] === 'faint';
        return (
          <g key={`n${n.v}`} opacity={faint ? 0.5 : undefined}>
            <circle cx={cx(n)} cy={cy(n)} r={r} style={{ fill, stroke }} strokeWidth={weight} strokeDasharray={faint ? '4 3' : undefined} />
            <text x={cx(n)} y={cy(n) + 5} textAnchor="middle" fontSize="14" fontWeight="600" style={{ fill: 'var(--color-ink)' }}>{n.v}</text>
            {badges[n.v] !== undefined ? (
              <text x={cx(n) + r - 1} y={cy(n) - r + 3} fontSize="10.5" fontWeight="700" paintOrder="stroke" strokeWidth="3" style={{ fill: 'var(--color-focus)', stroke: 'var(--color-ground)' }}>{badges[n.v]}</text>
            ) : null}
            {notes[n.v] !== undefined ? (
              <text x={cx(n)} y={cy(n) + r + 12} textAnchor="middle" fontSize="10" paintOrder="stroke" strokeWidth="3" style={{ fill: 'var(--color-ink-soft)', stroke: 'var(--color-ground)' }}>{notes[n.v]}</text>
            ) : null}
          </g>
        );
      })}
      {strip
        ? nodes.map((n) => (
            <g key={`s${n.v}`}>
              <line x1={cx(n)} y1={cy(n) + r + 3} x2={cx(n)} y2={stripY - 3} style={{ stroke: 'var(--color-rule)' }} strokeWidth="1" strokeDasharray="2 4" />
              <rect x={cx(n) - 19} y={stripY} width="38" height="30" rx="3" style={{ fill: 'var(--color-surface)', stroke: 'var(--color-rule-strong)' }} strokeWidth="1" />
              <text x={cx(n)} y={stripY + 20} textAnchor="middle" fontSize="14" fontWeight="600" style={{ fill: 'var(--color-ink)' }}>{n.v}</text>
            </g>
          ))
        : null}
      {caption ? (
        <text x={width / 2} y={treeH + 12} textAnchor="middle" fontSize="12" style={{ fill: 'var(--color-ink-soft)' }}>{caption}</text>
      ) : null}
    </svg>
  );
}

## El árbol binario

<Slide title="Dos hijos con nombre">
Un **árbol binario** es un árbol en el que cada nodo tiene **a lo más dos
hijos**, y cada hijo tiene un nombre: es el **izquierdo** o el **derecho**.
Aunque un nodo tenga un solo hijo, importa de qué lado está.

<div style={{ display: 'grid', gridTemplateColumns: 'repeat(auto-fit, minmax(180px, 1fr))', gap: '1rem', alignItems: 'end' }}>
<BinaryPicture tree={{ v: 5, l: { v: 8 } }} size={1.2} label="Un árbol binario de dos nodos: la raíz 5 con un hijo izquierdo, 8." caption="8 es el hijo izquierdo de 5" />
<BinaryPicture tree={{ v: 5, r: { v: 8 } }} size={1.2} label="Otro árbol binario de dos nodos: la raíz 5 con un hijo derecho, 8." caption="8 es el hijo derecho de 5" />
</div>

Como árboles generales, los dos son el mismo: una raíz con un hijo. Como
árboles binarios son distintos. Nombrar los dos hijos permite decir dónde
está cada nodo **respecto de su padre**, y con eso aparecen cosas que un
árbol general no tiene, como visitar un nodo entre sus dos lados.

</Slide>

<Slide title="Una definición recursiva">
Un árbol binario es una de dos cosas:

1. **El árbol vacío**, que no tiene nodos.
2. **Un nodo** con un valor y dos árboles binarios debajo: el subárbol
   izquierdo y el subárbol derecho.

El árbol vacío no es un detalle: es lo que hay debajo de cada hoja, y lo
que termina la recursión. Por eso casi toda función sobre un árbol binario
tiene la misma forma: **qué devolver con el árbol vacío**, y **cómo combinar
el valor del nodo con lo que devuelven sus dos subárboles**.

<BinaryPicture tree={BT} notes={{ 4: 'hoja', 7: 'hoja', 6: 'hoja' }} label="El árbol binario 3, con hijos 9 y 1; el 9 con hijos 4 y 7; el 1 con un solo hijo, el 6, a la derecha. Las hojas son 4, 7 y 6." caption="debajo de cada hoja, y a la izquierda del 1, hay un árbol vacío" />

</Slide>

<Slide title="Las invariantes del árbol binario">
Un árbol binario sostiene dos propiedades en todo momento:

1. **Cada nodo tiene a lo más dos hijos, y cada uno es el izquierdo o el
   derecho.** Es lo que permite escribir el nodo con dos campos fijos, en
   lugar de una lista de hijos.
2. **Cada nodo, salvo la raíz, tiene exactamente un padre.** Por eso hay un
   único camino desde la raíz hasta cada nodo, y por eso un recorrido que
   baja por los dos lados de cada nodo visita cada uno una sola vez.

Ninguna de las dos dice nada sobre los **valores**: un árbol binario no
ordena lo que guarda.

</Slide>

<Slide title="Los nodos en Java">
Cada nodo guarda su valor y una referencia a cada hijo; el árbol guarda una
referencia a la raíz. Un subárbol vacío es una referencia en `null`.

```java
class Node<T> {
    T value;
    Node<T> left;
    Node<T> right;

    Node(T value) {
        this.value = value;
    }
}

class BinaryTree<T> {
    Node<T> root;
}
```

Un árbol vacío es un `BinaryTree` con `root` en `null`. Las operaciones
reciben un `Node<T>`, la raíz de un subárbol, y se llaman a sí mismas con
`node.left` y `node.right`.

</Slide>

<Slide title="El preorden en un árbol binario">
Con dos hijos con nombre, cada recorrido es un método de tres líneas: la
visita y las dos llamadas recursivas. En **preorden**, la visita va antes de
las dos llamadas.

<SequenceStepper eda="binary-tree" operation="preorder" values={[3, 9, 1, 4, 7, null, 6]} />

</Slide>

<Slide title="El inorden">
El **inorden** es el recorrido que solo existe con izquierda y derecha: se
recorre el subárbol izquierdo, se visita el nodo y después se recorre el
derecho. La visita va **entre** las dos llamadas.

<SequenceStepper eda="binary-tree" operation="inorder" values={[3, 9, 1, 4, 7, null, 6]} />

Cada nodo está dibujado en la columna de su posición en el inorden, así que
el inorden se lee de izquierda a derecha y cada valor cae justo debajo de su
nodo.

</Slide>

<Slide title="El postorden en un árbol binario">
En **postorden**, la visita va **después** de las dos llamadas: un nodo se
visita cuando sus dos subárboles ya se recorrieron.

<SequenceStepper eda="binary-tree" operation="postorder" values={[3, 9, 1, 4, 7, null, 6]} />

</Slide>

<Slide title="La altura por recursión">
La altura sigue la definición recursiva al pie de la letra. El árbol vacío
tiene altura $$-1$$, para que una hoja, con dos subárboles vacíos, tenga
altura $$1 + \max(-1, -1) = 0$$. Un nodo tiene una unidad más que el más alto
de sus dos subárboles, así que responde **después** de ellos: es un
postorden.

<SequenceStepper eda="binary-tree" operation="height" values={[3, 9, 1, 4, 7, null, 6]} />

</Slide>

<Slide title="Contar hojas · la pregunta">
Con la misma forma de la altura —qué devolver con el árbol vacío y cómo
combinar los dos subárboles—, escribamos un método recursivo que cuente las
hojas de un árbol binario:

```java
int countLeaves(Node<T> node)
```

<BinaryPicture tree={BT} label="El árbol binario de la clase: 3, con hijos 9 y 1; el 9 con hijos 4 y 7; el 1 con un hijo derecho, 6." caption="en este árbol, countLeaves(root) devuelve 3" />

</Slide>

<Slide title="Contar hojas · la respuesta">
El árbol vacío no tiene hojas. Un nodo sin hijos es una hoja. Cualquier otro
nodo tiene tantas hojas como sus dos subárboles juntos.

```java
int countLeaves(Node<T> node) {
    if (node == null) return 0;
    if (node.left == null && node.right == null) {
        return 1;
    }
    return countLeaves(node.left)
        + countLeaves(node.right);
}
```

Cada nodo se visita una vez, así que cuesta $$\Theta(n)$$ en un árbol de
$$n$$ nodos.

</Slide>

<Slide title="Invertir un árbol · la pregunta">
**Invertir** un árbol binario es cambiar, en cada nodo, el subárbol izquierdo
por el derecho: el árbol queda como su imagen en un espejo. Escribamos el
método recursivo que lo hace sobre el mismo árbol, sin crear nodos:

```java
void invert(Node<T> node)
```

<div style={{ display: 'grid', gridTemplateColumns: 'repeat(auto-fit, minmax(200px, 1fr))', gap: '1rem', alignItems: 'end' }}>
<BinaryPicture tree={BT} label="El árbol antes de invertir: 3, con hijos 9 y 1; el 9 con hijos 4 y 7; el 1 con un hijo derecho, 6." caption="antes" />
<BinaryPicture tree={BT_INVERTED} label="El árbol después de invertir: 3, con hijos 1 y 9; el 1 con un hijo izquierdo, 6; el 9 con hijos 7 y 4." caption="después" />
</div>

</Slide>

<Slide title="Invertir un árbol · la respuesta">
El árbol vacío ya está invertido. En un nodo se intercambian sus dos
referencias, y después se invierte cada subárbol con la misma regla.

```java
void invert(Node<T> node) {
    if (node == null) return;
    Node<T> saved = node.left;
    node.left = node.right;
    node.right = saved;
    invert(node.left);
    invert(node.right);
}
```

El intercambio necesita una variable auxiliar: si se asignara `node.left`
primero, la referencia al subárbol izquierdo se perdería. Como cada nodo se
visita una vez, cuesta $$\Theta(n)$$.

</Slide>

<Slide title="Estricto, lleno y completo">
Tres formas de árbol binario tienen nombre:

- **Estricto**: cada nodo tiene cero o dos hijos, nunca uno.
- **Lleno**: es estricto y todas sus hojas están en el último nivel; cada
  nivel tiene todos los nodos que caben.
- **Completo**: todos los niveles están llenos, salvo quizás el último, que
  se llena de izquierda a derecha, sin huecos.

<div style={{ display: 'grid', gridTemplateColumns: 'repeat(auto-fit, minmax(190px, 1fr))', gap: '1rem', alignItems: 'end' }}>
<BinaryPicture tree={{ v: 1, l: { v: 2 }, r: { v: 3, l: { v: 4 }, r: { v: 5 } } }} minColumns={7} compact label="Un árbol estricto: 1 con hijos 2 y 3; 3 con hijos 4 y 5; 2 es hoja. Todos los nodos tienen cero o dos hijos." caption="estricto" />
<BinaryPicture tree={{ v: 1, l: { v: 2, l: { v: 4 }, r: { v: 5 } }, r: { v: 3, l: { v: 6 }, r: { v: 7 } } }} minColumns={7} compact label="Un árbol lleno de altura 2: siete nodos, todos los internos con dos hijos y las cuatro hojas en el último nivel." caption="lleno" />
<BinaryPicture tree={{ v: 1, l: { v: 2, l: { v: 4 }, r: { v: 5 } }, r: { v: 3, l: { v: 6 } } }} minColumns={7} compact label="Un árbol completo de seis nodos: los dos primeros niveles llenos y el último ocupado de izquierda a derecha, con el lugar del último nodo vacío." caption="completo" />
</div>

</Slide>

<Slide title="Cuántos nodos caben en una altura">
Cada nivel de un árbol binario tiene, a lo más, el doble de nodos que el
anterior: el nivel $$d$$ tiene a lo más $$2^d$$. Un árbol **lleno** de altura
$$h$$ los tiene todos:

$$
1 + 2 + 4 + \cdots + 2^h = 2^{h+1} - 1
$$

<BinaryPicture tree={{ v: 1, l: { v: 2, l: { v: 4 }, r: { v: 5 } }, r: { v: 3, l: { v: 6 }, r: { v: 7 } } }} levels label="Un árbol lleno de altura 2 con una línea por nivel: un nodo en el nivel 0, dos en el nivel 1, cuatro en el nivel 2; siete en total." caption="altura 2: 1 + 2 + 4 = 7 nodos" />

Ningún árbol binario de altura $$h$$ tiene más nodos que el lleno.

</Slide>

<Slide title="La altura mínima y la máxima">
Con $$n$$ nodos, la altura de un árbol binario queda entre dos extremos:

- **La más baja posible es $$\lfloor \log_2 n \rfloor$$**: los nodos llenan
  cada nivel antes de abrir el siguiente, como en un árbol completo. Como un
  árbol de altura $$h$$ tiene a lo más $$2^{h+1} - 1$$ nodos, hacen falta
  al menos $$\lfloor \log_2 n \rfloor$$ niveles bajo la raíz.
- **La más alta posible es $$n - 1$$**: cada nodo tiene un solo hijo, y el
  árbol es una cadena, una lista enlazada dibujada en diagonal.

<div style={{ display: 'grid', gridTemplateColumns: 'repeat(auto-fit, minmax(220px, 1fr))', gap: '1rem', alignItems: 'end' }}>
<BinaryPicture tree={{ v: 4, l: { v: 2, l: { v: 1 }, r: { v: 3 } }, r: { v: 6, l: { v: 5 }, r: { v: 7 } } }} label="Siete nodos en un árbol de altura 2, la mínima." caption="7 nodos, altura 2" />
<BinaryPicture tree={{ v: 1, r: { v: 2, r: { v: 3, r: { v: 4, r: { v: 5, r: { v: 6, r: { v: 7 } } } } } } }} size={0.75} label="Los mismos siete nodos en una cadena: cada nodo tiene un solo hijo, a la derecha. Altura 6, la máxima." caption="7 nodos, altura 6" />
</div>

Todas las operaciones que bajan por el árbol pagan su altura, y entre esos
dos extremos la diferencia es la que hay entre $$\log_2 n$$ y $$n$$.

</Slide>

<Slide title="La altura con $$n$$ nodos · la pregunta">
Antes de pasar a la respuesta, contestemos: con 15 nodos, ¿cuál es la altura
mínima de un árbol binario, y cuál la máxima? ¿Cuántos nodos tiene un árbol
binario lleno de altura 4?

</Slide>

<Slide title="La altura con $$n$$ nodos · la respuesta">
La mínima es la de un árbol que llena cada nivel, y la máxima la de una
cadena. Un árbol lleno suma todos sus niveles.

| Pregunta                               | Respuesta                                  |
| -------------------------------------- | ------------------------------------------ |
| Altura mínima con 15 nodos             | $$\lfloor \log_2 15 \rfloor = 3$$: un árbol lleno de cuatro niveles |
| Altura máxima con 15 nodos             | $$15 - 1 = 14$$: una cadena                 |
| Nodos de un árbol lleno de altura 4    | $$2^{5} - 1 = 31$$                          |

</Slide>

<Slide title="Costos del árbol binario">
Cada operación recorre el árbol entero, porque sin un orden entre los
valores no hay subárbol que pueda saltarse:

| Molde     | Operación                               | Peor caso       | Invariante que restaura      |
| --------- | --------------------------------------- | --------------- | ---------------------------- |
| Consultar | `preorder`, `inorder`, `postorder`      | $$\Theta(n)$$   | Ninguna: no cambian el árbol |
| Consultar | `height`, `countLeaves`                 | $$\Theta(n)$$   | Ninguna: no cambian el árbol |
| Modificar | `invert`                                | $$\Theta(n)$$   | Ninguna: el intercambio mantiene las dos |

</Slide>

<Slide title="Buscar en un árbol binario">
Para saber si un valor está en un árbol binario, la única regla posible es
mirar el nodo y, si no es, buscar en sus **dos** subárboles: nada dice en cuál
de los dos puede estar.

<SequenceStepper eda="binary-tree" operation="search" values={[3, 9, 1, 4, 7, null, 6]} target={5} />

Cuando el valor no está, la búsqueda compara los $$n$$ nodos: cuesta
$$\Theta(n)$$, lo mismo que buscar en una lista. La jerarquía organiza los
datos, pero sola no dice dónde buscar.

</Slide>

## El árbol binario de búsqueda

<Slide title="La búsqueda binaria en un arreglo ordenado">
En un arreglo **ordenado** se busca sin recorrerlo: se compara con el
elemento del medio y, según sea mayor o menor, se descarta la mitad que no
puede contenerlo. Cada comparación parte el problema en dos, así que bastan
$$\lfloor \log_2 n \rfloor + 1$$ comparaciones.

<SortedRow values={[1, 2, 3, 4, 5, 6, 7, 8, 9]} hot={4} out={[0, 1, 2, 3]} label="El arreglo ordenado del 1 al 9. Buscando el 7, la primera comparación es con el 5, el del medio, y la mitad izquierda, del 1 al 4, queda descartada." caption="buscar 7: se compara con 5, el del medio, y la mitad izquierda se descarta" />

El problema es **insertar**. Para que el arreglo siga ordenado, un valor
nuevo tiene que entrar en su lugar, y todos los mayores se corren una
casilla: $$\Theta(n)$$.

</Slide>

<Slide title="Las decisiones de la búsqueda binaria">
Las comparaciones de una búsqueda binaria siempre siguen el mismo patrón. La
primera es con el elemento del medio; si el buscado es menor, la segunda es
con el medio de la mitad izquierda; si es mayor, con el medio de la derecha;
y así. Dibujadas, esas decisiones forman un **árbol binario**: el medio es la
raíz, y cada mitad, un subárbol.

<BinaryPicture tree={FROM_ARRAY} strip label="El árbol de decisiones de una búsqueda binaria sobre el arreglo del 1 al 9. La raíz es 5; a la izquierda, 2, con hijos 1 y 3, y el 3 con un hijo derecho, 4; a la derecha, 7, con hijos 6 y 8, y el 8 con un hijo derecho, 9. Debajo, el arreglo ordenado, con cada valor exactamente bajo su nodo." caption="el arreglo ordenado es el inorden del árbol" />

Si, en lugar del arreglo, se guardan esas decisiones como **nodos
enlazados**, buscar sigue siendo comparar y bajar por un lado. E insertar ya
no corre nada: el valor nuevo se cuelga como una hoja en el lugar donde su
búsqueda termina.

</Slide>

<Slide title="El árbol binario de búsqueda">
Un **árbol binario de búsqueda** —en inglés, *binary search tree*, o
**BST**— es un árbol binario que cumple esta **invariante**:

> **para cada nodo, todos los valores de su subárbol izquierdo son menores
> que el suyo, y todos los de su subárbol derecho son mayores.**

La palabra que importa es **todos**. No basta con que cada hijo esté del lado
correcto de su padre: un valor tiene que estar del lado correcto de **cada**
nodo por encima de él.

<div style={{ display: 'grid', gridTemplateColumns: 'repeat(auto-fit, minmax(220px, 1fr))', gap: '1rem', alignItems: 'end' }}>
<BinaryPicture tree={{ v: 5, l: { v: 3, l: { v: 1 }, r: { v: 4 } }, r: { v: 8 } }} minColumns={5} label="Un árbol de búsqueda: 5 con hijos 3 y 8; el 3 con hijos 1 y 4. Todo lo que está a la izquierda del 5 es menor que 5, y todo lo de la derecha, mayor." caption="cumple la invariante en cada nodo" />
<BinaryPicture tree={{ v: 5, l: { v: 3, l: { v: 1 }, r: { v: 7 } }, r: { v: 8 } }} tones={{ 7: 'mark' }} notes={{ 7: '7 > 5' }} minColumns={5} label="Un árbol que no es de búsqueda: 5 con hijos 3 y 8; el 3 con hijos 1 y 7. Cada hijo está del lado correcto de su padre, pero el 7 está en el subárbol izquierdo del 5 y es mayor que 5." caption="7 está bien con su padre, 3, pero no con el 5" />
</div>

</Slide>

<Slide title="Las invariantes del árbol de búsqueda">
Un árbol binario de búsqueda sostiene tres propiedades:

1. **Cada nodo tiene a lo más dos hijos, izquierdo y derecho.**
2. **Cada nodo, salvo la raíz, tiene exactamente un padre.**
3. **Todo el subárbol izquierdo de un nodo es menor que él, y todo el derecho
   es mayor.** En particular, ningún valor se repite.

Las dos primeras son las del árbol binario, sin cambios. La tercera es la
nueva, y la que decide los costos: es la que permite descartar un subárbol
entero en cada comparación, y la que cada inserción y cada eliminación tienen
que dejar en pie.

</Slide>

<Slide title="El inorden de un árbol de búsqueda">
**El inorden de un árbol binario de búsqueda entrega sus valores ordenados de
menor a mayor.**

La razón es la misma definición recursiva. El inorden de un nodo es el
inorden de su subárbol izquierdo, después el nodo, y después el inorden del
derecho. Por la invariante, todo lo de la izquierda es menor que el nodo y
todo lo de la derecha es mayor; si cada subárbol, más pequeño, ya sale
ordenado, el nodo queda exactamente entre los dos, y el total sale ordenado.

<SequenceStepper eda="binary-tree" operation="inorder" values={[4, 2, 6, 1, 3, 5, 7]} />

</Slide>

Insertemos, en este orden, los valores 8, 5, 1, 4, 6, 7, 20 y 12 en un árbol
de búsqueda vacío: cada valor baja desde la raíz eligiendo un lado en cada
nodo, y se cuelga como hoja donde no hay más. Después escribamos el inorden
del árbol que queda.

</Slide>

<Slide title="Insertar a mano · la respuesta">
Cada valor quedó donde su búsqueda terminó, y el inorden, en la tira de
abajo, sale ordenado.

<SequenceStepper eda="bst" operation="insert" values={[]} value={[8, 5, 1, 4, 6, 7, 20, 12]} />

</Slide>

## Las operaciones del árbol de búsqueda

<Slide title="El árbol de búsqueda en Java">
La clase guarda la raíz y ofrece métodos públicos que delegan en uno
recursivo, que recibe la raíz de un subárbol. Para comparar dos valores se
usa `compareTo`, así que el tipo de los valores tiene que ser comparable.

```java
class BST<T extends Comparable<T>> {
    Node<T> root;

    boolean contains(T value) {
        return contains(root, value);
    }

    void insert(T value) {
        root = insert(root, value);
    }

    void remove(T value) {
        root = remove(root, value);
    }
}
```

`insert` y `remove` reasignan la raíz con lo que devuelve la versión
recursiva, porque insertar en un árbol vacío crea la raíz, y eliminarla
puede dejar otra en su lugar. Los nodos son los mismos `Node<T>` del árbol
binario.

</Slide>

<Slide title="Buscar en un árbol de búsqueda">
En cada nodo hay tres respuestas posibles: el valor es el buscado, es mayor,
o es menor. Si el buscado es menor, la invariante garantiza que no está a la
derecha, y se sigue solo por la izquierda; si es mayor, al revés. La
búsqueda baja por **un solo camino** y termina en el valor o en un subárbol
vacío.

<SequenceStepper eda="bst" operation="search" values={[4, 2, 7, 1, 3, 6, 9]} target={[6, 5]} />

Un camino desde la raíz tiene a lo más $$h + 1$$ nodos, así que buscar cuesta
$$O(h)$$, se encuentre o no el valor.

</Slide>

<Slide title="Insertar en un árbol de búsqueda">
Para insertar, se busca el valor. Si aparece, no se hace nada: el árbol no
guarda repetidos. Si la búsqueda termina en un subárbol vacío, ahí se cuelga
el valor nuevo como una **hoja**.

<SequenceStepper eda="bst" operation="insert" values={[8, 5, 1, 4, 6, 7, 20]} value={12} />

La invariante queda en pie: la hoja nueva quedó del lado que eligió cada
comparación, el lado correcto de cada nodo por encima de ella. Ningún otro
nodo se mueve, y el costo es el de la búsqueda: $$O(h)$$.

</Slide>

<Slide title="El mínimo y el máximo">
Por la invariante, todo lo menor que un nodo está a su izquierda. El
**mínimo** es entonces el nodo de más a la izquierda: se baja por la
izquierda hasta un nodo que no tenga hijo izquierdo. El **máximo** es el
simétrico: se baja por la derecha.

<SequenceStepper eda="bst" operation="minimum" values={[4, 2, 7, 1, 3, 6, 9]} />

Los dos bajan por un solo camino: $$O(h)$$. En un árbol vacío no hay mínimo,
y el método lanza una excepción.

</Slide>

<Slide title="El sucesor y el predecesor">
El **sucesor** de un valor es el menor valor del árbol que es mayor que él.
Se encuentra con una sola bajada desde la raíz: en cada nodo mayor que el
valor, ese nodo es un candidato y uno mejor solo puede estar a su izquierda;
en cada nodo menor o igual, el sucesor solo puede estar a su derecha. El
último candidato es el sucesor.

<SequenceStepper eda="bst" operation="successor" values={[4, 2, 7, 1, 3, 6, 9]} target={[3, 4]} />

Si el valor tiene subárbol derecho, el sucesor es el mínimo de ese subárbol;
si no, es el ancestro más cercano desde el que se bajó por la izquierda. El
**predecesor**, el mayor valor menor que él, es el simétrico. Los dos cuestan
$$O(h)$$.

</Slide>

<Slide title="Eliminar una hoja">
Para eliminar, primero se busca el valor. Cuando el nodo que lo tiene es una
**hoja**, basta con que su padre deje de apuntarle: la recursión devuelve el
subárbol vacío y el padre lo guarda en lugar del nodo.

<SequenceStepper eda="bst" operation="remove" values={[4, 2, 7, 1, 3, 6, 9]} target={1} />

</Slide>

<Slide title="Eliminar un nodo con un hijo">
Cuando el nodo tiene **un solo hijo**, su padre pasa a apuntar a ese hijo.

<SequenceStepper eda="bst" operation="remove" values={[8, 5, 1, 4, 6, 7, 20, 12]} target={1} />

</Slide>

La invariante se mantiene: todo el subárbol del hijo estaba del mismo lado
del padre que el nodo eliminado.

<Slide title="Eliminar un nodo con dos hijos">
Con **dos hijos**, el nodo toma el valor de su **sucesor** y se elimina el sucesor.

<SequenceStepper eda="bst" operation="remove" values={[8, 5, 1, 4, 6, 7, 20, 12]} target={8} />

</Slide>

Sacar el nodo dejaría dos subárboles colgando, y su padre solo tiene lugar
para uno; por eso se reemplaza su valor en lugar de quitarlo. El sucesor es el mínimo del subárbol derecho, y su valor es mayor que todo lo de la izquierda y menor que todo lo
demás de la derecha, así que la invariante queda en pie. Y el sucesor, por
ser el mínimo de un subárbol, no tiene hijo izquierdo: eliminarlo es uno de
los dos casos anteriores. Todo el trabajo es bajar dos veces por un camino:
$$O(h)$$.

<Slide title="Eliminar con dos hijos · la pregunta">
En este árbol, el 5 tiene dos hijos. Antes de pasar a la respuesta,
dibujemos cómo queda el árbol después de eliminarlo.

<BinaryPicture tree={{ v: 8, l: { v: 5, l: { v: 1, r: { v: 4 } }, r: { v: 6, r: { v: 7 } } }, r: { v: 20, l: { v: 12 } } }} tones={{ 5: 'focus' }} label="Un árbol de búsqueda: 8 en la raíz; a su izquierda el 5, con hijos 1 y 6; el 1 con un hijo derecho, 4; el 6 con un hijo derecho, 7; a la derecha del 8, el 20, con un hijo izquierdo, 12. El 5 está marcado." caption="eliminar 5, que tiene dos hijos" />

</Slide>

<Slide title="Eliminar con dos hijos · la respuesta">
El 5 toma el valor de su sucesor, 6, y el 6 de abajo deja su lugar al 7.

<SequenceStepper eda="bst" operation="remove" values={[8, 5, 1, 4, 6, 7, 20, 12]} target={5} />

</Slide>

<Slide title="Costos del árbol de búsqueda">
Cada operación baja por un camino desde la raíz, así que todas cuestan lo
mismo: la altura.

| Molde     | Operación                       | Peor caso  | Invariante que restaura                                    |
| --------- | ------------------------------- | ---------- | ---------------------------------------------------------- |
| Consultar | `contains`                      | $$O(h)$$   | Ninguna: no cambia el árbol                                |
| Consultar | mínimo, máximo                  | $$O(h)$$   | Ninguna: no cambia el árbol                                |
| Consultar | sucesor, predecesor             | $$O(h)$$   | Ninguna: no cambia el árbol                                |
| Modificar | `insert`                        | $$O(h)$$   | La de orden: la hoja nueva queda del lado que eligió cada comparación |
| Modificar | `remove`                        | $$O(h)$$   | La de orden: el sucesor cabe exactamente en el lugar que deja |

Y la altura de un árbol de $$n$$ nodos está entre $$\lfloor \log_2 n \rfloor$$
y $$n - 1$$.

</Slide>

<Slide title="Siete valores en un orden">
Los valores del 1 al 7, insertados en el orden 4, 2, 6, 1, 3, 5, 7: cada uno
cae en un nivel todavía incompleto, y el árbol queda lleno.

<SequenceStepper eda="bst" operation="insert" values={[]} value={[4, 2, 6, 1, 3, 5, 7]} />

</Slide>

<Slide title="Los mismos siete valores, ordenados">
Los mismos valores, insertados de menor a mayor: cada uno es mayor que todos
los anteriores, así que siempre baja por la derecha y se cuelga al final.

<SequenceStepper eda="bst" operation="insert" values={[]} value={[1, 2, 3, 4, 5, 6, 7]} />

El árbol quedó como una cadena de altura 6: buscar el 7 compara con todos
los nodos, igual que en una lista enlazada.

</Slide>

<Slide title="La altura que nadie controla">
El árbol de búsqueda responde cualquier pregunta sobre el orden —si un valor
está, el mínimo, el sucesor, insertar o eliminar— bajando por un solo camino:
cuesta la altura. Ninguna estructura de las que guardan elementos en fila
hace todo eso a la vez en tiempo logarítmico.

Pero la altura depende del **orden en que llegaron los valores**, y nada en el
árbol la controla. La invariante de orden dice dónde va cada valor y no dice
nada sobre la forma. Con los valores en el peor orden posible —ordenados—, el
árbol es una lista, y cada operación cuesta $$\Theta(n)$$.

Si las inserciones y las eliminaciones también cuidaran la **forma**,
reacomodando el árbol cada vez que se cargue hacia un lado, la altura quedaría
acotada por $$O(\log n)$$ y todas las operaciones con ella. El precio sería más
trabajo en cada inserción y en cada eliminación. Ese es el compromiso de un
**árbol de búsqueda balanceado**.

</Slide>

## Lo que sigue

Un árbol de búsqueda resuelve todas las preguntas sobre el orden con el costo
de su altura, y su altura depende de cómo llegan los valores. Árboles II
estudia qué pasa cuando llegan en el peor orden, y cómo un árbol puede
reacomodarse a sí mismo para que su altura quede siempre cerca de
$$\log_2 n$$.
