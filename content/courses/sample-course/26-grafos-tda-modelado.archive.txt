{/* StreetPlan — a street map in one frame at two stages of the modelling pattern (#356): `city` the four streets with their blocks of buildings, one-way arrows and the minutes each stretch takes; `streets` only the corners, lettered, and the stretches with their minutes and senses. The third stage is the graph, a <NodeGraph> beside it. File-local. */}

export function StreetPlan({ stage = 'city', label }) {
  const at = { A: [80, 60], B: [240, 60], C: [80, 180], D: [240, 180] };
  const stretches = [['A', 'B', 4, true], ['A', 'C', 3, false], ['C', 'D', 5, false], ['D', 'B', 2, false]];
  const tip = (x1, y1, x2, y2) => {
    const d = Math.hypot(x2 - x1, y2 - y1);
    const ux = (x2 - x1) / d;
    const uy = (y2 - y1) / d;
    const bx = x2 - ux * 9;
    const by = y2 - uy * 9;
    return `${x2},${y2} ${bx - uy * 5},${by + ux * 5} ${bx + uy * 5},${by - ux * 5}`;
  };
  const blocks = [];
  if (stage === 'city') {
    for (const [x0, x1] of [[22, 70], [90, 230], [250, 298]]) {
      for (const [y0, y1] of [[22, 50], [70, 170], [190, 218]]) {
        const n = Math.max(1, Math.round((x1 - x0) / 50));
        const m = Math.max(1, Math.round((y1 - y0) / 50));
        const w = (x1 - x0 - (n - 1) * 5) / n;
        const h = (y1 - y0 - (m - 1) * 5) / m;
        for (let i = 0; i < n; i++) for (let j = 0; j < m; j++) blocks.push([x0 + i * (w + 5), y0 + j * (h + 5), w, h]);
      }
    }
  }
  return (
    <svg viewBox="0 0 320 240" style={{ width: '100%', maxWidth: '340px', height: 'auto', display: 'block', margin: '0.4rem auto' }} role="img" aria-label={label}>
      {stage === 'city'
        ? [[12, 60, 308, 60], [12, 180, 308, 180], [80, 12, 80, 228], [240, 12, 240, 228]].map(([x1, y1, x2, y2], k) => (
            <line key={`s${k}`} x1={x1} y1={y1} x2={x2} y2={y2} style={{ stroke: 'var(--color-sunk)' }} strokeWidth="18" />
          ))
        : null}
      {blocks.map(([x, y, w, h], k) => (
        <rect key={`b${k}`} x={x} y={y} width={w} height={h} rx="2" style={{ fill: 'var(--color-surface)', stroke: 'var(--color-rule-strong)' }} strokeWidth="0.8" />
      ))}
      {stretches.map(([v, w, minutes, both], k) => {
        const [x1, y1] = at[v];
        const [x2, y2] = at[w];
        const mx = (x1 + x2) / 2;
        const my = (y1 + y2) / 2;
        const ux = (x2 - x1) / Math.hypot(x2 - x1, y2 - y1);
        const uy = (y2 - y1) / Math.hypot(x2 - x1, y2 - y1);
        const chipX = mx + (uy !== 0 ? 30 : 0);
        const chipY = my + (uy !== 0 ? 0 : -19);
        return (
          <g key={`t${k}`}>
            {stage === 'streets' ? <line x1={x1} y1={y1} x2={x2} y2={y2} style={{ stroke: 'var(--color-rule-strong)' }} strokeWidth="2" /> : null}
            <polygon points={tip(mx - ux * 14, my - uy * 14, mx + ux * 14, my + uy * 14)} style={{ fill: 'var(--color-ink-soft)' }} />
            {both ? <polygon points={tip(mx + ux * 14, my + uy * 14, mx - ux * 14, my - uy * 14)} style={{ fill: 'var(--color-ink-soft)' }} /> : null}
            <rect x={chipX - 25} y={chipY - 10} width="50" height="20" rx="5" style={{ fill: 'var(--color-surface)', stroke: 'var(--color-rule)' }} strokeWidth="1" />
            <text x={chipX} y={chipY + 5} textAnchor="middle" fontSize="13" style={{ fill: 'var(--color-ink)' }}>{minutes} min</text>
          </g>
        );
      })}
      {stage === 'streets'
        ? Object.entries(at).map(([v, [x, y]]) => (
            <g key={v}>
              <circle cx={x} cy={y} r="13" style={{ fill: 'var(--color-surface)', stroke: 'var(--color-rule-strong)' }} strokeWidth="1.4" />
              <text x={x} y={y + 5} textAnchor="middle" fontSize="14" fontWeight="700" style={{ fill: 'var(--color-ink)' }}>{v}</text>
            </g>
          ))
        : null}
    </svg>
  );
}

{/* Curriculum — a curriculum at two stages of the modelling pattern (#356): `table` the courses by semester, each saying which course it asks for; `arrows` the same courses with an arrow from each prerequisite to the course that asks for it. The third stage is the graph, a <NodeGraph> beside it. File-local. */}

export function Curriculum({ stage = 'table', label }) {
  const W = 118;
  const H = 50;
  const at = { 'Cálculo I': [72, 52], 'Álgebra': [206, 52], 'Cálculo II': [72, 146], 'Ecuaciones': [139, 240] };
  const asks = { 'Cálculo II': ['pide Cálculo I'], 'Ecuaciones': ['pide Cálculo II', 'y Álgebra'] };
  const arrows = [['Cálculo I', 'Cálculo II'], ['Cálculo II', 'Ecuaciones'], ['Álgebra', 'Ecuaciones']];
  const tip = (x1, y1, x2, y2) => {
    const d = Math.hypot(x2 - x1, y2 - y1);
    const ux = (x2 - x1) / d;
    const uy = (y2 - y1) / d;
    const bx = x2 - ux * 10;
    const by = y2 - uy * 10;
    return `${x2},${y2} ${bx - uy * 5.5},${by + ux * 5.5} ${bx + uy * 5.5},${by - ux * 5.5}`;
  };
  return (
    <svg viewBox="0 0 278 282" style={{ width: '100%', maxWidth: '300px', height: 'auto', display: 'block', margin: '0.4rem auto' }} role="img" aria-label={label}>
      {stage === 'table'
        ? ['1.er semestre', '2.º semestre', '3.er semestre'].map((t, k) => (
            <text key={t} x="13" y={20 + 94 * k} fontSize="12" fontWeight="600" style={{ fill: 'var(--color-ink-faint)' }}>{t}</text>
          ))
        : null}
      {stage === 'arrows'
        ? arrows.map(([v, w]) => {
            const [x1, y1] = [at[v][0], at[v][1] + H / 2];
            const [x2, y2] = [at[w][0] + (v === 'Álgebra' ? 24 : v === 'Cálculo II' ? -24 : 0), at[w][1] - H / 2];
            return (
              <g key={`${v}-${w}`}>
                <line x1={x1} y1={y1} x2={x2} y2={y2} style={{ stroke: 'var(--color-ink-soft)' }} strokeWidth="1.8" />
                <polygon points={tip(x1, y1, x2, y2)} style={{ fill: 'var(--color-ink-soft)' }} />
              </g>
            );
          })
        : null}
      {Object.entries(at).map(([name, [x, y]]) => {
        const lines = stage === 'table' ? asks[name] ?? [] : [];
        const top = y - 6 - lines.length * 7;
        return (
          <g key={name}>
            <rect x={x - W / 2} y={y - H / 2} width={W} height={H} rx="6" style={{ fill: 'var(--color-surface)', stroke: 'var(--color-rule-strong)' }} strokeWidth="1.2" />
            <text x={x} y={top + 11} textAnchor="middle" fontSize="15" fontWeight="700" style={{ fill: 'var(--color-ink)' }}>{name}</text>
            {lines.map((t, k) => (
              <text key={t} x={x} y={top + 26 + 13 * k} textAnchor="middle" fontSize="12" style={{ fill: 'var(--color-ink-soft)' }}>{t}</text>
            ))}
          </g>
        );
      })}
    </svg>
  );
}

{/* River — the ferryman's crossing at two stages of the modelling pattern (#356): `river` the two banks, the river and the boat, with the ferryman, the wolf, the goat and the cabbage on the starting bank; `states` two trips written as states, what stays on the starting bank, so the state graph beside it reads.   const tag = (x, y, t, k) => (

<Slide title="Leer un grafo">
La lista de aristas se lee línea a línea. Cada arista entra con `addEdge`, que
en un grafo sin dirección la deja en las dos listas:

```java
static Graph read(Scanner in) {
    int V = in.nextInt();
    int E = in.nextInt();
    Graph g = new AdjListGraph(V);
    for (int i = 0; i < E; i++) {
        int v = in.nextInt();
        int w = in.nextInt();
        g.addEdge(v, w);
    }
    return g;
}
```

</Slide>

<Slide title="De nombres a números">
La lista de aristas trae números, pero un problema casi siempre trae nombres:
ciudades, personas, ramos. El grafo numera sus vértices de $$0$$ a $$V - 1$$
para usarlos como índices, así que los nombres se traducen a esos números al
leerlos, con dos estructuras:

- un **Map** del nombre a su número, para traducir al leer;
- una **lista** del número a su nombre, para traducir de vuelta al escribir
  la respuesta.

Cada nombre nuevo recibe el siguiente número libre.

| Nombre   | Número |
| -------- | ------ |
| Santiago | 0      |
| Lima     | 1      |
| Bogotá   | 2      |
| Quito    | 3      |

</Slide>

<Slide title="De nombres a números en Java">
En Java, las dos estructuras son un `HashMap` del nombre a su número y un
`ArrayList` con los nombres, en el orden en que aparecieron:

```java
Map<String, Integer> ids = new HashMap<>();
List<String> names = new ArrayList<>();

int idOf(String name) {
    if (!ids.containsKey(name)) {
        ids.put(name, names.size());
        names.add(name);
    }
    return ids.get(name);
}
```

Un nombre que llega por primera vez recibe el número `names.size()`, el
siguiente libre. `names.get(v)` devuelve el nombre del vértice `v` al escribir
la respuesta.

</Slide>

<Slide title="La memoria de las dos implementaciones">
- **La matriz** guarda $$V^2$$ casillas, haya las aristas que haya:
  $$\Theta(V^2)$$.
- **Las listas** guardan una lista por vértice y una entrada por extremo de
  arista: $$\Theta(V + E)$$.

Las entradas de las listas se cuentan con el lema del apretón de manos:

$$
\sum_{v} |\mathrm{adj}(v)| = \sum_{v} \operatorname{grado}(v) = 2E
$$

Se lee «la suma de los largos de las listas es la suma de los grados, que es
dos veces la cantidad de aristas». Cuál ocupa menos depende de cuántas aristas
tiene el grafo.

</Slide>

<Slide title="Un grafo implícito">
A veces no hace falta guardar el grafo, ni en una matriz ni en listas: sus
aristas siguen una regla, y los vecinos de un vértice se calculan cuando se
necesitan. Es un **grafo implícito**.

- **El candado de cuatro ruedas**: son $$10^4$$ combinaciones, y los 8
  vecinos de cada una salen de girar una rueda una posición hacia arriba o
  hacia abajo.
- **Una grilla**, como un laberinto o un mapa por celdas: cada celda es un
  vértice, y sus vecinas son las celdas a las que se pasa en un paso.

<Slide title="El código de las vecinas">
Las vecinas no se guardan: se calculan con dos arreglos de desplazamientos,
uno para la fila y otro para la columna. Cada posición `k` es un paso, y una
vecina cuenta solo si cae dentro de la grilla.

```java
static final int[] DR = {-1, 1, 0, 0};
static final int[] DC = {0, 0, -1, 1};

static List<int[]> neighbors(int r, int c, int rows, int cols) {
    List<int[]> result = new ArrayList<>();
    for (int k = 0; k < DR.length; k++) {
        int nr = r + DR[k];
        int nc = c + DC[k];
        if (nr >= 0 && nr < rows && nc >= 0 && nc < cols) {
            result.add(new int[] {nr, nc});
        }
    }
    return result;
}
```

En 8 direcciones cambian solo los arreglos; el método queda igual:

```java
static final int[] DR = {-1, -1, -1, 0, 0, 1, 1, 1};
static final int[] DC = {-1, 0, 1, -1, 1, -1, 0, 1};
```

</Slide>

<Slide title="Las rutas de una aerolínea">
Una aerolínea publica sus rutas como un texto, una ruta por línea: los
códigos de los dos aeropuertos que une. Cada ruta se vuela en los dos
sentidos. La aerolínea quiere saber cuál es su aeropuerto con más rutas, y
a qué aeropuertos vuela desde ahí.

```text
SCL LIM
SCL EZE
SCL GRU
LIM BOG
LIM MIA
BOG MIA
LIM GRU
```

**Entrada.** Las rutas, a lo más $$10^5$$, sin repetir ninguna. $$R$$ es la
cantidad de rutas y $$A$$, la de aeropuertos.

**Salida.** El código del aeropuerto con más rutas —si hay empate, el que
aparece primero en el texto— y los códigos de sus destinos.

</Slide>

<Slide title="Rutas aéreas · el grafo">
Los aeropuertos son los vértices y cada ruta es una arista sin dirección,
porque se vuela en los dos sentidos. Las rutas no traen un número que el
problema use: no hay pesos. El problema se reduce a buscar el vértice de
mayor grado y entregar sus vecinos.

Contar cuántas líneas nombra cada código da los grados, pero no los
destinos. Buscar los destinos recorriendo el texto completo por cada
aeropuerto cuesta $$\Theta(A \cdot R)$$. Con el grafo armado, los destinos
son la lista de un vértice.

</Slide>

<Slide title="Rutas aéreas · la solución">
Al leer cada línea, los dos códigos se traducen a números con `idOf`, y la
ruta se guarda. Con la cantidad de aeropuertos conocida se arma el grafo, se
busca el vértice de mayor grado y se escriben los nombres de sus vecinos.

```java
static void busiest(Scanner in) {
    List<int[]> routes = new ArrayList<>();
    while (in.hasNext()) {
        int v = idOf(in.next());
        int w = idOf(in.next());
        routes.add(new int[] {v, w});
    }
    Graph g = new AdjListGraph(names.size());
    for (int[] r : routes) {
        g.addEdge(r[0], r[1]);
    }
    int best = 0;
    int bestDegree = degree(g, 0);
    for (int v = 1; v < g.V(); v++) {
        int d = degree(g, v);
        if (d > bestDegree) {
            best = v;
            bestDegree = d;
        }
    }
    System.out.print(names.get(best) + ":");
    for (int w : g.adj(best)) {
        System.out.print(" " + names.get(w));
    }
    System.out.println();
}
```

El `>` estricto deja, en un empate, el vértice de número menor: el que
apareció primero en el texto.

</Slide>

<Slide title="Rutas aéreas · el costo">
- **Tiempo.** Leer las $$R$$ rutas cuesta $$\Theta(R)$$ esperado, por el `Map`
  de `idOf`. Calcular el grado de cada vértice recorre todas las listas, que
  suman $$2R$$ entradas: $$\Theta(A + R)$$.
- **Memoria.** La lista de rutas, el `Map`, los nombres y el grafo:
  $$\Theta(A + R)$$.

Si el texto repitiera una ruta, el grafo la guardaría dos veces y la contaría
dos veces en el grado: el enunciado lo descarta.

</Slide>

<Slide title="Un solo trazo · la idea">
Probar todos los órdenes de los trazos funciona, pero $$E$$ trazos se pueden
ordenar de $$E!$$ maneras. El problema se reduce al camino euleriano, y la
regla de Euler responde sin probar ninguno: en un grafo conexo, lo deciden los
vértices de grado impar.

- **Ninguno**: cualquier punto sirve, y el trazo vuelve a él.
- **Dos**: hay que empezar en uno de los dos.
- **Más de dos**: no se puede.

Basta con calcular el grado de cada vértice y quedarse con los impares.

</Slide>

<Slide title="Un solo trazo · la solución">
```java
static int startOf(Graph g) {
    List<Integer> odd = new ArrayList<>();
    for (int v = 0; v < g.V(); v++) {
        if (degree(g, v) % 2 == 1) {
            odd.add(v);
        }
    }
    if (odd.isEmpty()) {
        return 0;
    }
    if (odd.size() == 2) {
        return odd.get(0);
    }
    return -1;
}
```

Sin vértices impares, cualquier punto sirve, y el método responde el $$0$$.
Con dos, el trazo empieza en el primero y termina en el segundo.

- **Tiempo.** El grado de cada vértice recorre su lista: $$\Theta(V + E)$$
  en total.
- **Memoria.** La lista de impares: $$O(V)$$.

La respuesta vale solo si el grafo es conexo, como dice el enunciado: dos
figuras separadas pueden tener sus grados pares y no dibujarse de un trazo.

</Slide>

<Slide title="Sugerir amigos">
Una red social sugiere a cada persona a alguien que todavía no es su amigo:
la persona con más **amigos en común** con ella.

**Entrada.** Las amistades de $$V$$ personas, numeradas de $$0$$ a $$V - 1$$,
y la persona `u` que recibe la sugerencia.

**Salida.** La persona que no es `u` ni amiga de `u` con más amigos en común
con `u` —si hay empate, la de número menor—, o $$-1$$ si nadie tiene un amigo
en común con `u`.

<Slide title="Sugerir amigos · la idea">
Contar los amigos en común de `u` con cada otra persona, uno por uno, compara
listas de amigos para cada persona de la red, aunque casi todas estén lejos
de `u`.

Un amigo en común con `w` es un amigo `x` de `u` que también es amigo de `w`.
Al revés: cada amigo `x` de `u` le suma un amigo en común a **cada uno de sus
propios amigos**. El problema se reduce a recorrer los vecinos de los vecinos
de `u`, con un contador por persona, saltándose a `u` y a quienes ya son sus
amigos.

<Slide title="Sugerir amigos · la solución">
```java
static int suggest(Graph g, int u) {
    boolean[] friend = new boolean[g.V()];
    for (int x : g.adj(u)) {
        friend[x] = true;
    }
    int[] common = new int[g.V()];
    for (int x : g.adj(u)) {
        for (int w : g.adj(x)) {
            if (w != u && !friend[w]) {
                common[w]++;
            }
        }
    }
    int best = -1;
    for (int w = 0; w < g.V(); w++) {
        if (common[w] > 0 && (best == -1 || common[w] > common[best])) {
            best = w;
        }
    }
    return best;
}
```

`friend` marca a los amigos de `u` para saltarlos en tiempo constante, sin
preguntar `hasEdge`, que en listas recorrería la lista de `u` cada vez.

</Slide>

<Slide title="Sugerir amigos · el costo">
- **Tiempo.** Recorrer los amigos de los amigos de `u` cuesta la suma de los
  grados de los amigos de `u`, a lo más $$2E$$. Crear los dos arreglos y
  buscar el mayor cuesta $$\Theta(V)$$. En total, $$O(V + E)$$, y casi siempre
  mucho menos que $$E$$ en el recorrido: solo se miran las personas a dos
  pasos de `u`.
- **Memoria.** Los dos arreglos: $$\Theta(V)$$.

Si `u` no tiene amigos, o sus amigos no tienen otros amigos, ningún contador
sube y el método retorna $$-1$$.

</Slide>
