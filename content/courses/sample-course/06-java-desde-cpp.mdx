# Java desde C++

Ya sabes programar. Sabes qué es un ciclo, una función y un tipo de dato, y has
peleado con un compilador. Nada de eso hay que aprenderlo de nuevo.

Lo que cambia es el idioma, y este documento se ocupa **solo de lo que cambia**.
Lo que Java hace igual que C++ ocupa un párrafo; lo que hace distinto se gana las
páginas. Al terminar vas a poder escribir, compilar y ejecutar un programa Java, y
vas a saber por qué está cada palabra de `public static void main(String[] args)`.
Los tipos, los operadores, la entrada de datos y el control de flujo son el tema del
documento que le sigue.

Los bloques con botón *Ejecutar* compilan y corren **en tu navegador**. Puedes
editarlos. Deberías editarlos. Los demás son listados para leer y comparar.

<SectionBreak />

<Slide title="De dónde viene Java">
En 1991, un equipo de Sun Microsystems trabajaba en un lenguaje para
electrodomésticos: televisores, decodificadores, cosas con poca memoria y
procesadores de marcas distintas. Lo llamaron **OAK**, después **Green**, y
finalmente **Java**.

Ese origen explica casi todo lo que Java es hoy. Para correr en aparatos con
procesadores distintos no puedes compilar al lenguaje máquina de ninguno en
particular: compilas a un formato intermedio y pones en cada aparato una **máquina
virtual** que lo interprete.
</Slide>

Los electrodomésticos nunca llegaron. La web sí, y después Android. Pero ese diseño
de 1991 dejó tres decisiones que te van a acompañar todo el curso.

<Slide title="Las tres decisiones que te acompañan">
- **Compilar una vez, ejecutar en cualquier parte.** El compilador no produce un
  binario para tu máquina, sino *bytecode* para la máquina virtual.
- **Recolección de basura.** Nadie llama `delete`. La memoria que ya no se usa se
  libera sola, y cuándo exactamente no es asunto tuyo.
- **Orientado a objetos sin escapatoria.** En C++ puedes escribir un programa entero
  sin declarar una clase. En Java no.
</Slide>

<Slide title="El mismo programa, en dos idiomas">
Este es el programa que ya conoces, en los dos idiomas.

<SideBySide left="C++" right="Java">

```cpp
#include <iostream>

int main() {
    std::cout << "Bienvenidos a EDA"
              << std::endl;
    return 0;
}
```

```java
class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Bienvenidos a EDA");
    }
}
```

</SideBySide>

Cuatro diferencias, y ninguna es cosmética.
</Slide>

<Slide title="Cuatro diferencias, una por una">
1. **`main` no es una función libre.** Vive dentro de `class HelloWorld`: en Java no
   existen las funciones fuera de una clase, y el compilador no te deja.
2. **No hay archivo de cabecera.** Una clase se declara y se define en el mismo lugar:
   no hay `.h`, ni guardas de inclusión, ni declaración adelantada.
3. **`System.out.println` en vez de `std::cout <<`.** No es un operador sobrecargado
   sino una llamada a método corriente: Java no tiene sobrecarga de operadores.
4. **`main` no retorna nada.** En C++ devuelve `int`; en Java es `void`, y el código de
   salida se manda con `System.exit(n)` cuando hace falta.
</Slide>

La primera vez tarda: el navegador descarga una máquina virtual de Java completa antes
de poder correr nada. Después es cuestión de segundos.

<Slide title="Por qué main tiene tantas palabras">
`public static void main(String[] args)` son cinco decisiones, no una fórmula mágica.
Tres de esas palabras van a aparecer en todo lo que escribas de aquí en adelante.

| Palabra | Qué dice |
|---|---|
| `public` | Se puede llamar desde fuera de la clase. La máquina virtual está fuera, así que necesita este permiso |
| `static` | Pertenece a la **clase**, no a un objeto de la clase |
| `void` | No devuelve nada |
| `main` | El nombre exacto que la máquina virtual busca para empezar |
| `String[] args` | Los argumentos de la línea de comandos |
</Slide>

<Slide title="Qué significa static">
Un método normal pertenece a un *objeto*: para llamarlo necesitas primero haber creado
uno. Un método `static` pertenece a la clase misma y se llama sin crear nada. Por eso
`main` tiene que serlo: cuando la máquina virtual arranca tu programa todavía no existe
ningún objeto, y no tendría cómo saber cuál crear.

Es la misma idea que un método estático de C++, y también se llama igual.
</Slide>

<Slide title="Pruébalo: el método sin static">
`main` no puede llamar directo a un método que **no** es `static`: no hay ningún objeto
al que pedirle nada, así que hay que fabricar uno primero. Descomenta la última línea y
ejecuta para ver el error.

<CodeEditor
  language="java"
  defaultValue={`class Saludo {
    // static: pertenece a la clase. main lo llama directo.
    static String formal() {
        return "Buenas tardes";
    }

    // sin static: pertenece a un objeto. Hay que crear uno.
    String informal() {
        return "hola";
    }

    public static void main(String[] args) {
        System.out.println(formal());

        Saludo s = new Saludo();
        System.out.println(s.informal());

        // Prueba a descomentar esta línea y ejecutar:
        // System.out.println(informal());
    }
}
`}
/>
</Slide>

El error que aparece —*Cannot make a static reference to the non-static method
informal() from the type Saludo*— es de los que más vas a ver este semestre, y ahora
sabes exactamente qué significa. En tu computador, con el JDK instalado, el mismo error
viene redactado distinto: *non-static method informal() cannot be referenced from a
static context*. Es el mismo problema; los compiladores no se ponen de acuerdo en cómo
decirlo.

Sobre `String[] args`: es el equivalente de `int argc, char** argv`, con dos
diferencias. El arreglo **sabe su propio largo**, así que no hace falta pasarlo aparte.
Y `args[0]` es el **primer argumento**, no el nombre del programa: en C++, `argv[0]` es
el nombre y los argumentos empiezan en `argv[1]`. En este curso casi nunca lo vas a usar.

<Slide title="Compilar y ejecutar">
En C++ el ciclo termina en un binario para tu máquina:

```
programa.cpp  →  [g++]  →  programa      (instrucciones de TU procesador)
```

En Java hay un paso más, y un intérprete al final:

```
Hola.java  →  [javac]  →  Hola.class  →  [java]  →  ejecutando
                          (bytecode)      (la JVM)
```

`javac Hola.java` produce `Hola.class`. Ese archivo **no es un ejecutable de tu
sistema**: es bytecode, un lenguaje máquina inventado para una máquina que no existe.
`java Hola` arranca la máquina virtual, que lo lee y lo ejecuta.
</Slide>

Ahí está la promesa de 1991: el mismo `Hola.class` corre en Linux, en Windows y en un
teléfono Android, porque los tres tienen una máquina virtual de Java. En C++, cambiar de
sistema o de arquitectura significa recompilar. El precio es que hay un intérprete en el
medio, y por eso Java arranca más lento que C++. A cambio, la máquina virtual observa tu
programa mientras corre y recompila a lenguaje máquina las partes que más se usan.

> **Y en esta página, ¿qué pasa?** Exactamente esos dos pasos. El botón *Ejecutar* corre
> un compilador de Java sobre lo que escribiste y después ejecuta el `.class` que salió.
> No es exactamente `javac`: es ECJ, el compilador de Eclipse, y por eso algunos mensajes
> de error están redactados distinto de los que verás en tu computador. Lo distinto es
> dónde: la máquina virtual está compilada a WebAssembly y vive en tu navegador. Por eso
> la primera ejecución tarda tanto — está descargando un Java completo.

<Slide title="El archivo se llama como la clase">
Una regla que el navegador te perdona y tu computador no: si una clase es `public`, el
archivo **tiene que llamarse igual que ella**. `public class Tarea` va en `Tarea.java`, o
`javac` se niega antes de compilar.

En esta página los ejemplos usan clases que **no** son `public` —por eso `HelloWorld`
corre en un archivo con cualquier nombre—, pero en cuanto le pongas `public` a una, el
nombre del archivo deja de ser libre. Es el error más común de la primera semana, y es
también por qué el documento de código ejecutable usa `public class Main` dentro de
`Main.java`.
</Slide>

<Slide title="import y paquetes">
Las clases de Java se organizan en **paquetes**, y el nombre completo de una clase
incluye el suyo: `java.util.Scanner` es la clase `Scanner` del paquete `java.util`.

```java
import java.util.Scanner;
```

`import` se parece a `#include`, pero hace algo muy distinto. `#include` **pega el
contenido** del archivo en el tuyo antes de compilar; `import` no copia nada, solo dice:
*cuando escriba `Scanner`, me refiero a `java.util.Scanner`*. Es una abreviatura.
</Slide>

<Slide title="La prueba del nombre completo">
Que es solo una abreviatura se comprueba: puedes escribir el nombre completo y saltarte
el `import`. Nadie programa así, pero compila igual.

<CodeEditor
  language="java"
  variant="lab"
  warmOnMount={false}
  defaultValue={`class SinImport {
    public static void main(String[] args) {
        // El nombre completo, sin ningún import arriba.
        java.util.Scanner stdin = new java.util.Scanner(System.in);
        System.out.println("Leí: " + stdin.nextInt());
    }
}
`}
  defaultStdin={`42
`}
/>
</Slide>

Un paquete se importa solo: **`java.lang`**. Por eso `System`, `String`, `Math` e
`Integer` funcionan sin que hayas escrito nada arriba. Todo lo demás —`Scanner`,
`ArrayList`, `HashMap`— hay que pedirlo.

## Lo que sigue

Ya puedes leer, escribir, compilar y ejecutar un programa Java, y sabes por qué está
cada palabra de `public static void main(String[] args)`. Lo que todavía no viste es con
qué trabaja ese programa: los tipos primitivos y sus diferencias con C++, los operadores,
cómo leer datos con `Scanner` y el control de flujo.
